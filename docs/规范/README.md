# 规范总纲（`docs/规范/`）

> **作用**：本目录是**约束性文档**的唯一落点。本文件是它的门面：效力等级、引用格式、分册清单、**规则 → 门禁映射**、生效与废弃流程。
> **配套**：目录/命名/头部/编号的细则见 [`SPEC-005-文档枢纽契约.md`](SPEC-005-文档枢纽契约.md)；全量文档索引见 [`../INDEX.md`](../INDEX.md)。
> **规则的可执行落地**：DSH 分发版内的 `governance/`（`RULES.md` = 规则→门禁映射，`gates/` = **18 条门禁**，2026-10-08 实测）。

---

## 1. 效力等级

**效力 = 违反它的后果**。等级越高，越不允许"这次先这样"。

| 等级 | 含义 | 违反后果 | 谁定的 |
| --- | --- | --- | --- |
| **铁律** | 用户拍板的硬约束，无例外或例外必须写明并留档 | 停下来改；不得以"省事"为由绕过 | 用户 |
| **准则** | 治理方法论层，事故驱动固化 | 门禁可拦则拦；不可拦则必须在复盘里交代 | 用户 + 审核 |
| **纪律** | 工程操作层，代价可量化（一次事故一条） | 门禁拦截或自检失败 | 事故 |
| **操作规范** | runbook，照做即可复现 | 命令跑不通即违反 | 实践 |
| **指南** | 方法论与复刻步骤，允许因地制宜 | 不构成阻断 | 实践 |

## 2. 引用格式

| 写法 | 指向 | 例子 |
| --- | --- | --- |
| `SPEC-NNN` | 整份规范 | `SPEC-001` = 铁律 |
| `SPEC-NNN §<小节>` | 规范内某节 | `SPEC-004 §调试铁律 19` = 只 `git add <指定文件>` |
| `铁律 N`（0–5） | `SPEC-001` 内的命名铁律编号 | `铁律 5` = 路径不写死盘符 |
| `调试铁律 N` | `SPEC-004` 内的纪律编号（现 **1–69**） | `调试铁律 53` = 门禁的排除项最危险 |
| `OPS-X*` | `SPEC-10x` 操作规范内的清单项 | `OPS-E8` = 新建仓收尾四步 |

> ⚠ **`铁律 N` 与 `调试铁律 N` 是两套编号，裸写「铁律 4」同时匹配两者** —— 引用一律带限定词（该约束原写在 `MEMORY.md`，现随规范一同迁入本目录）。
> ⚠ `调试铁律` 的实际末号是 **66**（2026-10-06 订正：此前本行与 `SPEC-004` 标题都写 62，属账实不符）；
> DSH `RULES.md` 与治理 persona 段里的「1–58」是**过期值**，以 `SPEC-004` 为准。

## 4. 规则 → 门禁映射（总表）

**「被视为要求」的判据就是这张表**：左边是规矩，右边是把它变成退出码的东西。**没有承载体的规范必须显式写「无」并给理由**，不许留空。

### 4.3 明确**不可**机械化的（流程纪律）

写在这里是为了**防止有人硬编成假绿门禁**：铁律 1 的"先读 README"、铁律 2 的对话节奏、铁律 3 的"无人值守不推送"、冗余三查里的**语义拆分**（哪几个功能面算一个面）——这些靠判断，只能靠复盘与抽检。

## 5. 生效 · 修订 · 废弃

1. **生效**：规范由用户拍板或由事故驱动提炼；新增须按 SPEC-005 §7 四步走。
2. **修订**：改条文须在规范末尾的「修订记录」表里留一行（日期 / 版本 / 改动 / 依据）；**改判据必须同时改门禁自检**（调试铁律 53）。
3. **废弃**：**不删除**。把头部 `状态` 改为 `已废弃`，正文首行写明替代者，引用方改为指向替代规范。
4. **冲突**：两条规范冲突时，效力高者胜；同级冲突时，**带日期的记录不作为依据**，须改用现行规范并回头修规范本身。

## 6. 与本目录外的东西的关系

| 对象 | 关系 |
| --- | --- |
| `SPEC-005` 契约 | 本目录的**形式规则**（放哪、叫什么叫什么、头部写什么） |
| `../INDEX.md` | 全量登记；本目录每份规范都必须在其中有一行 |
| `../事实源/` | 取值型事实（端口、许可、机器）——规范引用它们，但不复制它们的值 |
| `../记录/` | 证据型文档——规范**引用**记录的结论，记录**不得**反过来当规范用 |
| DSH `governance/RULES.md` | 分发版侧的映射表；**规则事实源仍是本目录**，RULES.md 只做落地映射 |
