# dsh 终端进程泄漏排查记录

- **日期**：2026-08-28
- **现象**：deepseek（dsh harness 内的代理）拉起大量终端进程后不关闭，终端频道被阻塞，屏幕持续"往外弹"终端窗口/标签
- **处理结果**：已全部清理，仅保留必需的 npm 本地镜像代理

---

## 一、问题背景

- dsh (DeepSeek Harness) Web UI 于当日 11:41 启动，deepseek 代理在会话中执行了大量 shell 操作
- 12:18 前后 Web UI 的 terminal 频道下拉已堆积大量 Terminal/PowerShell 会话条目
- 用户 12:24:33 与 12:25:43 两次双击 `start-dsh.bat` 尝试重启，两个 cmd 窗口均卡死（npx 始终未拉起 node，3080 端口从未被绑定）
- 12:25:21 用户通过桌面快捷方式打开 Chrome 访问 dsh Web UI（此时后端已死）

## 二、第一轮排查与清理

### 发现的残留进程

| 进程 | PID | 启动时间 | 说明 |
|---|---|---|---|
| cmd.exe（start-dsh.bat）×2 | 25988 / 3012 | 12:24:33 / 12:25:43 | 卡死的启动器，无 node 子进程，3080 无监听 |
| conhost.exe ×2 | 26924 / 26960 | 随 cmd | 控制台宿主 |
| python npm_local_mirror.py（重复实例） | 22848 | 08-24 05:23 | 僵尸副本，8899 端口实际由健康实例 17376 持有 |
| python -m http.server 8123 | 16468 | 08-27 18:45 | 前一日 deepseek 会话遗留 |
| python -m http.server 8124 | 15188 | 08-27 18:55 | 同上 |
| python -m http.server 8125 | 21528 | 08-27 18:57 | 同上 |
| 空壳 WindowsTerminal | 26596 | 12:24:48 | 只剩死页签的终端窗口 |

### 处置

- `taskkill /F /T` 终止上述全部进程（OpenConsole 11168/26276 随 cmd 自动退出）
- 保留：8899 端口的 npm 本地镜像代理（PID 17376，08-23 起运行，HTTP 200 健康，dsh 启动依赖它）
- 保留：CodeBuddy 自身进程（bash 会话、http.server 8077、edgeone MCP node 等）

## 三、第二轮排查与清理（关键）

第一轮清理后用户反馈"还在往外弹"，截图显示屏幕上叠了多个终端窗口。

### 新发现

1. **Chrome 前端死循环拉进程（真正的"往外弹"源头）**
   - 桌面快捷方式打开的 Chrome 窗口（PID 11332，标题 `DeepSeek Harness - 127.0.0.1`，12:25:21 启动）
   - 在后端 3080 已死的情况下，页面 JS 仍循环重连/重建会话
   - 12:34:25 ~ 12:34:38 的 13 秒内密集派生 15 个 Chrome 子进程，视觉效果即"终端不断往外弹"
2. **新开的空 WindowsTerminal**（PID 3140，12:32:28，无 OpenConsole 子进程）
3. **排查陷阱记录**：此时对 3080 的 HTTP 探测返回"操作超时"而非"连接拒绝"，一度误判为后端在监听；实为 Chrome 重试连接干扰。`Get-NetTCPConnection -State Listen` 确认 3080 根本无人监听

### 处置

- `taskkill /F /T /PID 11332`：终止 Chrome 及其 15 个子进程
- `taskkill /F /PID 3140`：终止空 WindowsTerminal
- 清理后复核：最近 2 分钟内除排查命令自身外无任何新进程

## 四、根因与已知问题（摘自 DEPLOY.md）

1. **npx 静默挂起**：`start-dsh.bat` 在本地镜像代理（8899）未就绪时跑 npx，连接被拒后按 fetch_retries 静默重试数分钟，期间无任何输出、无端口（已复现 120s 无日志无端口）
2. **腾讯电脑管家拦截 Junction 遍历（WinError 448，核心故障）**：npx 缓存清除或 dsh 版本升级后，必须先重跑 `fix_dsh_fallback_patch.py` 再执行启动器
3. **本次新增观察**：dsh Web 前端在后端失联时会持续重连并派生浏览器进程，即使后端已死也会造成"还在弹"的表象；排查时不能只看后端端口/进程，必须同时检查浏览器侧

## 五、后续建议

1. 重启 dsh 前确认腾讯电脑管家未拦截 junction，必要时先运行：
   ```
   /notpython/deepseek-harness-master/fix_dsh_fallback_patch.py
   ```
2. 先启动 `start-dsh.bat`，用 `Get-NetTCPConnection -State Listen` 或 `curl http://127.0.0.1:3080` 确认 3080 真正监听后，再打开 Chrome 页面；不要先用桌面快捷方式开页面
3. 后端异常退出后，随手关闭对应的 Chrome 标签页，避免前端死循环拉进程
4. 长期：可给 dsh 前端加后端失联时的退避（backoff）与停止重连逻辑，从根上消除此类"弹窗"问题
