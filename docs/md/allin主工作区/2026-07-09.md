### ⚠️ 复用级坑：Git Bash 路径 ≠ Python os.path 路径（Windows）
- 在 Git Bash 里 `/d/allin/example` 能被 `cd`/`ls` 正确识别，但**传给 Python 后 `os.path` 会把它规范化成 `\d\allin\example`（丢掉盘符）**，导致 `os.path.isdir` 返回 False、`import mcclone` 失败。症状：`ModuleNotFoundError: No module named 'mcclone'`，且 `sys.path[0]` 是 managed python 的 `python314.zip`（managed 运行时也不自动加 cwd/PYTHONPATH）。
- **正确写法：** 用带盘符的 Windows 路径——`D:/allin`、`D:/allin/example`（正斜杠 + 盘符 Python 能正确规范化为 `D:\allin\example`）。README 的运行命令 `PYTHONPATH="D:/allin;D:/allin/example" python -m mcclone.main_gui` 用的就是这种，是对的。
- **pytest 为何不受此坑影响：** conftest.py 用 `os.path.dirname(os.path.abspath(__file__))` 算路径，得到的是真实 `D:\allin\example`，所以注入正确。手动写 harness 时必须同样用盘符路径，不能抄 Git Bash 的 `/d/...` 形式。
- managed Python 还无视 `PYTHONPATH` 与 cwd（sys.path[0] 恒为 python314.zip），故非 pytest 场景下必须显式 `sys.path.insert(0, r"D:\allin\example")`。
