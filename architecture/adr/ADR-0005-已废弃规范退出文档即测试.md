# ADR-0005 —— 已废弃的规范退出「文档即测试」判定

- 状态：**accepted**（2026-10-28 落地：`g19-docs-refs` 的 `declared_status()` 豁免分支）
- 相关：ADR-0004（文档即测试的判定口径）、SPEC-005 §121（规范状态闭集）

## Problem

ADR-0004 定下「规范判现在为真，记录判当时如此」之后，剩下一类文件无处安放：
**已废弃的规范**。

SPEC-005 §121 早已把状态闭集写成 `生效 / 草案 / 冻结 / 已废弃`，并规定
「**废弃不删除**，改状态并在正文首行写明替代者」。于是这类文件的正文被刻意保留下来，
而正文里必然写着已经不存在的东西——那是原 `siwpan/deepseek-harness` 分发版配套的
启动脚本、依赖锁定文件与分发说明文档。
它们**不是谎话，是证据**：那正是被废弃的那个东西长什么样。

把这类文件交给 g19 判，等于逼出一个残酷选择：

- 要么**删掉证据**（把正文里的路径抹去，好让门禁绿）；
- 要么**编造内容**（把路径改成别的东西，好让门禁绿）。

两条都比「这条引用失效」本身糟糕得多。门禁不该奖励毁尸灭迹。

## Decision

**头部状态为 `已废弃` 的规范整体退出 g19 判定，并计入可见的豁免计数。**

- 识别方式：读文件前 20 行，匹配 `**状态** <值>`；值取自 SPEC-005 §121 的闭集，
  只认 `已废弃`（不连带 `冻结`——冻结件是另一回事，本仓目前也没有）。
- 退出的是**整份文件**（命令与路径都不判），不是只豁免路径：已废弃规范里记的命令
  同样属于那个已退役的对象。
- 豁免**计数可见**（`exempted: deprecated spec (<文件>)=1`），不静默放过。
- 免责的前提是**首行写明替代者**——这是 SPEC-005 §121 的既有要求，
  本 ADR 只是让门禁不再惩罚遵守该要求的行为。若哪天有人用 `已废弃` 当逃避判定的后门，
   exempted 计数与 `git log` 都看得见。

首个适用对象：**SPEC-104**（DSH 分发版使用说明）。其分发版已退役、原远端仓已删除，
治理内核 2026-10-26 并入本仓 `tools/gate/governance/`；已按 §121 改状态为 `已废弃`
并在正文首行写明替代者（现行门禁目录、`architecture/adr/`、`SPEC-105`）。

## Alternatives considered

| 方案 | 为什么没选 |
| --- | --- |
| 照判不误 | 逼出「删证据」或「编内容」，两者都比失效引用本身糟糕 |
| 把已废弃规范移出 `docs/规范/`（改当记录） | 要换编号体系、改 INDEX 登记、改 D4 日期命名规则；语义上它是「被废弃的规范」不是「审计记录」，搬家是掩盖语义 |
| 只豁免路径、仍判命令 | 同一份文件里两套标准，读者更难预测门禁行为；且已废弃规范的命令同样属于退役对象 |
| 在 `exceptions.yml` 里逐条登记 | 一处文件一个例外，条目随废弃数线性膨胀，而「已废弃」本身已是规范自带的声明——读它比维护第二份清单可靠 |

## Consequences

- 正：废弃规范可以诚实地保留原文，门禁不再逼人毁证；SPEC-005 §121「废弃不删除」得以真正执行。
- 正：判定口径收敛到一处——规范头部自己声明的状态，而不是门禁里另存一份清单。
- 负：**出现了一条绕过判定的路径**（把状态改成 `已废弃` 就能免检）。
  缓解靠可见性：豁免计数打印在每次运行的 `exempted:` 行里，且状态变更必然进提交历史。
- 负：g19 对「状态」字段产生了依赖——若将来规范头部格式变化（不再写 `**状态**`），
  该豁免会静默失效（退化为照常判）。自检用例 `deprecated-spec` 覆盖的是「能识别」的那一侧；
  「格式变了」一侧没有机械哨兵，靠本次在 ADR 里写明依赖。
