## 二、两个值得记的坑

### 2.1 git quotepath（中文 Windows）

`git ls-files` 默认把中文路径转义成 `"zhidao/\346\214\207\345\257\274.txt"`，与磁盘路径对不上，导致 bloodmusic 的「指导.txt」被工具误判为未跟踪、跳过清洗。
⇒ 必须 `git -c core.quotepath=false -C <repo> ls-files`。全哥记忆里已吃过这个亏，本轮又踩一次。

### 2.2 路径替换的形态优先级

`cd D:/allin && cmd` 与 `cd D:/allin/sub/path` 两条正则若顺序错，前者会吃掉后者的子路径，产出 `\stay\pq_multiverse\src` 这种既非绝对也非相对的残串。
⇒ 「必须跟 `&&` 或行尾」的收紧判据优先；仓库名作锚点时要把 `-` 与 `_` 归一化（`pq-multiverse` vs `pq_multiverse`）。

## 三、门禁接入与待裁决机制

`tools/publish_area_gate.py`（新建）：调用 repocheck、应用逐项豁免台账、聚合退出码。**不复制任何判据**——判据只有 repocheck 一份。

豁免台账：`tools/gate/audit/publish_area_exemptions.csv`，10 条逐条带实证与 `status`：

- `accepted-exemption`（2 条）：已实证裁决
  - private-radio-stations 的 GPL 是 vendored 上游目录自带 LICENSE，与本仓 MIT 不矛盾；
  - 直播平台的客户端静态常量是公开的第三方值，非持有者密钥。
- `pending-review`（7 条）：**登记但不放行**——版本以 tag 还是清单为准、许可证冲突取哪个，均属业务决策，agent 无权替全哥拍板。
- `--strict-pending` 开关：全哥在场逐项裁决时可让待裁决项也判红。

接入 `scripts/run_all_gates.sh`：发布区缺席时降级 SKIP（`publish_area_gate:skip(no-publish-area)`），与既有 `_run_repo_hygiene` 同款。

**为什么不把待裁决项判红**：139 仓里 7 条全是业务决策，红灯会逼出「为了绿灯随便改版本号/许可证」这种更坏的结果。登记 + 单列 + JSONL 留痕才符合 SPEC-002「高风险逐项确认」。
