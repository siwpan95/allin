# `/allin/docs` — 文档枢纽（Documentation Hub）

> **这是什么**：整个工作区的**唯一文档入口**。所有面向人（以及面向后续 AI 会话）的说明、规则、事实、证据都汇总在这里，
> 并随公开仓 [`siwpan/allin`](https://gitee.com/siwpan/allin) 一起发布 —— **开发过程对任何人透明可读、可复跑、可接手续做**。
> **本目录的规矩**：**只放文档**（脚本→ `/tools/`、产物与归档→ 数据盘的 `archive/`）。
> **大修记录**：2026-09-28 按用户拍板做了一次**系统性整理**（四分类归位 + 总目录 + 规范去日期编号化 + 拆分超长文件 + 索引门禁）。
> 判据与规则见 [`规范/SPEC-005-文档枢纽契约.md`](规范/SPEC-005-文档枢纽契约.md)。

## 二、四分类（**先定性，再找文件**）

| 类别 | 判据（先"是"者胜） | 可变性 | 文件名 |
| --- | --- | --- | --- |
| **[规范](规范/)** | 有人在**将来**必须照它做 | 受控修订 | `SPEC-<号>-<中文短名>.md`，**禁日期** |
| **[事实源](事实源/)** | 是**当前**状态的单一权威台账，别人会来取值 | 就地更新 | 中文名，**禁日期** |
| **[记录](记录/)** | 是**某一次**发生的事的证据/流水 | **只增不改** | `<主题>_<YYYY-MM-DD>.md` |
| **[历史](md/)** | 大修前存量文档树，冻结留证 | **冻结** | 保持原样 |

**ASCII 别名并置**：`规范/`↔`spec/`、`事实源/`↔`facts/`、`记录/`↔`records/`、`md/`↔`历史/`。
内容**只存一份**（真身在中文目录）。别名靠 junction 实现、**不入库**，换机后用
`pwsh -File tools/gate/make_doc_aliases.ps1` 一键重建，`-Check` 校验。

## 三、"规矩为什么现在有牙"

大修的核心不是把文件摆整齐，而是让**指导性文档从"产物"变成"要求"**：

| 机制 | 落地 |
| --- | --- |
| **可引用** | 每份规范有稳定编号 `SPEC-NNN`，引用写 `SPEC-004 §调试铁律 19`，不靠文件名 |
| **有效力** | 头部声明 效力等级 / 状态 / 生效 / 最后修订 / 适用面 |
| **有兜底** | 头部写明**承载体**（哪条门禁把它变成退出码）；**不可机械化的显式写"无"并给理由** |
| **不会过期** | `INDEX.md` 全量登记，`docs_index.py` D1/D2 双向校验 |
| **不会走样** | D3 头部字段、D4 命名（规范禁日期 / 记录必带日期）、D5 分类、D7 卷号连续 |
| **规则→门禁总表** | [`规范/README.md`](规范/README.md) §4（含 DSH 分发版 **18 条**门禁的映射，2026-10-08 实测） |

## 四、边界与维护

**只在枢纽里放**：`.md` 文档、`.txt` 纯文本、说明性 `.yaml`（如端口表）。
**不放**：脚本与工具（→ `/tools/`）、构建/审计产物与归档（→ 数据盘 `archive/`）、二进制与第三方资料、任何令牌/密钥。

**维护三条**
1. **单一事实源**：同一事实只写一份 —— 规则在 `规范/`，当前值在 `事实源/`，过程在 `记录/`；其他地方只放链接。
2. **入库前扫描**：任何新增文档提交前跑一次敏感串扫描（32-hex / `sk-` / `api_key` / 密码 / Cookie），命中即改写为示例值或移出。
3. **改完就同步**：文档里的路径/清单变更时同步更新引用（preset、索引、其他仓），并跑一次门禁 —— 见 `SPEC-003 §创新三原则 2`。

**收尾自检**

```powershell
python tools/gate/docs_index.py --no-baseline --list-all   # 索引契约（存量应为 0）
python tools/gate/docs_index.py --selfcheck                # 门禁自证
pwsh -File tools/gate/make_doc_aliases.ps1 -Check          # ASCII 别名
```
