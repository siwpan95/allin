# 安装包发布评估（2026-08-25）

> 依据（用户观点 + 引用文章共识）：简单工具直接单 exe；复杂软件需要安装包（引导安装/卸载/升级）；是否需要安装包取决于**软件生命周期长度与用户规模**。

## 一、判定框架（5 条硬指标）

| 指标 | 安装包能提供 | 单 exe 的短板 |
|---|---|---|
| 用户规模（给别人用） | 引导式安装、桌面/开始菜单入口 | 用户要自己找解压目录、被杀软误报时无白名单引导 |
| 生命周期（持续迭代） | 版本号+升级通道+卸载干净 | 换新版=手工覆盖，残留配置无人管 |
| 组件复杂度（多服务/外部依赖） | 统一布置 Node/ffmpeg/MediaMTX/模型 | 用户自己装依赖，路径对不上就崩 |
| 系统集成（自启动/托盘/右键/文件关联） | 安装器注册这些是本职 | 单 exe 做不了或要做脏活 |
| 数据/资产（配置目录/大资源） | %APPDATA% 目录、可选组件、校验下载 | 数据散落在 exe 旁，升级即丢 |

## 二、G 盘项目分级结论（对照平台 95 项目）

### A 级：值得做安装包（复杂/服务/系统集成，7 个）

| 项目 | 理由 | 安装包要点 |
|---|---|---|
| **allin-platform** | 生命周期最长、面向全项目、Node 依赖、频繁迭代 | Inno Setup：便携 Node+依赖+registry 配置+桌面入口+升级版本号 |
| **private-radio-stations 簇**（radio/video/portal） | Node+Cordis+MediaMTX+ffmpeg 四依赖、服务型常驻 | Inno Setup：全套依赖+服务/tray 注册+卸载停止服务 |
| **pywallpaper** | 壁纸常驻（自启动+托盘）+4972 配方资源+持续升级 | Inno Setup：exe+recipes+自启动+卸载即恢复壁纸 |
| **cellular_automaton** | 壁纸常驻+141 规则库 | 同上 |
| **shikonghuaban** | 壁纸/可视化常驻+PortAudio 依赖 | 同上（PortAudio 检测指引） |
| **audio_separator** | Demucs 重模型+Web 服务 | 安装器+模型可选组件（分卷下载） |
| **station**（音频工作站） | VST 宿主+复杂依赖+专业软件形态 | Inno Setup，VST 桥接依赖一并布置 |

### B 级：单 exe / 便携 zip 即可（简单工具与游戏，约 60 个）

- 街机 10 游戏 + 小游戏（mahjong/fish/dungeon 等）→ 单 exe（街机已按此方案跑通）；
- tools 组小工具（renamer/subtitle/pdf/print/yasuo/auto-clicker/repocheck 等）→ 单 exe；
- CLI 工具（audio_pipeline/novel/video_generator 等）→ 便携 zip（用户即开发者）。

### C 级：不做安装包（开发者分发）

- alloy（引擎）→ pip/源码（gitee 仓）；particle/bloodmusic（库）→ pip。

### 修正（2026-08-25 用户拍板）：musickit 是服务型，不是资源包

- **musickit 完整流程 = 提示词（music_prompt_generator）→ 混音（remix/mixer）→ 电台（radio）**——此前把 radio 单独拉出来讨论是错的：radio 已完成架构化（Node+Cordis monorepo），但 musickit 本体**尚未架构化**，这一点纳入进程（下一步立项）。
- musickit 安装包 = **基本框架**（提示词/混音/电台三段的编排+服务），采样库/资源包（117GB）不进安装器，作为独立资源包随下载器分发。
- musickit 与 allin-platform 同为服务型安装包路线。

## 三、技术选型

- **Windows GUI/服务应用**：Inno Setup（免费、脚本化、中文路径友好、自启动/卸载/升级一体、支持可选组件）；
- **Node 应用**：Inno Setup 打包便携 Node 运行时 + node_modules + 服务注册；
- **重资产**：安装器 + 可选组件下载（安装时只放核心，模型/采样首次运行下载校验）。
