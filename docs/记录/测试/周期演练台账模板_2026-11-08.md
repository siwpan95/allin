# 周期演练台账模板（Periodic Drill Ledger）

> **说明（R-31）**：本台账对应 R-31，用于把周期演练（如月度审计、恢复演练）的执行情况**留痕与对账**。仓库已存在接入计划任务的周期脚本，本台账**不重复造轮子**，只做记录与对账的汇总层。

---

## 1. 既有周期项锚点（已接入计划任务，仅记录 / 对账，不重做）

以下为仓库既有、已接入计划任务的周期自动化项，本台账对其做逐次执行留痕与对账：

| 既有项 | 脚本位置 | 周期 | 角色 |
|--------|----------|------|------|
| 月度审计 | `tools/deploy/monthly-audit-task.ps1`（`monthly_audit.py` 为审计逻辑） | 每月（由计划任务触发） | 已接入计划任务 |
| 恢复演练 | `tools/deploy/restore-drill-task.ps1`（`test_restore_drill.ps1` 为演练逻辑） | 每月（由计划任务触发） | 已接入计划任务 |

> 原则：执行仍由上述脚本在计划任务中完成；本台账只登记「最近一次执行日期 / 结果 / 证据路径」，用于审计与对账，避免重复实现周期调度。

---

## 2. 台账字段（逐行填充）

每个演练项占一行，按需新增：

| 演练项 | 周期 | 最近一次执行日期 | 结果 | 负责人 | 下次计划 | 证据路径 | 备注 |
|--------|------|------------------|------|--------|----------|----------|------|
| （如：月度审计 / 恢复演练 / 或新增 ET 章程演练） | cron 或「每月第 N 个工作日」 | YYYY-MM-DD | PASS / FAIL / SKIP | 姓名 | YYYY-MM-DD | 指向输出日志/报告的绝对路径 | 异常说明 / 跟进 |
|        |      |                  |      |        |          |          |      |

### 字段定义
- **演练项**：演练名称，既有的直接引用 `monthly-audit-task.ps1` / `restore-drill-task.ps1`；新增项写明章程编号（关联 R-25）。
- **周期**：cron 表达式，或自然语言「每月第 N 个工作日」。
- **结果**：PASS / FAIL / SKIP 三选一；FAIL 必须在备注与证据路径中可追溯到根因。
- **证据路径**：必须可复跑 / 可审计——指向脚本输出、日志或报告文件，而非口头结论。
- **关联**：与 R-25 章程联动时，在「备注」填写章程编号与会话记录编号。

---

## 3. 对账规则（R-31 闭环判定参考）

- 已接入计划任务的既有项：以脚本实际执行产出为证据，台账逐行登记。
- 新增 ET 章程演练：须有对应《探索性测试章程模板》编号 + 《ET会话记录》且要素齐备。
- 抽查 2 个会话要素 100% 齐备、故障注入-恢复记录可复跑，方视为该维度闭环。
- 本台账由人工逐期填充，脚本不自动写此表（仅提供证据）。
