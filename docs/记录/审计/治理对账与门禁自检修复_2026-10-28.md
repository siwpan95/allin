## 三、发现与处置

### 3.1 根因 A · 门禁解释器未钉死 → `g18-exceptions` 假红（环境错配，非仓库缺陷）

- **现象**：`g18-exceptions` 报 `ledger-unusable: PyYAML 不可用（无法解析 exceptions.yml）`。
- **根因**：`tools/gate/governance/run.ts` 按 `python3` → `python` → `py -3` 顺序探测解释器（`DSH_GOVERNANCE_PYTHON` 可覆盖）。
  本机 `python3` 命中 WorkBuddy 便携 **3.13.14**，**无 PyYAML**；而仓内 `.venv` 有 **yaml 6.0.3**。
  ⇒ 同一份代码在不同机器上结论不同。
- **复验**：`DSH_GOVERNANCE_PYTHON=<仓根>/.venv/Scripts/python.exe` 重跑 ⇒ `g18-exceptions -> exit 0`。
- **处置**：**未改代码**（解释器选择是环境变量，本就留了覆盖口）；本条作为**遗留建议**登记（见第六节）。

### 3.2 根因 B · `g15-docs-contract` 自检假阳性（**真缺陷，已修**）

- **现象**：`g00-meta` 报 3 条 BLOCK：
  `self-check exited 1` / `proved nothing about clean input` / `reported 1 false positive(s)`。
- **根因链**（逐段实测）：
  1. `g15_docs_contract.py` 的 `build_fixture()` 用 `os.symlink()` 建 4 个 ASCII 别名，
     且 `except OSError: pass` **静默吞掉**失败；
  2. Windows 上 `os.symlink` 需管理员或开发者模式 → 本机实测 `OSError 22`（**建不出来**）；
  3. 而 junction（`mklink /J`）**免管理员可用** → 实测退出码 0、别名建成；
  4. 别名静默缺失 ⇒ D6「别名缺失」在**干净用例**里误报 3 条 ⇒ `clean=0, misreports=1` ⇒ 元门禁判红。
  （仓内 `tools/gate/make_doc_aliases.ps1` 用的是 junction，与此同源。）
- **处置**：新增 `make_alias()` —— 符号链接优先，Windows 退 junction（`mklink /J`），
  **建不出来时响亮 WARN，不再静默吞掉**；并把失败原因打到 stdout。
- **复验**：`g15_docs_contract.py --selfcheck` → `SELFCHECK {"caught":9,"clean":1,"misreports":0}` exit 0；
  `g00_meta.py` → `blocking 0`（19 门禁全契约自证通过）。

## 六、遗留建议（**本轮未做，待排期**）

1. **门禁解释器应钉死**：`run.ts` 的 `python3 → python → py -3` 探测链会因机器而异，
   本次已实测「同一份代码、同一提交，不同解释器 ⇒ 一绿一红」。
   建议在 `scripts/run_all_gates.sh` 与 CI 里显式走仓内 `.venv`，或固定 `DSH_GOVERNANCE_PYTHON`。
2. **`g18-exceptions` 的 SELFCHECK 输出格式与契约文本不一致**：实际输出
   `SELFCHECK {"caught": 4, "clean": 1, "misreports": 0}`（冒号后带空格），
   契约（RULES.md §自证有效）写的是 `SELFCHECK {"caught":N,"clean":M,"misreports":K}`（无空格）。
   当前元门禁正则 `^SELFCHECK (\{.*\})$` 仍能匹配，**不影响判定**；但建议统一格式，避免将来收紧正则时误伤。
3. **提交信息里的门禁结论应当可复现**：`ef2a545` 自称「19/19 门禁 clean」，
   而在无符号链接权限 + 无 PyYAML 的机器上跑出来是 18/19。
   建议发版前用**与 CI 相同的解释器**复跑，并把退出码贴进提交信息。
4. **`repocheck` 的 tkinter 依赖**：CLI 模式目前也被模块级 `import tkinter` 卡住，
   建议后续把 tkinter 降为 GUI 模式的可选依赖，让 CLI 在精简解释器上也能跑。
