- **2026-10-28** [windows] Windows 上删含 `.git` 的目录：`shutil.rmtree(ignore_errors=True)`
  遇只读文件会**静默失败**，留下半删目录，让后续 `git clone` 报
  「already exists and is not an empty directory」这类假失败。
  正确做法：先 `os.walk` 逐文件 `os.chmod` 清只读属性，再带 onerror 回调 rmtree。

  （实测第 2~3 次成功；单次超时给足 600s 以上，大仓 700s+ 也正常）。

- **2026-10-28 11:40** [windows] Windows 上 `os.symlink` 建**目录别名**需要管理员或开发者模式，无权限时抛 `OSError 22`；
  免管理员的替代是 **junction**（`mklink /J`，退出码 0 即成），Python 里用 `subprocess` 调即可，
  `os.path.samefile()` 对 junction 与符号链接都判同源 ⇒ 两者的判定口径一致。
  ⚠ **更危险的不是建不出来，是 `except OSError: pass` 把它吞掉**：门禁自检夹具里这会让
  「干净用例」被 D6 误判成不干净 ⇒ 元门禁报红，而真凶（别名没建成）无人看见。
  建不成时必须响亮报出，别让「静默」变成假阳性的温床。

- **2026-10-28 12:14** [governance] **别拿管道末端的退出码当命令的退出码**。
  `cmd | tail -20; echo $?` 打印的是 `tail` 的退出码——我据此把 repocheck 的失败读成了「退出码 0」。

  同理，**文档里写的退出码也要这么复核**：README「B 仅剩规则 1 固有项」实测是退出码 1、5 条 error。

- **2026-10-29 10:10** [governance] **「缺对象」≠「不是祖先」**：`git merge-base --is-ancestor`
  对「确实不是祖先」和「本地根本没这个对象」返回同一个非零退出码。凡拿远端 sha 判同步方向，
  必须先 `git cat-file -e <sha>^{commit}` 确认对象在本地；不在就先补取该分支的远端跟踪 ref
  （只动 `refs/remotes/*`，别碰本地分支/索引/工作树），取不到就记 SKIP/UNVERIFIED 并打印原因，
  绝不臆造「分叉」。实证：本仓落后 origin/master 3 笔，旧判据报 `DIVERGED` 并叫我去 rebase，方向反了。
  反向同理：**`git status` 干净 + ahead/behind 0/0 可能只是 `origin/BR` 缓存正指向本地 HEAD**，
  陈旧缓存的净效果是「看不见落后」，不能当同步证据。
- **2026-10-29 10:55** [governance] **同一段正文存在多份派生副本时，手抄必漂，且漂的那份
  往往正是「实际被读取」的那份**：治理段一份正文 + 三份副本（存档件 / npm bundle / 已挂载
  profile 层），其中挂载层在仓外，**仓内任何门禁都看不见它** —— 实测它落后了整整一代
  （仓内 19 道门禁，挂载层仍教「15 道」）。修法不是「更小心地抄」，而是：① 一个幂等写入器
  （只改标记段、保留缩进/BOM/EOL），② 一个 `--check` 判新鲜（落后 exit 3），
  ③ 校验脚本里加「副本 vs 正文」逐行比对，④ 把 `--check` 并进跑齐脚本。
  判据要点：定位标记段必须**按标记整行**锚定，别用「子串首次出现」——注释里提一句
  `GOVERNANCE:BEGIN/END` 就会把块起点拉到注释上，反而让副本「靠注释过关」。
