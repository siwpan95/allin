# ADR-0009 —— 架构资产（SVG + adr/）对账门禁固化

- 状态：**accepted**（2026-11-04 落地：`tools/gate/check_arch_assets.py` + 接入 `scripts/run_all_gates.sh` ⑧）
- 相关：ADR-0007（架构叙事迁入 SPEC-204，图源与 adr/ 留在判据外）、ADR-0004（文档即测试判定口径）

## Problem

ADR-0007 把架构**叙事正文**迁入 SPEC-204 后，`architecture/` 只剩两类资产：
两张 SVG 图源与 `adr/` 现行决策。二者仍在文档契约判据（docs_index / g19）之外——
这是有意豁免，但豁免范围没有兜底检查。2026-11-04 系统架构体检验证了代价：

- ADR-0006/0007/0008 三个文件存在近月，`adr/README.md` 索引却只登记到 0005，无人能拦；
- 两张 SVG 缺 `packages/`、`website/` 子系统，且图内 4 处数字漂移静默存活
  （门禁 15 道→20 道、D1–D8→D1–D14、124/135 仓→138）——与 ADR-0007 记录的
  「正文数字漂移两代」是同一类债，只是换了载体。

## Decision

- 新增 `tools/gate/check_arch_assets.py`（纯标准库，单落点，不进 20 道门禁套件），
  六项对账全部**从真身推导**、不抄声明：
  A. adr/ 索引 ↔ adr/*.md 文件集合（双向差集 + 状态闭集 proposed/accepted/superseded + 链接名核对）；
  B. SVG 门禁数 ↔ `tools/gate/governance/gates/` 实际文件（编号范围 / 总数 / 缺号）；
  C. SVG docs_index D 范围 ↔ SPEC-204 声明（SPEC-204 受 g19 管辖，作传递锚）；
  D. SVG + SPEC-204 仓数 ↔ `PORTFOLIO.md`（Gitee API 生成物，仓数的离线代理）；
  E. 两张 SVG 标题必须带「YYYY-MM-DD 修订」日期（陈旧度可见，无门禁也能人眼判龄）；
  F. website 默认端口 ↔ `docs/事实源/ports.yaml` 登记（README「已登记」声明从口头变机检）。
- 接入 `scripts/run_all_gates.sh`（⑧，与 `check_readme_refs.py` 同款挂法）。
- 不做成 g21 进 run.ts 套件：对账对象在 docs/ 契约体系之外，属独立辅助门禁；
  若未来对账面扩大（如 SVG 节点级结构断言）再评估升级。

## Consequences

- `architecture/` 从「全免检」变为「六项声明受机检、结构与美术仍免检」——豁免的代价收敛到可接受面；
- SVG 数字、ADR 索引、端口登记三类漂移从「静默存活」变「跑批即红」；
  代价是每次跑批多 <0.2s（纯文本解析，无网络无子进程）；
- PORTFOLIO.md 措辞（「共 N 个仓库」）成为对账锚：生成脚本 `build_portfolio.py`
  改输出格式时必须同步本脚本（否则报「失去基准」而非静默漏检——fail-loud）。
