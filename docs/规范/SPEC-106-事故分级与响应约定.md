## 1. 与单人团队的关系

本仓维护主体是一人 + AI 协作者，没有 on-call 轮值。因此：

- **决策人 = 全哥**（唯一）；**备份决策路径 = 在场的 AI 协作会话**（按本规范 §2 的 SEV
  行动基线自主推进，但**不可**代替人做"接受数据丢失"这类不可逆决定）。
- "响应时限"约束的是**开始处置的动作**，不是修复完成时间——单人团队允许中断，但
  SEV1/SEV2 必须先完成 §2 表中"T+15min 内"的最小动作（确认影响面 + 四段式记录开账），
  才允许搁置去睡觉。

## 2. SEV 分级（结合"本地部署 + 单人"语境校准）

| 级别 | 定义（本仓语境） | 典型例子 | 首个动作时限 |
| --- | --- | --- | --- |
| **SEV1** | 数据不可逆丢失或等效核心功能全面失效，且**无恢复路径** | website 主密钥丢失（全量密文不可解密、全账号不可登录）；site.db 损坏且无备份 | 立即开四段式记录；止损评估 1h 内出"可救/不可救"清单 |
| **SEV2** | 主链路被阻塞或**静默失效**（无感知的防线丢失），但有明确恢复路径 | CI 门禁双侧全红阻塞推送；DSH preset 挂载静默降级（治理段丢失）；platform 起不来 | 15 分钟内开始处置 |
| **SEV3** | 单子系统降级，有绕行路径 | 单道门禁误报（其余绿）；website 单页异常 | 当日处置 |
| **SEV4** | 观感问题 / 无功能影响 | 文档错字、日志噪音 | 顺手修或记账 |

> 评级存在双值时**就高不就低**；"泄露可轮换止损 → SEV2、丢失不可轮换 → SEV1"这类
> 区分（见 2026-11-04 演练情景 A）在评级时必须写明依据。

## 3. 响应通用流程（四步）

1. **确认影响面**（先于一切修复）：哪些子系统/数据/会话受影响，哪些明确不受影响。
2. **止损优先于根因**：能回滚先回滚（回滚不涉门禁基线操作——基线棘轮只拦新增），
   能隔离先隔离；修复在止损后进行。
3. **四段式记录开账**（见 §4）：T0 起记，边处置边补，不许事后凭记忆重写时间线。
4. **复盘收口**：5 Why + 行动项（带状态跟踪）+ "该事故该封印成哪道门禁"的判定
   （走 [`记录/专题/治理门禁哲学与事故表_2026-10-26.md`](../记录/专题/治理门禁哲学与事故表_2026-10-26.md) 的映射）。

## 4. 四段式事故记录模板（落 `docs/记录/事故/<事件>_YYYY-MM-DD.md`）

```markdown
# <事件名>（SEV<x>）

> **T0** <发现时间> ｜ **发现途径** <...> ｜ **状态** 已恢复 / 持续中 / 搁置
> **影响面** <子系统 / 数据 / 会话；显式写出"不受影响"的边界>

## 事态（一句话）
## 已知（处置开始时的确凿事实，含证据路径）
## 时间线（T0 / T+15min / T+1h … 每个动作一行，含当时看到的现象与依据）
## 已做（动作 + 退出码 / 复现命令）
## 下一步（编号清单，做完打勾）
## 5 Why（ ≥5 层，第 5 层必须指向"流程/门禁缺口"而不是"人失误"）
## 行动项（| # | 动作 | 状态 | 证据 |——状态只允许 待办/进行/完成/放弃(写理由)）
## 预防（该事故映射到哪道既有门禁；若无覆盖 → 提出新门禁提案）
```

两份历史复盘（2026-08-20 / 2026-08-28）按"只增不改"纪律保留原样，**不**回填本模板。

## 5. CI 门禁全红 triage（SEV2 固定四步）

> 先例：2026-10-31 Windows job 因步骤顺序挂红（`gates.yml` L115–119 注释实录）。

1. **本地复现**：`bash scripts/bootstrap.sh && bash scripts/run_all_gates.sh`
   （与 CI 完全同一条命令——若本地也红，说明的不是 CI 环境问题，而是"照文档做会失败"）。
2. **按退出码分类**：`3`=环境错（先修环境）；`1`=新阻断（`--no-baseline --list-all`
   看全量，对照"事故类型→门禁"表反查是哪类事故复发）；`2`=用法错（查调用方）。
3. **排除门禁自腐**：若疑似门禁自身误报，先跑
   `npm run check:governance:selfcheck` 证明门禁还能抓到注入缺陷。
4. **回滚 / 前滚决策**：revert 引入提交（安全：基线棘轮只拦新增）或前滚修复；
   变绿后**双通道推送 + `git ls-remote` 复核**（2026-10-31 交接卷验收口径）。

改动 `.github/workflows/` 或 `scripts/run_all_gates.sh` 本身时，必须双平台本地各跑一次
bootstrap + gates（CI 配置漂移不在 20 道门禁覆盖内，唯一防线是这个动作纪律）。
