### 1.5 核心交互流程

**读路径（两页共用）**：
SSR 渲染骨架（各卡片显示「加载中」占位 + `aria-busy="true"`）→ JS 立即 `fetch('/member/api/governance/overview')` → 填充卡片 → 之后每 5s 轮询（页面不可见时暂停，恢复可见立即补拉一次）→ 每次响应刷新「数据截至」时间戳。

**写路径（仅 /admin/governance）**：
点「停止」→ 按钮进入武装态（文案变「再次点击确认」，3s 未确认自动复位）→ 再点 → `POST /member/api/governance/entries/:id/stop`（携带 `X-CSRF-Token` 头）→ 成功：行内 notice（ok）+ 立即重拉 overview + 刷新本行状态徽；失败：行内 notice（error）+ 文案按响应 `code` 映射（见 §4）。

## 2. 关键页面设计：五态覆盖（AC 要求逐卡三态起，这里统一按五态口径给全）

> 状态字典：正常=实时数据；空=上游明确返回空集合；加载=首帧或切换中；错误=上游故障；无权限=角色/会话不满足。降级态（PORTAL_UNREACHABLE / UPSTREAM_TIMEOUT）归入「错误态」的两个分类子型，**页面整体始终 200，不报错**（P1b 决策三）。

### 平台概览卡（gov-overview-card）

| 态 | 表现 |
|---|---|
| 正常 | kv 列表：版本 / uptime / 端口 / 登记 total / running / invalid；标题右侧 `tag--ok ● 正常` 徽（含 ● 图标） |
| 空 | 上游返回 `library.total=0` 时登记区显示「尚无登记项目」muted 文案，portal 字段照常 |
| 加载 | 骨架：kv 键名照常、值区 `▒▒▒` 闪烁占位（`prefers-reduced-motion` 时静态灰色块），`aria-busy` |
| 错误·平台未启动 | 整卡内容替换为 `notice--warn`：「平台未启动——治理面（portal）当前离线，其余站点功能不受影响」+ ▲ 图标；卡片标题徽变 `tag--warn ▲ 未连接`；轮询继续（恢复后自动回到正常态） |
| 错误·超时回快照 | 展示上次成功快照数据，卡顶插入细条 `notice--info`：「网络波动，数据截至 HH:MM:SS（快照）」+ ◷ 图标；时间戳醒目 |
| 无权限 | 页面级拦截：匿名 302→login（沿用 denyLogin），不存在卡内态 |

### 门禁健康卡（gov-gate-card）

正常：`lastRunAt / lastOkAt / escapeRate` 三项 kv + 状态徽（escapeRate=0 且 lastOkAt 近于 lastRunAt → `tag--ok ● 门禁健康`；超 24h 未跑或 escapeRate>0 → `tag--warn ▲ 降级`）。空：`readable:false` 或无门禁运行记录 → 「尚无门禁运行留痕（gate-runs.jsonl 为空）」。加载：同上骨架。错误：平台未启动 → 同概览卡降级卡；数据字段缺失 → 显示「数据不可读」+ code。无权限：页面级。

### 编排健康卡（gov-orchestration-card）

> **三态口径（2026-11-04 契约增量，覆盖前版两态设计）**：判据由 `healthy` 布尔（判红三条件：`routesReadable=false ∨ 任一 error ∨ drift(error 级)>0`）与 `lastCheckError` 共同决定。

| 态 | 判定 | 表现 |
|---|---|---|
| ① 门禁自身故障 | `lastCheckError` 非空 | 红卡：`tag--error × 判据门禁未正常运行`，卡体显示 `lastCheckError.code` + 截断后的 msg（≤500 字符，超长折叠）；提示「g21 门禁上次运行崩溃，漂移结论不可信」 |
| ② 跑完全绿 | `lastCheckError` 为空 且 `healthy:true` | `tag--ok ● 双形态已同步` + `driftCount` + `lastCheckAt` |
| ③ 判出漂移 | `lastCheckError` 为空 且 `healthy:false`（存在 error 级漂移或路由表不可读） | 红卡 `tag--error × 存在漂移` + error 级漂移清单（id/side/reason/severity）；warn 级漂移**不判红**，只在折叠区计数展示（`tag--warn ▲ N 条 warn 级差异`） |

空：routes 为空数组且 `readable:false` → 「编排路由表不可读（routes.yaml 缺失或未登记）」，归入态③（判红），不渲染成「0 条路由=健康」。加载/错误/无权限：同上。

### 路由健康表（gov-route-health）

正常：15 行表格，每行双形态归属用 `tag--info`（workbuddy / dsh）；漂移行整行加 `×` 前缀 + 红色 tag + reason 列。空：同编排卡空态文案。加载：表体一行「加载中…」占位行。错误：表体替换为降级 notice 行。无权限：页面级。交互：默认折叠只显示摘要（漂移数），点「展开路由明细」切换——15 行表格在 member 页是次要信息。

### 项目列表（gov-entry-list，仅 admin 页）

正常：行式列表（复用 .table），每行状态徽带图标（● running 绿 / ■ stopped 灰 / ▲ invalid 黄）+ 操作按钮。running 行只有「停止」，stopped 行只有「启动」，invalid 行无按钮 + 行内说明。空：`library.total=0` → 「注册表中没有项目」。加载：骨架行。错误：整区降级 notice，操作按钮全部禁用（`disabled` + `aria-disabled`）。无权限：member 访问 `/admin/governance` → 403 页（沿用 requireRole 错误页 + 审计 `authz.denied`），列表不渲染。

### 审计流水过滤视图（gov-audit-filter，仅 admin 页）

正常：SSR 渲染（GET 查询参数驱动，非 JS——过滤是低频操作，不值得做成前端状态），过滤条为 `<form method="get">`：动作前缀输入框、结果下拉（全部/ok/fail）、条数（20/50/100）。空：过滤无命中 → 「没有匹配的审计记录」+ 「清除过滤」链接。加载：SSR 无此态（同步渲染）。错误：数据库异常走既有 error.ejs 500 友好页。无权限：页面级 403。设计要点：**只读视图不参与轮询**，避免 admin 页打开时审计表格闪动。

### 3.2 关键骨架（status-pill + 写操作按钮约定）

```html
<!-- status-pill 输出形态（EJS） -->
<span class="tag tag--<%= state %> gov-pill" role="status">
  <span class="gov-pill__icon" aria-hidden="true"><%= icon %></span>
  <span><%= label %></span>
</span>

<!-- 启停按钮（entry-list 内，admin 页） -->
<form class="gov-action" method="post" action="/member/api/governance/entries/<%= e.id %>/<%= e.status==='running'?'stop':'start' %>">
  <input type="hidden" name="_csrf" value="<%= csrfToken %>">
  <button class="btn btn--sm <%= danger ? 'btn--ghost' : '' %>" type="submit"
          data-gov-action data-confirm="停止该项目？" data-id="<%= e.id %>">停止</button>
</form>
```

- CSRF **双通道**：表单隐藏域 `_csrf`（form 兜底路径）+ `governance.js` 对 fetch 统一从 `<main data-csrf="<%= csrfToken %>">` 读值加 `X-CSRF-Token` 头。已核读 `middleware/auth.js`：`csrfProtect` 接受 `req.body._csrf || req.headers['x-csrf-token']`，两通道任一即可，表单兜底保证 JS 失效时写操作仍可用（渐进增强）。
- 防重复提交：`data-gov-action` 按钮 in-flight 时 `disabled` + 文案「执行中…」；两段式确认（停止类）：首次点击→armed（文案「再次点击确认停止」，加 `gov-btn--armed` 类），3s 未确认自动复位；确认后提交。启动类单段直接提交。
- 通知体系：成功/失败不新造文案域——失败/成功信息在卡片顶部以 `.notice--error / .notice--ok` 行内呈现（同 admin.ejs 解密失败的行内 notice 惯例）；URL 级 notice 仅在两段确认超时等场景复用 `notices.js`（新增两条 code：`governance_action_done` / `governance_action_fail`，【待确认】是否需要，fetch 场景多数无需整页跳转）。

### 3.3 状态色语义（无障碍基线）

| 语义 | 色（复用既有变量） | 图标 | 文本 |
|---|---|---|---|
| 健康/正常 | `--ok` (#34d399) | ● | 正常 / 已同步 / running |
| 降级/警告 | `--warn` (#ffd166，同 --amber) | ▲ | 降级 / 未连接 / 漂移计数>0 |
| 故障/失败 | `--error` (#ff5c7a) | × | 失败 / 存在漂移 |
| 快照/陈旧 | `--cyan` (--info 语义) | ◷ | 数据截至 HH:MM:SS |
| 停止/未知 | `--dim` | ■ | stopped / 不可读 |

铁律：**任何状态徽必须有图标 + 文本，颜色只是第三冗余**；轮询刷新用 `aria-live="polite"` 的容器承载「数据截至」行，读屏用户可感知更新但不打断。

## 4. 状态与数据流

### 4.1 轮询节流策略

| 项 | 规则 |
|---|---|
| overview 轮询 | 5s（对齐 library 页既有惯例）；`document.hidden=true` 时暂停，`visibilitychange` 恢复时立即补拉 |
| orchestration 轮询 | 30s（路由表变化频率远低于运行态；减少无谓上游读） |
| 轮询节流 | 单飞锁（in-flight 时不叠加下一轮）；连续 3 次失败退避到 15s，成功后恢复 5s |
| 超时 | 前端 `AbortController` 8s 硬超时（后端代理自身 3s，前端超时只是兜底防悬挂） |
| 写后刷新 | start/stop 成功后立即触发一次 overview 拉取（不等下个 5s 周期） |

### 4.2 代理响应包装（与 backend-engineer 的契约，前端按此消费）

```jsonc
// GET /member/api/governance/overview → 永远 200（除 401/403 鉴权失败）
{
  "ok": true,
  "degraded": null,            // 或 { "code": "PORTAL_UNREACHABLE" | "UPSTREAM_TIMEOUT", "message": "…" }
  "snapshotAt": "2026-11-04T21:47:43+08:00",  // 本次真实上游时间；降级时为缓存时间
  "data": { "portal": {...}, "library": {...}, "alerts": {...}, "gates": {...}, "orchestration": {...} }
}
// GET /member/api/governance/orchestration → 同包装，data = { routes, drift, lastCheckAt, readable,
//   lastCheckError,   // g21 门禁自身崩溃信息 {code, msg≤500}，非空即判红（门禁故障态）
//   healthy           // 布尔：false 当 routesReadable=false ∨ 任一 error 级 drift ∨ drift>0（终稿口径）
// }
// drift 条目：{ routeId, side, reason, severity: "error"|"warn" }
//   error → 进漂移清单（判红）；warn → 仅折叠区计数，不判红
// 数据源：tools/gate/audit/g21-runs.jsonl 尾行（bridge 侧消化，前端不感知文件）
```

**UI 标注规则（AC）**：
- `degraded.code === 'PORTAL_UNREACHABLE'` → 各卡渲染「平台未启动」降级卡（▲/tag--warn），页面标题行显示 `tag--warn ▲ 平台未启动`；
- `degraded.code === 'UPSTREAM_TIMEOUT'` → 照常渲染 `data`（缓存快照）+ 标题行 `tag--info ◷ 数据截至 {snapshotAt 本地化 HH:MM:SS}（快照）`；
- `degraded === null` → 正常显示「数据截至 HH:MM:SS」，快照字样不出现；
- `PORTAL_FORBIDDEN`（围栏被改）→ 按 P1b fail-loud 口径渲染 `notice--error` 报警卡（× 故障），不静默。

### 4.3 fetch 错误分类处理（governance.js）

| HTTP | 处理 |
|---|---|
| 200 | 按 degraded 渲染 |
| 401 JSON（code=LOGIN_REQUIRED） | 停轮询，`location.assign(loginUrl)`（响应体已带，对齐 denyLogin 结构） |
| 403 JSON（code=FORBIDDEN） | 停轮询，页面顶部 `notice--error`「权限不足」 |
| 5xx / 网络层失败 | 卡片顶部行内 `notice--error`「治理数据暂时不可用」，轮询退避，不清空已渲染数据（避免闪空） |

### 4.4 前端工程落点

- `governance.js` 结构：IIFE（对齐 main.js 风格），四个模块函数：`poller`（节流/单飞/退避）、`render`（按 §3.1 契约重绘卡片体）、`actions`（写操作 + 两段确认 + 防重复）、`staleBadge`（时间戳格式化）。无框架、无依赖、`'use strict'`、var/function 旧式写法保持与 main.js 一致。
- 路由组 `routes/governance.js`：`requireAuth` 挂 `/member/dashboard` 与两个 GET 代理端点；`requireRole('admin') + csrfProtect` 挂 POST 写端点与 `/admin/governance`；`server.js` 注册一行。写成功由 backend 侧落 `audit_log`（`governance.entry.start/stop`），前端无需关心。
- 样式追加：cyberpunk.css 末尾追加 `.gov-*` 段（骨架闪烁动画、armed 按钮态、pill 图标间距、折叠明细），只消费既有 CSS 变量；补 `prefers-reduced-motion` 覆盖（骨架动画关闭）。

## 7. 前端验收清单（可直接转 QA 用例）

**页面可达与权限**
1. 匿名 GET /member/dashboard → 302 到 /login?next=/member/dashboard&notice=login_required。
2. 匿名 Accept:application/json GET /member/api/governance/overview → 401 JSON，code=LOGIN_REQUIRED，含 loginUrl。
3. member 角色登录 GET /admin/governance → 403 页面，文案「仅管理员」，audit_log 新增 authz.denied。
4. member 角色 POST /member/api/governance/entries/:id/stop（带合法 CSRF）→ 403 JSON code=FORBIDDEN，audit_log 有 authz.denied。
5. admin 正常访问两页 → 200，页面结构含 §1.3/§1.4 全部区块。

**降级与降级标注**
6. platform 停止状态下打开看板 → 页面 200，各卡显示「平台未启动」降级卡（▲ 图标 + tag--warn），无任何 5xx/报错堆栈。
7. platform 模拟超时（>3s）→ 页面 200，展示缓存快照 + 「数据截至 HH:MM:SS（快照）」标注，QS：时间戳与缓存时刻一致。
8. portal 恢复后 ≤10s 内看板自动回到正常态（轮询自愈）。
9. PORTAL_FORBIDDEN 场景（伪造围栏）→ 故障报警卡（× + tag--error），非静默。
10. orchestration 端点 routes.yaml 缺失 → 编排卡显示「路由表不可读」空态，且按判红三条件归入红卡（不显示为「0 条=健康」）。
11. **编排卡三态区分（门禁崩溃行用例）**：
    a. mock `lastCheckError` 非空 → 编排卡显示红卡「判据门禁未正常运行」+ error code，**不**渲染漂移清单（崩溃时漂移结论不可信）；
    b. mock `healthy:true` → 绿徽「双形态已同步」；
    c. mock 仅含 `severity:"warn"` 的 drift 条目 → 卡片仍为绿徽（不判红），折叠区出现「N 条 warn 级差异」warn 计数；
    d. mock 含 `severity:"error"` 条目 → 红卡「存在漂移」+ 漂移清单仅列 error 级条目，warn 条目不出现在清单中。

**写操作**
12. admin 点击「停止」→ 首次进入武装态（文案变化），3s 未确认自动复位，未发出请求。
13. admin 二次确认 → 请求携带 X-CSRF-Token，成功后行内 ok notice + 状态徽即时更新（无需手动刷新）。
14. 缺失/错误 CSRF 头的写请求 → 403，audit_log 有 csrf.failed，UI 行内 error notice。
15. in-flight 期间按钮 disabled 且文案「执行中…」，连点不产生第二个请求。
16. JS 禁用时启停表单（隐藏域 _csrf 路径）仍可提交成功（渐进增强）。

**轮询与数据流**
17. 页面在后台标签页 ≥1 分钟 → 无请求发出（visibility 暂停）；切回前台 → 立即补拉一次。
18. 连续 3 次上游失败 → 轮询间隔退避至 15s；恢复后回到 5s。
19. 每次成功轮询后「数据截至」时间戳更新且 aria-live 容器生效。

**样式与无障碍**
20. 全部状态徽含图标 + 文本（色弱模式下仅凭图标/文字可区分健康/降级/故障）。
21. 860px 视口下两页单列自适应、无横向溢出（表格允许内部横向滚动）；导航抽屉可用。
22. prefers-reduced-motion 下骨架无闪烁动画。
23. 键盘 Tab 可达全部按钮，Enter 可触发启停；折叠明细 aria-expanded 状态正确。
24. 新增样式仅消费既有 CSS 变量；`npm run smoke` 19 项不回退（含明文检查——治理数据不落 website 库）。
