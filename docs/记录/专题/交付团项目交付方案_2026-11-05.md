## 1. 一句话项目定义与成功标准

**把 allin（138 仓治理体系）从「三套分散面」升级为「一键贯通、全绿可验证」的本机智能体应用**：website 为唯一整合 UI 面，platform 为治理状态唯一聚合出口，kernel 保持 CLI 定位，治理大脑维持文本注入双形态（不引入 LLM 运行时）。

成功标准（可复跑）：SC1–SC9 全绿，核心新增 = **`npm run smoke:e2e`**（CLI 前门 → kernel 探测 → portal 回环探活 → website 探活 → g21 漂移判据，≥6 检查点，证据落 JSONL，exit 0）。

## 2. 需求范围

**Must（本期必做 5 项）**：M1 smoke:e2e 端到端冒烟；M2 门禁覆盖缺口收口（README ⚠ 2026-11-01 三条承诺不回退）；M3 双形态同步判据双路拦截（g21 接 run_all_gates.sh，CI 零改动自动三路）；M4 website 密钥灾备演练落地一次（**运维动作，涉及真实密钥，待全哥现场确认后执行**）；M5 skill 路由台账门禁化（实测 15/15 齐整，被 g21 吸收，≤1 天）。

**Should**：website 开机自启+守护+日志轮转（Task Scheduler）；portal 库页对治理面只读透出；allin-governance 0.0.0a3 复验；gate-runs.jsonl 5MB 轮转。

**Out of Scope（用户拍板）**：公网部署、多用户鉴权、付费 LLM 运行时/API 编排、138 仓全量自动克隆、跨机分布式调度。

## 3. 系统架构与技术选型

### 3.1 架构增量（加边不加层，SPEC-204 全保留）

| 增量 | 落点 |
|---|---|
| G1 website 控制台看 platform 启停状态（只读 BFF 代理） | website→portal `GET /api/library` |
| G2 门禁留痕进 website 管理台 | gate-runs.jsonl → portal `/api/gate-history` → 代理 |
| G3 kernel `allin status` 跨面只读汇总（文件级，离线可降级） | 读 running.json / gate-runs.jsonl / g21-runs.jsonl |
| G4 编排健康可视化 | g21 产物 → portal `/api/orchestration` → website 看板 |
| 编排事实源 routes.yaml（机器可读 15 条路由） | `tools/orchestration/routes.yaml` |
| 门禁 g21（agent-parity 三方对账） | `tools/gate/agent_parity.py` |
| 部署守护面（自启/守护/备份，仓外执行） | Task Scheduler 4 任务 + tools/deploy/ 脚本 |

写路径唯一：website admin+CSRF → 服务端代理 → portal 既有 start/stop。浏览器零新增暴露面（只认 9042 单源）。

### 3.2 关键选型（被否决备选详见 P1b §2）

| 决策 | 采纳 | 主要否决理由 |
|---|---|---|
| 贯通方式 | 混合：platform 聚合出口 + website 整合 UI + 文件事实源 | 门户扩容反代（违按需形态/ kernel 非 HTTP）、纯文件监听（Windows 不可靠） |
| 身份边界 | website 服务端 BFF 代理 | 浏览器直连（破坏单源）、platform 加鉴权（单机重复建设） |
| 编排工程化 | 对账式（routes.yaml + g21 锚点对账） | 生成式渲染（丢手写语义）、verify-mount 扩职责（失败域混淆） |
| g21 产物 | **JSONL `tools/gate/audit/g21-runs.jsonl` 尾行快照**（v3 冻结） | 单快照 JSON（Windows 覆写损坏窗口 + 崩溃行假绿漏洞，成员实证推翻） |
| 自启守护 | Task Scheduler 登录触发+失败重启 | PM2（年久失修/后台异常实测）、启动文件夹（无守护）、NSSM（需管理员，留备选） |
| 备份 | 每日 robocopy /MIR → **E:\allin-backup**（与数据 D 盘异盘）7 天轮转 + manifest sha256 | D 盘备份（同盘单点）；密钥不走 robocopy（唯一通道 backup-key） |

## 4. 数据库设计摘要（零 DDL）

website **不加表不加列**：治理流水复用既有 `audit_log` 五列（action 命名空间 `governance.entry.start/stop`、`governance.view`——view 只在页面加载记一次，绝不挂 5s 轮询）；SCHEMA_VERSION 保持 1。明文最小化已论证（action/target 必须明文保索引）。治理状态**零镜像**：唯一事实源 = platform data/ 文件 + gate/g21 运行时产物。备份 WAL 三件套先 `wal_checkpoint(TRUNCATE)` 再镜像。

## 5. 前后端与智能体实现要点

- **portal**（零依赖 node.http）：新增 `src/bridge.js`——`GET /api/overview`（聚合+30s 内存缓存+generatedAt）、`GET /api/orchestration`（读 g21-runs.jsonl 尾行，缺失 readable:false）；Host 围栏/loopbackOnly 零改动。
- **website**（Express+EJS 零构建）：`routes/governance.js` + `services/portalProxy.js`（AbortController 3s 超时、错误三分类 UNREACHABLE/FORBIDDEN/TIMEOUT、内存快照缓存）；`/member/dashboard` + `/admin/governance` 两页，五态组件（正常/空/加载/错误/无权限），编排健康卡四态（含门禁自身故障 lastCheckError）；写操作三道闸（会话/admin/CSRF）+ 两段式确认。
- **kernel**：`status` 只读子命令（SERVICES 白名单+1，纯文件读，退出码 0 缺失降级/1 损坏/2 strict）。
- **智能体编排（文本注入双形态工程化）**：routes.yaml 15 条 ↔ SKILL.md 锚点 ↔ GOVERNANCE 段锚点三方对账；锚点 `<!-- route:<id> -->` 计数=1；g21 管「台账↔正文」、refresh-gov-block 管「正文↔副本」、verify-mount 管「正文↔安装」——失败域分离不越界。

## 7. 部署上线方案

Task Scheduler 4 任务：① ALLIN-website（登录常驻 :9042）② ALLIN-portal（登录常驻 PORT=0）③ ALLIN-daily-backup（每日 02:00，robocopy<8 判定+manifest+7 天轮转+checkpoint）④ ALLIN-weekly-e2e（每周 smoke:e2e）。日志按日轮转 14 天。回滚 = 删任务+删脚本；仓内变更走 git 回退。注册脚本落 `tools/deploy/`（UTF-8 BOM、零盘符、env 注入），**只写不注册，注册动作由全哥执行**。

## 8. 测试与验收清单

金字塔：单测（kernel/platform 既有）→ 集成（bridge×状态文件矩阵、代理×降级三态）→ E2E（smoke:e2e ≥6 检查点，临时实例复用优先、端口 9156）→ 验收（SC1–SC9 + 恢复演练 8 项）。前端 23 用例 + 后端 13 自测 + QA 统一验收总表（含灰度 3 天双跑观察期）。缺陷分级对齐 SPEC-106；放行 gate = 全门禁绿 + smoke:e2e 绿。非功能数值先实测基线再定阈值。

## 10. 决策与权衡（含被否决方案与改判记录）

1. routes.yaml 落点：preset/allin/（初裁）→ **tools/orchestration/**（终裁，preset 单一职责 + 消费方全在执行器侧）。
2. g21 产物：单快照 JSON（初裁）→ **JSONL 尾行快照**（终裁，成员实证推翻：覆写损坏窗口 + 假绿漏洞）；severity error|warn 采纳，`type` 统一 "g21-run"。
3. allin status 退出码：恒 0 提案否决 → **缺失 0 / 损坏 1 / strict 2**（fail-loud 文化）。
4. kernel 加 HTTP 面否决（CLI 定位 + 文件即事实源）；SSE/WebSocket 否决（单机轮询足够）。
5. 备份根 D:\ → **E:\**（devops 抓到同盘问题）。
6. M4 密钥灾备演练属运维动作，涉及真实密钥，**不在 AI 实施范围**，待全哥授权后按 SPEC-106 §6 执行。
