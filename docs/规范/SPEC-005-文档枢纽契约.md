## 1. 这份契约解决什么

大修前（2026-09-28 之前）的实测病症，逐条对应本契约的条款：

| 病症 | 实测 | 对应条款 |
| --- | --- | --- |
| **没有总目录** | 32 份文件平铺在 `docs/`，`README.md` 只覆盖约 25 份且按"主题"分类 | §3、`INDEX.md` |
| **规范与产物同层** | 约束性文档（`MEMORY.md`、`协作工作流程约定_2026-08-28.md`）与一次性报告挤在同一层；**文件名带日期**让"长期要求"读起来像"上次会话的产物" | §2、§4.1 |
| **单文件无界膨胀** | `MEMORY.md` 661 行混装铁律/调试铁律/机器事实/审计清单/项目契约；`会话交接` 162 KB、76 节、横跨 33 天 | §6、§7 |
| **规矩没有牙** | 没有任何门禁检查"文档是否被登记 / 规范是否还有效 / 编号是否连续" | §5、§9 |

**一句话**：文档被当成产物，是因为它**没有编号（无法被稳定引用）、没有效力声明（无法被要求）、没有承载体（没人兜底）、没有登记（找不到）**。本契约把这四件事都补上。

## 2. 四分类（唯一判据）

判断顺序：**先问"这份文档被违反会怎样"，再归类**。四类的判据互斥，不允许"既是规范又是记录"（混装即拆成两份，用链接互相指）。

| 类别 | 目录 | 判据（依次回答，先"是"者胜） | 判据问句 | 可变性 | 文件名 |
| --- | --- | --- | --- | --- | --- |
| **规范** | `规范/` | 有人在**将来**必须照它做；违反会产生可指认的错误 | 「这条规矩明天还管用吗？」 | 受控修订（改版本、留修订记录） | `SPEC-<号>-<中文短名>.md`，**禁止日期** |
| **事实源** | `事实源/` | 是**当前**状态的单一权威台账，被别的文档/代码引用取值 | 「别人会来查这个值吗？」 | 就地更新（带时点） | 中文名，**禁止日期** |
| **记录** | `记录/` | 是**某一次**发生的事的证据/流水/结论，只增不改 | 「这是哪一天发生的事？」 | **只增不改**（勘误用追加节） | `<主题>_<YYYY-MM-DD>.md` 或按月卷 `<YYYY-MM>.md` |
| **历史** | `md/` | 大修前存量文档树，冻结留证 | 「它还代表任何现行结论吗？」 | **冻结**（不改名、不改内容） | 保持原样 |

**边界裁决三例**（写下来防止以后反复争）：

1. **一份文档既讲规矩又讲当时怎么发现的** → 拆。规矩进 `规范/`，发现过程进 `记录/`，规范里用一行链接指过去（例：调试铁律 19 的"只 `git add <指定文件>`"进 SPEC-004，事故经过留在 `记录/审计/`）。
2. **带日期的"清单/计划"** → 一律 `记录/`。哪怕它写了"必须执行"，那也是**当时那次**的执行要求，不是长期规矩；长期化的部分要单独提炼进 `规范/`。
3. **机器事实** → 现行状态进 `事实源/机器分区索引.md`；某次导出的硬件清单进 `记录/快照/`。**同一事实只写一份**，快照不得被当作现行值引用。

## 3. 目录契约

### 3.1 目录树（唯一形态）

```
docs/
├─ README.md            门面：这是什么 · 30 秒上手 · 四分类导航
├─ INDEX.md             ★ 总目录：全量文档索引（唯一，门禁校验）
├─ 规范/                约束性文档（SPEC 编号）
│   └─ README.md        规范总纲：效力等级 / 引用格式 / 规则→门禁映射
├─ 事实源/              活台账
│   └─ README.md        本类准入判据 + 时效要求
├─ 记录/                证据流水（只增不改）
│   ├─ README.md        本类准入判据 + 子类清单
│   ├─ 交接/            逐轮会话交接，按月分卷
│   ├─ 审计/            审核 / 核对 / 盘点 / 修复计划
│   ├─ 计划/            待执行的方案与规划
│   ├─ 事故/            故障与排查
│   ├─ 专题/            一次性调研与执行报告
│   ├─ 决策/            冻结的 ADR（Problem/Decision/Alternatives/Consequences）
│   ├─ 外部/            外部工作区同步与备份
│   ├─ 记忆/            agent 长期记忆月账（按月分卷，只增不改）
│   └─ 快照/            某时点的机器/环境快照
└─ md/                  历史树（冻结，231 篇）
```

### 3.2 ASCII 别名并置（本机特有）

`docs/` 同时提供**中文目录名与 ASCII 目录名**，内容**只存一份**（真身在中文目录）：

| 真身（入库） | ASCII 别名（不入库） | 历史树别名 |
| --- | --- | --- |
| `规范/` | `spec/` | — |
| `事实源/` | `facts/` | — |
| `记录/` | `records/` | — |
| `md/`（本身即 ASCII） | — | `历史/` |

- 别名由 **junction** 实现，**不进 git**（`.gitignore` 显式忽略）；理由：同一份内容进两次库违反"单一事实源"。
- 别名丢失/换机后重建：`pwsh -File tools/gate/make_doc_aliases.ps1`；校验：`... -Check`。
- **规范引用一律写中文真身路径**（`docs/规范/SPEC-001-铁律.md`）；ASCII 别名是给跨工具/习惯 ASCII 的使用者的便利，不是引用基准。
- 门禁 D6 校验四个别名存在且指向正确，**并显式跳过别名目录**（防止把同一份内容数两遍）。

### 3.3 `docs/` 根只放三样

`README.md`、`INDEX.md`、`MEMORY.md`（路由页）+ 四个分类目录。**任何新文档不得再落在 `docs/` 根**（门禁 D5 拦）。

### 3.4 总目录必须自述份数（门禁 D8）

`INDEX.md` 头部**必须**有这一行，且逐项与实际相符：

```
> **时点** YYYY-MM-DD ｜ **覆盖** 根 N + 规范 N + 事实源 N + 记录 N = **M 份**（不含 `md/` 历史树 N 篇）
```

**为什么要机械化**：大修首日就出现过「头部写 51 ／ 实际 49」——三个分项数字全部与磁盘不符，而**没有任何判据能发现**（D1/D2 只校验"登记 ↔ 存在"的双向关系，不看自述的汇总数字）。只靠人眼，必然复发。

### 3.5 章节锚点、覆盖区间与两处计数必须可机检（门禁 D9–D14）

> **2026-11-01 新增**。三处盲区实测存在过、且都真实漏过网，因此补判据而不是补提醒。

| 判据 | 管什么 | 真实漏网的形态 |
| --- | --- | --- |
| **D9** 章节锚点 | 指向性 `§N` 引用必须落在**真实章节**上 | `g19-docs-refs` 只解析**文件路径**、不查**章节锚点** ⇒ 改章节序就留静默失效指针（2026-10-30 重写机器分区章节序时一次留下 **6 处**，隔一天才靠专项审计抓到） |
| **D10** 区间随文 | 交接卷卷首声明的覆盖区间，必须**覆盖正文最新日期** | D7 只校验卷首**有没有**声明区间 ⇒ 10 月卷长期写「~ 2026-10-16」而正文已写到 10-31，**无任何判据能发现** |
| **D11** 两处计数 | INDEX 头部覆盖行与各节标题里的「N 份」必须一致 | 同一文档**两处**计数各漂各的（实测出现过 头部 54 / §四 标题 53）；D8 只看头部 ⇒ 漏 |
| **D12** 登记自述 | INDEX 交接表「覆盖区间」列的自述，必须与**该卷自身**相符 | 登记的节区间过窄（实测曾写「§一百零七」而该卷已到 §一百一十一）、登记日期与卷首声明不同步 |

**D12 为什么必须按卷判**：交接卷的顶级节用中文序数，而**节号在不同卷间会重复**
（`§一` 在 2026-08 卷是「总体状态」、在 2026-10 卷是「用户拍板」）⇒ `§N` 必须带卷才无歧义，
全局判必然误报。D12 的三条：(a) 列内每个 `§X` 都存在于该卷；(b) 声明的**末节 ≥ 该卷实际末节**
（真实漏网形态）；(c) 声明的**日期区间 == 该卷卷首声明**。
⇒ 与 D10 串成一条闭合链：**正文日期 ≤ 卷首区间 == INDEX 登记**。
（`§A 起` 形式为开区间，只判 (a)(c)；**不判「起节 ≤ 实际首节」**——有的卷在 `## 九十四` 之后
又用 `## 一、`~`## 五、` 作子节，首节取最小值不可靠。）

**D9 的判定范围（刻意保守，宁可漏也不错报）**

- **源**限于 `规范/` + `事实源/` + 枢纽根件；**不含 `记录/`** —— 记录是「只增不改、不作为约束」的历史证据，
  它引用的旧锚点**当时是对的**（改历史才是错的，只能不判）。
- **目标**只认**四种无歧义的指向形态**：
  1. **紧邻型**：`[...](path.md) §N` / `` `path.md` §N ``；
  2. **规范编号型**：`SPEC-005 §N`（规范编号本身即可定位文件）；
  3. **中文别名型**：`索引 §N`（别名→文件是有意的**硬编码**，本仓只认「索引」→`事实源/机器分区索引.md`；
     加新别名前须确认全仓无歧义）；
  4. **自引用型**：`本文件 §N` / `本文 §N` / `本卷 §N`。
  裸文件名与"行内讨论某文档"**不算目标**（`MEMORY.md` 661 行混装… 这类句子里的文件名是**被讨论对象**，
  实测按它归因会产生一批假红 —— 一次假红就足以让人把门禁关掉）。
- 目标文件无编号标题（`## 铁律 5：…` 这类文字标题）⇒ 无法判定，跳过并计数。
- **编号列表项算不算节号**：只在「该文档**全文没有编号标题**」时才算 —— 实测 SPEC-004 的 69 条
  「调试铁律」就是 `## 调试铁律` + `1.`~`69.` 列表项，`SPEC-004 §48` 指的正是列表项 48；
  而机器分区索引有编号标题，它 §0 下的「1. …」只是子项、**不算** §1
  （否则会冒充，把「改了节号」的断链糊过去）。

**已知边界（刻意不覆盖）**：**裸 `§N`**（目标需靠上下文推断，如「见 §5 冲突裁决」「原登记（交接档 §107.4）」）
**不判** —— 实测按「段落唯一目标继承」「表格行按列归属」两种启发式试算，247 处里会误判 **82 处**
（表格行里「覆盖区间列归本行链接」与「主线列归别的文档」无法机械区分）⇒ 风险大于收益。
这类引用改为**写全目标**（`交接档 2026-10.md §107.4`）即可纳入 D9 校验。

**判据只有一份**（同 `SPEC-004` 调试铁律 64 的教训）：D9–D13 的实现只在
`tools/gate/governance/runtime/docs_contract.py` 一处，仓内 `docs_index.py` 与分发版 `g15-docs-contract`
**import 同一份** ⇒ 结构上杜绝两份判据漂移，而不是靠"记得同步"。

### 3.6 INDEX 登记表的**列语义契约**（门禁 D13）

> **2026-11-01 新增**。D9 只能判「目标紧邻可定位」的引用，登记表行里那些**写在摘要列**的 `§N`
> （如 REC-HO-03 行的「`§107.5–§107.10 … §110 … §111`」）判不到 —— 而那正是历史上真出过错的形态。
> 解法不是再加启发式，而是**先把列语义写成契约**，让判据按契约读。

**契约条款**

1. **登记行的「文件/卷」列指向唯一一份文档**；该行其余列里**不带文档限定词**的 `§N`，
   指的就是**这份文档**的节。（例：`| REC-HO-03 | [2026-10.md](记录/交接/2026-10.md) | … | … §110 … |`
   ⇒ `§110` 指 `2026-10.md`。）
2. **带限定词的 `§N` 指别的文档**，不属于本行链接：
   - **文档限定词**（「交接 §107.10」「索引 §1」）⇒ 归那份文档；
   - **INDEX 行号**（`FACT-01 §5.1`、`REC-AU-20 §七`）⇒ 归**该行号所登记的文档**（行号是稳定主键）。
3. **链接标签内的 `§`**（如 `[§107.4 六条清理计划](…)`）指别处，**不归**本行。
4. 行内有**多个不同链接** ⇒ 目标不唯一 ⇒ 整行不判。

**配套的节号比较规则**：节号比较**数值化**（中文序数与阿拉伯等价）——
顶级节写 `## 一百一十、` 而引用方写 `§110`，是**同一节**，不得判成失效；
节号可能是多层小数（`§2.1.1`）⇒ 用规范化字符串键，**不用 float**（`float("2.1.1")` 会抛）。

**写登记表行时怎么用**：要引用**别的**文档的节，就把限定词写上（`交接 §107.10`、`FACT-10 §5`）；
只写 `§N` 会被理解成**本行链接的那份文档**的节。

### 3.7 **`§` 引用的书写规范**（门禁 D14）

> **2026-11-01 新增**。前几轮把「裸 `§N` 的上下文继承」这条判据否决了（覆盖 129 处、误判 82 处）。
> 本轮换的是**文档侧**的办法：**把书写规范写死**，让剩下的裸 `§N` 变成**可判的**。

**规范两条**

1. **同一份文档内，裸 `§N` 默认指本文件**的节 N（自引用）。
   ⇒ 门禁 D14 按此判定：裸 `§N` 必须在**本文件**里存在对应章节。
2. **指别的文档时必须写全目标**：`X.md §N` / `SPEC-XXX §N` / `索引 §N` / `交接 §N` / `本卷 §N` /
   `该文件 §N` / `同文件 §N`（后两个指**前面刚提到的那个文件**）。
   ⇒ 表格行另按 §3.6 的**列语义契约**。

**豁免（刻意保守，宁可漏也不错报）**

- **行内代码 / 代码块里的 `§`** ⇒ 那是**示例**，不是引用（如「引用方写 `§110`」）；
- **表格行** ⇒ INDEX 由 D13 的列语义契约判；其它文档的表格**无列语义契约** ⇒ 跳过；
- **「原 §N」** ⇒ 历史对照语义（指**旧结构**，如迁移对照表的「原章节」列），不指现行章节；
- 头部契约的**「引用格式」字段**（那是格式声明，不是活指针）。

**为什么值得做**：这条规范把 **69 处**本来就指本文件的引用从「判不了」变成**可校验**，
同时逼着把 **21 处**指别处的裸引用改写成**无歧义**形式——其中改写过程**抓出了 3 处真断链**
（`FACT-01` 的 `§5.1`、SPEC-004 引的「文档 `§3.8`」、SPEC-201 引的《会话交接_2026-08-27.md》已改名）。
⇒ **规范的价值不在门禁，在于它逼着人把话说清楚。**

**写起来的三条实操经验**

- 跨文件引用的路径**要相对 `docs/`**（如 `事实源/机器/DESKTOP-KQABATS.md`）——
  相对**当前文档目录**的路径在别处解析不到；
- **跨行引用**（路径在上一行、`§` 在下一行）**判不了** ⇒ 路径与 `§` 必须同行；
- 举例子时把 `§N` **放进反引号** ⇒ 判据自动当作示例豁免。

### 3.8 **字节级完整性：禁止非法控制字符**（门禁 D15）

> **2026-11-06 新增**。上一轮记档「控制字符损坏不被任何门禁覆盖」：历史卷
> `记录/交接/2026-08.md`（6 处）与 `记录/交接/2026-09.md`（1 处）含 U+0007 / U+0008 / U+000C，
> 而本契约 D1–D14、`g19-docs-refs`、`g01-paths` 全都不判这一层
> （`g01` 只判「写死了什么盘符」，不判盘符 / 短 SHA 是否被转义吃掉）。

**规范两条**

1. `docs/` 下任何文件**不得含 `ord(c) < 32` 的控制字符**，例外只有 LF / CR / TAB 三个排版字符。
   ⇒ 短 SHA、盘符路径的首字符被反斜杠转义吃掉（响铃符 / 退格符 / 换页符）即属此类。
2. **行内代码跨度（反引号内）不得含 TAB** —— 路径 / 短 SHA / 命令里的 TAB 只可能是转义损坏；
   普通正文与 diff 快照里的 TAB 合法，故判据只覆盖代码跨度（全仓量化：仅 3 行含 TAB，
   其中落在代码跨度的 1 行正是损坏处 ⇒ 修好后真实树 0 假红）。

**范围**：**全部 `docs/` 文件，含 `记录/` 历史卷** —— 与 SPEC-005 §3.5 的 D9、SPEC-005 §3.7 的
D14 刻意排除 `记录/` 不同：字节损坏不分活文档与历史证据，本判据要守的正是历史卷。

**判据唯一实现**：`tools/gate/governance/runtime/docs_contract.py` 的 `check_d15()`，
仓内 `docs_index.py` 与分发版 `g15-docs-contract` 两个入口 import 同一份（同 SPEC-005 §3.5）。
**门禁数不变（仍 20 道）** —— 是既有文档契约的延伸，不新增 gate。

**配套纪律**：写含反斜杠的文档时不用 bash heredoc 传内容（会被多层解释）；
用 `chr(92)` 构造或写脚本文件；写完**必须回读整行 `repr` 并扫控制字符** ——
脚本会照常报成功，而这类损坏对肉眼与既有门禁都隐形。存量 7 处的逐条还原证据与
两处短 SHA 的确定性逆推，详见 `记录/交接/2026-11.md` 的 `§一百三十四`。

### 3.9 **计划闭环：状态机闭集与证据强制**（门禁 D16）

> **2026-11-07 新增**。ERP 的灵魂是「计划下达 → 执行反馈 → 偏差修正」闭环（MRP II 底层逻辑）；
> 本仓的组合分级执行顺序此前状态写在叙述句尾、无证据指针，完成与否靠自觉回写。

**规范两条**（判定对象：[`事实源/组合分级决策索引.md`](../事实源/组合分级决策索引.md) 的
「执行顺序」**状态机表**，叙述行不判）

1. **状态列取值出闭集即报红** —— 闭集五态：`⏳ 待执行` / `🔄 进行中` / `✅ 完成` /
   `⏸ 搁置` / `⚠ 偏差挂起`。自创状态（如 `❓`、`✅✅`）一律拦下。
2. **`✅` / `⚠` / `⏸` 行的证据列必须含指向 `docs/记录/` 的指针**（markdown 链接目标或
   反引号路径含 `记录/`）—— 宣布完成、登记偏差、执行搁置都要在记录区留得住账；
   `⏳` / `🔄` 行暂无证据要求。

**判据唯一实现**：`governance/runtime/docs_contract.py` 的 `check_d16()`，双入口 import 同一份。
**门禁数不变（仍 20 道）**。

### 3.10 **事实源留痕：最新时点块必须指向记录区**（门禁 D17）

> **2026-11-07 新增**。实测漏洞：`SIWPAN` 分区文件夹化当日（`b964f18`）发起方未在记录区留痕，
> 只在拉入方的交接卷里有间接记载 —— 「变更发生了，账本里却找不到发起方的账」。

**规范一条**：`docs/事实源/**/*.md`（各 `README.md` 除外）**日期最新的时点块**必须含至少一个
指向 `docs/记录/` 的指针（markdown 链接目标或反引号路径含 `记录/`）。
无时点块的文件豁免（如 `端口分配表.md`）；历史块不判（与 D9 / D14 排除记录区的同一精神：
不逼人改写历史，只管**从今往后的变更**留痕）。

**判据唯一实现**：`governance/runtime/docs_contract.py` 的 `check_d17()`（最新时点块作用域
算法与 `g20_facts.header_scope` 同一逻辑，独立实现以维持门禁自包含），双入口 import 同一份。
**门禁数不变（仍 20 道）**。跨机缺口按铁律 6 处理：提出方登记统辖索引待修项 +
双入口基线棘轮挂账，待该机自补后自然消解。

## 4. 命名规则

| 类别 | 规则 | 反例（门禁报红） |
| --- | --- | --- |
| 规范 | `SPEC-<号>-<中文短名>.md`；短名不含日期、不含空格 | `协作工作流程约定_2026-08-28.md`（带日期） |
| 事实源 | 中文名或沿用既有公认名（如 `ports.yaml`）；不含日期 | `新机配置汇总_2026-09-24.md`（带日期 → 应归记录） |
| 记录 | `<主题>_<YYYY-MM-DD>.md`；按月卷为 `<YYYY-MM>.md` | `gitee项目记录.md`（无日期 → 门禁报红） |
| 历史 | 保持原样 | 改历史树文件名 |

**为什么规范不许带日期**：日期在文件名里等于宣称"这是某天的产物"。规范的时效写在头部字段（生效日期 / 最后修订 / 状态），不写在文件名。

## 5. 头部契约

每份**规范**开头必须有下面这个块（字段齐全，门禁 D3 逐项校验）：

```markdown
> **编号** SPEC-004 ｜ **效力** 纪律（可被门禁引用）｜ **状态** 生效
> **生效** 2026-08-24 ｜ **最后修订** 2026-09-27 ｜ **适用面** 全工作区
> **承载体** g11-undef-names、g09-python-hygiene（不满足会红）
> **引用格式** SPEC-004 §调试铁律 19
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| 编号 | `SPEC-NNN` | 与文件名一致；唯一、连续 |
| 效力 | `铁律` / `准则` / `纪律` / `操作规范` / `指南` | 见 `规范/README.md` §1 效力等级 |
| 状态 | `生效` / `草案` / `冻结` / `已废弃` | **废弃不删除**，改状态并在正文首行写明替代者 |
| 生效 / 最后修订 | `YYYY-MM-DD` | 最后修订须 ≥ 生效 |
| 适用面 | 一句话界定边界 | 防止被无限外推 |
| 承载体 | 门禁 id 或 `无（流程纪律）` | **没有承载体的规范必须显式写"无"并给理由**——不允许留空 |
| 引用格式 | 一行示例 | 让别人知道该怎么引用它 |

每份**事实源**开头必须有：`> **时点** YYYY-MM-DD ｜ **观测工具/命令** … ｜ **失效条件** …`（承 `g07-doc-freshness`）。
每份**记录**开头必须有一行：`> **本文是 <时点> 的一次性记录，不作为约束。**`

## 7. 新增文档 SOP（4 步，缺一步门禁报红）

1. **定类别**：按 §2 判据表选规范 / 事实源 / 记录；选不出 = 这份文档该拆。
2. **领编号或锚点**：规范领 `SPEC-<区间内最小空号>`；记录确定日期或月份卷。
3. **写头部**：按 §5 补齐该类必需字段（规范七项、事实源三项、记录一行）。
4. **登记 `INDEX.md`**：加一行（类别 / 编号 / 标题 / 路径 / 状态 / 时点 / 一句话）并跑 `docs_index.py`。

> 门禁 D1 会拦"文件存在但没登记"，D2 会拦"登记了但文件不存在"——**索引不可能悄悄过期**。

## 8. 引用与链接规则

- 规范之间引用写 `SPEC-NNN §<小节号>`；跨类引用写仓根相对路径（`docs/记录/审计/深度审核报告_2026-08-27.md`）。
- **不写盘符**（铁律 5）：仓内用仓根相对路径，跨仓用约定变量。
- 引用一份**记录**时必须带日期（它的路径里就有），使人一眼看出这是某时点的结论而非现行要求。
- 规范被废弃后，**引用不得删除**：改指向替代规范，并在替代规范里注明沿革。
