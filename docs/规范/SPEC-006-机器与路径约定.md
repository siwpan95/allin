## 1. 盘位是在位性动态事实，不是常量

- **观测三要素**：任何盘位结论必须同时给出「**时点 + 观测工具 + 观测结果**」。缺任一项即不得作为依据。
- **工具不等价**：`Get-Volume`（卷视图）、`Get-Disk`（物理盘/总线视图）、路径探测 + 真实读写（可用性视图）**三者可能给出不同答案**；涉及写入的动作前，用**真实文件读写**验证目标卷可用。
- **冲突裁决**：同一事实出现两份互相矛盾的声明时，按 `SPEC-004 §调试铁律 57 / 58` 处理 —— 权威归**随日期演进的事实流水**，带日期的快照降级为记录；**但流水条目自身也会过期**，所以它是"更权威"，不是"永远正确"。
- **快照必须带失效条款**：任何自称"事实源/快照"的文档，头部必须写明时点与失效条件（`g07-doc-freshness` 强制）。
- **"不存在 / 已下线 / 已被取代"这类否定判断，必须由该物的权威源给出**（2026-10-26 补）：
  机器类事实 → [`../事实源/本机事实.md`](../事实源/本机事实.md)（**先读它再谈盘位**）；
  项目状态 → `platform/registry` + 远端实测；**自动化状态 → 该自动化自己的记录目录**。
  **没查就写"不存在"，是本仓最容易犯且最难自查的错误**：否定判断没有现场证据支撑时，
  正确表述是"**尚未查证**"，不是"**不存在**"。
- **自动化的生死以它的记录为准，不以目录印象为准**（2026-10-26 补）：
  改动任何 automation 的启用 / 暂停 / 参数 / 工作目录之前，先读它的记录（工作区里的
  `archive_report.txt`、`run.log`、`run_*.sh`，以及 `.workbuddy/memory/automations/<id>/`），
  再做远端实测；**不得凭"目标目录看起来不在"就判定它已死**。
  ⚠ 反面教材（2026-10-26 实录）：曾因未读 `本机事实.md`（该文件 §1/§2.2 早已写明 D 盘是活跃数据盘）
  与自动化记录，把一个**当天 09:41 刚成功跑完**的周更自动化误判为"已死"并**暂停**——
  实为 D: 盘仍在、归档目录完好、自动化完全正常。**误暂停一个在跑的自动化，比不动它更糟。**

## 2. 路径一律不写死盘符（铁律 5 的可执行化）

| 场景 | 写法 | 例子 |
| --- | --- | --- |
| 仓内文件 | **仓根相对路径** | `preset/allin/allin.patch.yml`、`docs/SPEC` 体系的 `docs/规范/SPEC-001-铁律.md` |
| 跨仓 / 外部依赖 | **约定变量或环境变量** | `$DSH_HOME`、`$PROJECTS_ROOT` |
| 文档里必须举绝对路径时 | **去符盘形式**（表示"仓根/约定父目录"，不是本机真实路径） | `D:/allin` → `/allin`；`G:\repos\x` → `/repos/x` |

- **反例（门禁拦）**：脚本 / 配置里硬编码 `D:\...`；把"本机当前盘符"当事实写进提交；文档里留本机专属绝对路径。
- **例外（合法）**：Windows 专用脚本里的盘符（门禁按平台归属只报告不阻断）；行内审计注记写明"已失效/占位/源自上游"的路径。

## 3. 仓库落点契约

- **一仓一目录**：本地目录名 = 远端仓名（`repo_hygiene.py` H7 判）。核远端一律用 `git config --get remote.origin.url` **解析出的仓名**，不靠目录名猜（本地目录名可与远端仓名不同）。
- **项目盘**：所有项目检出集中在**项目盘的一个目录**下（现行值见 `事实源/本机事实.md`）。
- **索引仓**（本仓 `allin`）承载治理说明、文档枢纽与 preset 载体，**不承载项目源码**。
- **源码按需懒拉取**：不预先克隆全量远端仓；`PORTFOLIO.md`（仓根）是远端全量索引，由脚本生成。
- **`local/` 是纯本地区，`repos/` 才是发布区**（2026-09-28 用户明确）：
  - `/local/` 下的仓是**本地专用**（实验、暂存、未定形态），**默认不对外发布**，不必也不应逐个建远端仓。
  - **任何要公开的东西，必须先迁到 `/repos/<仓名>`**，在那里建远端仓并按 `SPEC-001 §铁律 0/4` 配齐三件套。
  - **两区语义不同**：`/repos/` = "已定形态、可发布、一仓一目录、仓名=目录名"；`/local/` = "还没定，别拿它当发布源"。
    不要把"在 `local` 里能跑"当成"可以发布"，也不要把 `local` 里没有远端当缺陷去补。

## 4. 编码边界（中文 Windows）

| 面 | 约定 | 不遵守会怎样 |
| --- | --- | --- |
| `.md` / `.txt` | **UTF-8 无 BOM** | 往返改写烤坏中文（`SPEC-004 §调试铁律 59`） |
| `.ps1` | **UTF-8 带 BOM** | PowerShell 5.1 按 ANSI 解码，报一堆假语法错误 |
| **编辑 `.ps1` 之后** | **复核首三字节** `239,187,191`（`[IO.File]::ReadAllBytes($f)[0..2]`）；要补 BOM 走**字节级**前插 | 编辑工具会**静默剥掉 BOM**（`pwsh` 下看不出，PS 5.1 必炸）——见 `SPEC-004 §调试铁律 66`；机器兜底 `tools/gate/check_ps1_bom.py`（随仓分发） |
| `.cmd` | 不允许存 UTF-8 | cmd 按 ANSI 解码，中文注释让整条命令解析错乱 |
| Python 文本 I/O | 一律显式 `encoding="utf-8"` | 默认 GBK，读崩或**静默写出 GBK 文件** |
| Python 入口脚本 | `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` | 带 `✓`/emoji 的输出在默认控制台 `UnicodeEncodeError` |
| 路径字面量（Python） | **raw 字符串** `r"..."` | `\a` `\t` `\n` `\b` `\v` `\f` 被解释成控制字符（docstring 同样危险） |

## 5. 文件系统能力边界

- **exFAT 卷不支持硬链接与目录联接** ⇒ 文件写入工具在该卷上报 `EISDIR`；目录联接类方案不可用。
- **工作区与 git 仓必须放在 NTFS 卷上**（当前盘位分配见 `事实源/本机事实.md`）。
- 判"某盘能不能开机检查（autochk）"**先看 `BusType`**：`Bus=USB` 的外置盘不要指望 autochk（`SPEC-004 §调试铁律 55 / 56`）。
- 外置盘上的 git 仓，在盘出现 IO 重试期间**不要做大批量写入**；仓的权威副本必须在远端。

## 6. git 行为边界

- 本机若报 `dubious ownership`，用 `git config --global --add safe.directory <路径>`（跨盘/换机会出现）。
- **按中文路径过滤 git 输出必须带 `-c core.quotepath=false`**，否则非 ASCII 文件名被转义、过滤恒假。
- 同步状态**只信 `git ls-remote`**；`origin/BR` 是缓存，会因 URL 直推而过期（`SPEC-101`）。
