## 一、单一公开停止原语

停止工作只有一个公开入口（cancel），不要堆多个 ad-hoc 动词（abort/stop/kill 各自半吊子）。它清空队列、中止活动 turn、保留"运行前就取消"的标记使得未领取的 prompt 永不运行、而后续 prompt 仍独立。一个有效调用在清空/中止前发出带类型的 cause（`user | parent`）；空闲取消不发出任何事件、也不会让下一个 prompt 悬空。

> 对治理段：治理段 agent 的长任务、注入、重启，统一走一个停止原语；不要为不同来源各写一套取消逻辑。

## 二、disposer 是"消费者能力"

拆除（dispose）不是谁都能做的：只持裸对象的观察者（registry observer）**无法**拆除它。调用方 fiber 与注册 provider 是**结构共主**——调用方卸载强制结构化所有权，provider 卸载必须停掉那些作用域经它解析的旧实例。三者最终都汇聚到**同一个记忆化拆解**：停循环 → 等其退出与空闲 flush（真静默，不是仅翻转 `disposed` 状态）→ 脱钩 agent → 脱钩 session → 回卷作用域。

## 三、拆解顺序有负载意义

拆解顺序不是随意的。把 session 生命周期折进 agent 的**单一复合 effect**，使内部拆解按 LIFO 有序链执行：循环先停 + `await agent.done` **先于** session 脱钩，于是循环的最终 flush 在"handle.dispose()"和"fiber 卸载"两条路径都被捕获。若拆成兄弟 effect，fiber 卸载会并发拆解（Promise.all），竞态地抢在循环关闭 flush 之前移除发布钩子，丢掉 closing `turn/end`。**顺序即正确性。**

## 四、所有权令牌抗模块热重载

后台任务的所有权不要活在插件局部 `Map<string, Agent>` 里——一次 HMR 重载会让旧任务看起来"无主"。所有权令牌应活在**执行器**上（随执行器 fiber 一起销毁），于是重载后旧任务既不可被别的 session 读、也不可被杀。读路径只有一条（不冗余 API）。访问策略（令牌比对）留在 Consumer；能力本身把令牌当**不透明值**，永不解释——这正是 Service Definition / Service Provider / Consumer 的正确分边界。

> 对治理段：任何"长生命周期、跨重载存活"的状态（后台任务、会话句柄），所有权必须挂在执行器/会话层，而不是某个会被热重载的插件局部变量。

## 五、turn 围栏不变量（单一持久化边界）

turn 是**唯一的**崩溃恢复 / 持久化 / 回放边界。每个 session 事件都活在 turn 内（`turn/start` 与 `turn/end` 之间）：

- 排队的 `user/message` 在 `turn/start` **之后**追加（在 turn 内），不在之前；
- 运行中的 `inject()` 并入已开的 turn；空闲时的 `inject()` 用一次性 turn 包裹（`turn/start{trigger:injection}` → `context/message` → `turn/end`）；
- turn 编号每轮从日志派生（`lastTurnNumber + 1`），空闲注入的一次性 turn 不会与下一真实 turn 撞号。

**producer 侧强制、dev 报错，而非 reader 容忍**：在没有任何 turn 打开时追加 `user/context/steering/message` 即抛 `InvariantError`。拒绝"放宽 reader 而非约束 producer"——单一可查的 producer 规则，胜过要推理半截 turn 和松散间隙事件的边界扫描。于是未来换后端（SQLite/WAL）白捡干净边界；插件在 turn 外记事件会在 dev 响亮失败，而不是下次 resume 静默丢数据。

## 六、结构化失败跨边界

跨接缝的失败必须带**可路由的 code**，不是被压平的字符串。`toError` 把非 Error 抛出也包成带 `code:'UNKNOWN'` 的结构化错误（原值链到 `cause`），保证即便坏抛出也带可路由 code 进 session 错误事件。模型仍只看文本块；结构化字段供代码分支与回放。**不要**把结构化错误灌进模型历史。

## 七、对治理段的对位

| 生命周期原则 | 治理段落点 |
| --- | --- |
| 单一停止原语 | 治理段 agent 的取消/重启统一入口 |
| disposer 是消费者能力 | 长任务句柄的所有权挂在会话/执行器层，不挂可热重载的插件局部 |
| 拆解顺序有负载 | 会话与 agent 拆解的 LIFO 顺序在粘合剂 effect 内有序 |
| turn 围栏 | 治理段日志/审计轨迹以"单一边界"为回放单位，producer 侧强制 |
| 结构化失败 | 治理段向门禁/日志报告的失败带 `code`，模型只见文本 |

**判定口诀**：能跨重载/重启存活的状态挂执行器层；停止只用一个原语；拆解顺序当作正确性来设计；日志以单一边界为回放单位并在 producer 侧强制；失败带 code 不灌模型。
