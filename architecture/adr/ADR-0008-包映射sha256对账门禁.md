# ADR-0008 —— 「一份源码两处消费」以 sha256 对账门禁固化；dist/ 出库

- 状态：**accepted**（2026-11-04 落地：`tools/check_pkg_parity.py` + CI init 端到端 job 对账步骤；
  `.gitignore` 排除 `packages/*/dist/`）
- 相关：REC-AU-21（repocheck 并入 allin-governance 的决策）、`packages/allin-governance/pyproject.toml`

## Problem

`pyproject.toml` 用跨目录 `package-dir` 映射（`../../tools/repocheck`、`../../tools/gate/governance`）
实现"一份源码两处消费、不复制"。但"映射后与仓内真身一致"只有**一次性实测记录**
（README「SHA-256 逐字节相同」），没有固化成门禁——对照仓内自己的教训
（「派生副本手抄必漂」「门禁写了不跑 = 没有门禁」），这是同一类债：

- wheel 是**构建时点快照**：发布后仓内源码继续演进，旧 wheel/已发布版本与仓内必然分叉；
- 映射本身依赖仓 checkout 的相对布局，目录搬一层即断，断了却无人知道；
- `dist/` 构建物曾落在包目录内，有被误收进版本库的风险。

## Decision

- 新增 `tools/check_pkg_parity.py`：对**已安装的** `allin_governance._repocheck` /
  `._gatesuite` 与仓内 `tools/repocheck` / `tools/gate/governance` 逐文件 sha256 对账，
  不等即 exit 1（含"包根本没装"的显式报错）；
- 接入 CI：gates.yml 的 init 端到端 job 在 `pip install packages/allin-governance` 之后
  立即跑对账（装的就是刚构建的 wheel，正是"发布物 ↔ 仓内真身"的对应关系）；
- `.gitignore` 排除 `packages/*/dist/`：构建物只随 release tag 产出，不入版本库。

## Consequences

- CI 多约 10–20 秒（venv 安装 + 逐文件哈希）；换来"外部消费者拿到的包与仓内源码
  可审计对应"，把口头纪律变成退出码；
- 该对账只证明**本次构建**的 wheel 与仓内一致；已发布到 PyPI 的历史版本由
  `allin-governance verify`（快照复核）在消费端兜底，两者互补。
