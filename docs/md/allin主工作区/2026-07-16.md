## duitang 项目评估（D:/allin/tools/image-scraper/duitang）
- 本质：今天(20260716)由 DeepSeek 生成的 Chrome MV3 扩展「堆糖图片搜索器」初稿，6 个 `deepseek_*` 文件 + icons/。
- 致命问题：文件名与 manifest/HTML 期望完全对不上（manifest 要 `popup.html`/`popup.css`/`popup.js`/`manifest.json`，目录里全是 `deepseek_*` 名），直接拖进 chrome://extensions 无法加载。
- manifest 缺 `background.service_worker` 字段，service worker 代码未注册且 popup.js 直接 fetch、从不调 sendMessage → 后台代理是死代码。
- 运行时风险：堆糖 API `napi/blog/list/by_search/` 与 Python 端 `sources/json/duitang.json` 端点/字段完全一致；但 popup 用 fetch 设 User-Agent/Referer（浏览器禁止头，被丢弃）+ 跨域 CORS，搜索很可能失败。Python 端是服务端请求所以正常。正确做法是用已写好的 background 代理。
- 图标 3 个「png」其实是同一张 87×87 的 JPEG（JFIF），扩展名/尺寸都不对。
- 与现有项目关系（经全哥纠正）：Python image-scraper = 外置/桌面版本，duitang/ = 浏览器扩展版本，二者是不同交付形态（桌面 GUI vs 扩展），并非重复实现；都打同一个堆糖 API 属正常，不是冗余。我之前说"并行重复实现/功能重叠"是误判，已收回。

## duitang 批量下载：防盗链/可达性实测 + batchDownload 改直链
- 用 Python(managed 3.13.12) + urllib 模拟真实请求：
  - 搜索 API `napi/blog/list/by_search/` 返回 200，拿到 5 张真实图片 URL（c-ssl.duitang.com）→ API 存活。
  - 图片 CDN 对照测试：不带 Referer=200/image/jpeg/1,336,814 字节；带 Referer 同样 200/同字节 → **duitang CDN 不防盗链**，带不带 Referer 都行。
- 据此把 `batchDownload` 由「fetch→blob→createObjectURL→download(blobUrl)」改为**直接 `chrome.downloads.download({url: item.url})`**：避免 Service Worker 休眠导致 blob URL 失效而下载失败，popup 关闭也能继续，更稳。host_permissions 仍保留 `*.duitang.com`。`fetchImageBlob` 仅剩 `proxyImage` 预览兜底在用。
- 校验：background.js 通过 node --check，batchDownload 不再含 blobUrl/revokeObjectURL。
- 修复清单：重命名 → 加 background 字段 → popup 改走后台代理 → 删 deepseek_xml 占位 → 换真 16/48/128 PNG → 决策独立扩展还是并入 Python。
