## 二、两个值得记的坑

### 2.1 git quotepath（中文 Windows）

`git ls-files` 默认把中文路径转义成 `"zhidao/\346\214\207\345\257\274.txt"`，与磁盘路径对不上，导致 bloodmusic 的「指导.txt」被工具误判为未跟踪、跳过清洗。
⇒ 必须 `git -c core.quotepath=false -C <repo> ls-files`。全哥记忆里已吃过这个亏，本轮又踩一次。

### 2.2 路径替换的形态优先级

`cd D:/allin && cmd` 与 `cd D:/allin/sub/path` 两条正则若顺序错，前者会吃掉后者的子路径，产出 `\stay\pq_multiverse\src` 这种既非绝对也非相对的残串。
⇒ 「必须跟 `&&` 或行尾」的收紧判据优先；仓库名作锚点时要把 `-` 与 `_` 归一化（`pq-multiverse` vs `pq_multiverse`）。

### 8.1 由 #4~#7 引出的系统排查

这四例都是「`.gitignore` 规则过宽误伤源码」，于是做了两次全仓扫描：

- **全仓扫 PEP 701**（tokenize 判「同一 f-string 内，表达式的字符串引号 == 其分隔引号」）：
  139 仓命中 **2 处**（`zhuangtaiji`、`tavern-rogue`），已全修。
  ⚠ 注意：`ast.parse(feature_version=(3,11))` **检测不出**这类问题（实测各版本都 PASS），
  必须用 tokenize 逐 token 判引号嵌套。
- **全仓扫 `__init__.py` 是否入库**：命中 5 仓，逐一核实后**全部是 `archived/`、`dist/`、
  `tmp/`、`_ref/` 等产物/副本目录**（合理忽略），`wave4` 是唯一真缺陷，已修。

### 8.2 tkinter 与 CI 环境的真实差异

9 个仓的自检因本地 Python 缺 `tkinter` 而失败。铺 CI 后实测发现：

- **`actions/setup-python` 提供的是精简构建，不含 tkinter**（3 仓跑绿说明其自检不需要它）；
- 需要 tkinter 的仓（`math`、`daily_player`）改用 **ubuntu-latest 预装的系统 `python3` +
  `apt install python3-tk`**，再 `python3 -m venv` 装依赖 —— 这是唯一能同时满足
  「tkinter 可用」与「依赖装得干净」的组合。
