## 一、env 命名规范（用户要求统一）

### 1.1 三条原则

1. **优先复用各仓已有 env 名**（不新造同义变量）——工作区已存在 190+ 个自定义变量；
2. **默认值必须可推导**（`Path(__file__)` / `%~dp0` / `sys.executable`），env 只作覆盖；
3. **找不到就明确报错**（fail-loud），禁止静默回退到无效路径。

### 1.2 统一命名表

| 用途 | 变量名 | 默认值（推导） | 已存在同名 |
|---|---|---|---|
| **工作区根**（跨盘引用总开关） | `ALLIN_WORKSPACE` | `G:\`（Windows 下由当前盘或 `Path.home()` 推导不便，故用 env + 文档说明） | 新设 |
| 某仓根（跨仓引用） | `<PROJECT>_ROOT` | `ALLIN_WORKSPACE\repos\<project>` | `MUSICKIT_ROOT`、`PLATFORM_ROOT`、`PP_ROOT` 已有 |
| 本仓自身根 | （不用 env） | `Path(__file__).resolve().parents[N]` / `%~dp0` / `$PSScriptRoot` | — |
| 解释器 | `<PROJECT>_PYTHON` 或全局 `PYEXE` | `sys.executable`（py）/ `python`（bat、走 PATH） | `PP_PYTHON`、`BLOODMUSIC_PYTHON`、`CRAWL_PYTHON`、`PLATFORM_PYTHON`、`PYEXE` 已有 |

### 7.1 范围与口径修订（**重要**：原「54 处 / 11 仓」被本轮实测推翻）

原清单只在 `hardcoded_paths_final_*.csv` 的 **MUST_FIX** 行上判「路径是否已失效」（T1）。实跑中暴露**三个系统性盲点**，真实修复面远大于原估计：

| # | 盲点 | 机制 | 实证 |
|---|---|---|---|
| ① | 只在 MUST_FIX 行上判死 | 赋值型行（`MUSIC_ROOT = Path(r"/radio/music")`）被判为 LIKELY_FIX，**从未进入 T1 清单** | audio-separator 的 `_inspect_*.py` / `_stat_*.py` / argparse 默认值共 25 处 |
| ② | 转义双反斜杠漏判 | Python 源码里写作 `"//allin//not//OK"` 时，取「前两段」得到 `D:\`，`Test-Path D:\` 为真 → **判活** | py_test_runner `main.py` 147/168/293/360、fish 16 处 |
| ③ | 死根清单来自 ① 的产物 | 清单只含 MUST_FIX 里出现过的死根，漏掉 `G:\csmusic*`、`G:\csmusic_stems*` 等 | 复扫时新出现 `G:\csmusic` / `G:\csmusic_stems` |

**修正后的判死口径**（已用于本轮终检，第 4 批门禁沿用）：
1. 对**全量命中**判死，不限于 MUST_FIX；
2. 分隔符容错 `[\\/]{1,2}`（兼容转义写法）；
3. 判据 = 路径前 1~2 段在盘上不存在；系统路径白名单（`Windows\`、`WINDIR`、`SYSTEMROOT`、`ProgramData\chocolatey`、`C:/`、`C:/Users`）除外；
4. 命中后按 `CODE 有效行 / CODE 注释行 / DOC·CFG` 三分，只有「CODE 有效行」算阻断项。

按此口径，本批实际处置 **12 仓 / 约 130 处**（原范围 54 处）。
