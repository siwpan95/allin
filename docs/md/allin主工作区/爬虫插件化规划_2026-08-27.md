# 爬虫插件化规划（2026-08-27 立项）

> 用户拍板方向：爬虫类适合插件化（D20 实验证伪单机小游戏插件化）。本文是规划文档，不是执行记录；决策点逐项列明，拍板后按顺序执行。

## 0. 方向与判定标准（+ 拍板记录 2026-08-27）

- **适合插件化**：宿主天然「多能力组合 + 频繁增删 + 生命周期可逆」——爬虫源族/站点族满足全部三条（源=插件、随时增删、任务可停可重投）。
- **不适合**：单机 GUI 小游戏（D20 教训：玩法整体不可拆，插件化只剩复杂度）。
- 判定口径（入 MEMORY）：是 → 插件化；否 → 单体优先。

**用户拍板（2026-08-27）**：
- 顺序：先做 P1 规范，再动项目；
- P2 首批改造三项全做：photo 并入 image-scraper 源族（A 模式）+ webcopier 出 manifest 接入 crawl-hub（B 模式）+ Sohu/Taobao/Xianyu/Zhaopin 归档；
- P3 crawler-kit **三件全提**：Downloader + 身份池 + 登录态一次提炼；
- 老爬虫四件处置 = 归档。

## 2. 选型判定表（什么爬虫选什么形态）

| 条件 | 形态 |
|---|---|
| 同语言轻量、源族多、需共享状态（断点/进度/代理池/身份池） | **A 进程内插件**（image-scraper 模式）：源族作为注册表条目 |
| 重依赖/易崩/跨语言/需独立发布/自带 GUI 或服务 | **B 进程级插件**（crawl-hub 模式）：manifest + 子进程隔离 |
| 已有浏览器扩展/网页形态的能力 | **C 迁移**：契约先定，宿主换（Playwright 桥接），参考 bilibili-helper-py |
| 单站点一次性脚本、无人维护 | 归档/单体，不插件化（老爬虫四件候选归档） |

- 生命周期可逆：B 模式 stop 字段与平台 stop 纪律一致；A 模式 Downloader.close() 随任务结束回收。
