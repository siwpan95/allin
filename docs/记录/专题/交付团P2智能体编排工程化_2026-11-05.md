## 1. routes.yaml 完整 schema 定义（落点：`preset/allin/routes.yaml`）

### 1.1 字段定义

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `version` | int | ✅ | 恒为 `1`（当前代） | schema 代数，g21 拒绝不认识的代数（fail-loud） |
| `routes` | list[map] | ✅ | 长度 ≥1；本期 = 15 | 路由条目，顺序即 SKILL.md §4 表序 |
| `routes[].id` | str | ✅ | `^[a-z0-9][a-z0-9-]*$`，全表唯一 | 同时是锚点 id 与 skill 目录名（本期二者同值，见 1.3 注） |
| `routes[].skill` | str | ✅ | = `.workbuddy/skills/` 下真实目录名 | 路由目标 |
| `routes[].entry` | str | ✅ | 仓根相对 POSIX 路径（`/` 分隔，禁盘符——g01 判据） | 入口文件，默认 `<skill>/SKILL.md` |
| `routes[].forms` | list[enum] | ✅ | 非空子集 ⊆ `[workbuddy, dsh]` | 该路由须在哪些形态有锚点；g21 按此逐形态判 |
| `routes[].trigger` | str | ✅ | 非空，≤120 字 | 机器可读命中条件；**不要求**与 SKILL.md 人写措辞逐字一致（对账靠锚点不靠文本相等） |
| `routes[].lastVerified` | str | ✅ | `YYYY-MM-DD` | 最近一次人工/实测验证日期；g21 对超龄只 WARN 不红（见 §2.4） |

### 1.3 零依赖 schema 校验方式（Python 标准库，无 PyYAML 也能跑）

背景实证：`run_all_gates.sh` 注释明示「PATH 上的便携 3.13.14 无 PyYAML ⇒ g18 假红」。g21 若依赖 PyYAML 就会重蹈覆辙。routes.yaml 是**受控子集**（无嵌套 map、无多行标量、无锚点引用），足以用 ~60 行行式解析器覆盖：

```python
# tools/gate/agent_parity.py 内嵌（伪代码，仅标准库）
ANCHOR_RE = re.compile(r'^\s*-\s*\{\s*id:\s*(\S+?),')      # 条目起始
FIELD_RE  = re.compile(r'^\s*(\w+):\s*(.+?)\s*\}\s*$')      # 条目收尾（flow 式）
KEYVAL_RE = re.compile(r'^(\w+):\s*(.*)$')                  # 顶层 version/routes

def load_routes(path):
    """解析受控 YAML 子集；超出子集即 fail-loud（exit 2），绝不静默猜。"""
    # 1) 逐行扫：顶层只认 version:<int> 与 routes:；
    # 2) routes 下每条必须是单行 flow map { k: v, ... }（§1.2 骨架即此形），
    #    遇到 '- id:' 多行式 / 嵌套缩进 / '!!' tag / '|' 块标量 →
    #    raise ParseError(f"L{n}: routes.yaml 超出受控子集，请保持单行 flow 条目")；
    # 3) 逐条校验 §1.1 表：id 正则、forms ⊆ {workbuddy,dsh} 且非空、
    #    lastVerified 用 datetime.strptime(x, '%Y-%m-%d')、trigger 非空≤120；
    # 4) id 重复 → E201 级结构错（fail-loud）。
    # 显式 encoding="utf-8"（GBK 控制台边界）；解析结果返回 list[dict]。
```

**为什么不直接用 PyYAML-有则用-无则降级**：g21 的结论要进 CI 与判据 JSON，「有时用 A 解析有时用 B 解析」本身就是不可复现源。受控子集 + fail-loud 是唯一可复现解。若未来 schema 升级到需要真 YAML，届时再评（§7 待确认）。

## 2. g21 门禁（agent-parity）详细设计

### 2.1 落点与定位

- 文件：`tools/gate/agent_parity.py`（命名对齐既有 `check_ps1_bom.py` / `agent_regression.py` 的 Python 门禁族；编号 g21 沿 P1b 增量表，g02 空缺沿用不回填）。
- 接线：**进 `run_all_gates.sh`（Python 门禁族模式），不注册进 run.ts 的 TS 套件**——与 docs_index/check_ps1_bom 同等待遇，理由：g21 是纯标准库 Python，跨平台，且 TS 套件与 Python 门禁的分界（npm run check:governance vs bash 跑批）是既有秩序，不打破。
- **吸收 M5**：g21 顺带校验 `entry` 文件存在且非空可读（它手里已有台账，另设门禁就是两道门禁扫同一事实——P1b 决策「对账式」精神）。

### 2.2 锚点注入方式与格式规范

锚点正则：`<!--\s*route:([a-z0-9][a-z0-9-]*)\s*-->`（与 routes.yaml `id` 同一字符集）。

| 形态 | 载体 | 注入位置 | 形态示例 |
|---|---|---|---|
| workbuddy | `SKILL.md` §4 路由表 | 每行表格行尾追加锚点列 | `\| DSH 本地部署拉不起来 / 会话异常 \| \`dsh-deploy-repair\` \| <!-- route:dsh-deploy-repair --> \|` |
| dsh | `allin.patch.yml` GOVERNANCE 段 | 段内**新增紧凑路由清单**，每条一行、行尾挂锚点 | `- DSH 部署修复→dsh-deploy-repair <!-- route:dsh-deploy-repair -->` |

**格式纪律（全部来自仓内踩坑实录，逐条对应）**：

1. **每锚点每形态恰好一次**。重复 → 红（E104）。防止「注释里举例写了一遍」造成假命中——verify-mount.ps1 的 Get-GovBlock 特意「锚定标记整行而非子串首现」（2026-10-29 g16 踩坑），g21 用「计数=1」的更严判据同源防坑。
2. **DSH 侧锚点必须落在 GOVERNANCE:BEGIN/END 之内**。段外命中视为孤儿（E103）。段定位复用 verify-mount 同款规则：`TrimStart().StartsWith('<!-- GOVERNANCE:BEGIN')` 的**整行**标记，避免正文上方注释里的字样拉错块起点。
3. **锚点只增不语义化**：锚点本身零语义（人写正文可自由改措辞），g21 只判「有/无/唯一」，措辞漂移不归它管——归 refresh-gov-block/verify-mount 的同源层管（§2.5）。
4. **改 GOVERNANCE 段后必跑派生副本三连**：`refresh-gov-block.py --write` → `--check` → `verify-mount.ps1`（§3 流程），否则仓内 g21 绿而挂载层仍旧一代——两个失败域分开判。

### 2.3 三方对账算法（伪代码）

```python
def main():
    routes = load_routes(ROOT/'preset/allin/routes.yaml')          # §1.3，超子集 exit 2
    wb_text   = read_utf8(ROOT/'.workbuddy/skills/allin-governance-agent/SKILL.md')
    dsh_block = extract_gov_block(read_utf8(ROOT/'preset/allin/allin.patch.yml'))  # 整行标记定位，缺失 exit 2
    wb_anchors, dsh_anchors = count_anchors(wb_text), count_anchors(dsh_block)     # {id: count}

    errors, warnings = [], []
    ids = [r['id'] for r in routes]
    for r in routes:
        if not (ROOT/r['entry']).is_file() or (ROOT/r['entry']).stat().st_size == 0:
            errors.append(E105(r['id'], r['entry'], FIX='补齐入口文件或改 entry 指向'))
        if 'workbuddy' in r['forms'] and wb_anchors.get(r['id'], 0) != 1:
            errors.append(E101/E104(r['id'], 'workbuddy'))          # 0 次=缺，>1 次=重复
        if 'dsh' in r['forms'] and dsh_anchors.get(r['id'], 0) != 1:
            errors.append(E102/E104(r['id'], 'dsh'))
        if days_since(r['lastVerified']) > 90:
            warnings.append(W301(r['id']))                          # 只 WARN 不红（见 2.4）
    # 反向对账：正文里有而台账里没有的锚点 = 孤儿锚（台账腐化或锚点笔误）
    for side, m in (('workbuddy', wb_anchors), ('dsh', dsh_anchors)):
        for aid in m:
            if aid not in ids: errors.append(E103(aid, side, FIX='删孤儿锚或补 routes.yaml 条目'))
    write_result_line(errors, warnings)     # §2.4；一次运行=一行完整快照（原子性硬约束），append 至 g21-runs.jsonl
    print_human_summary(errors, warnings)   # 逐条 [E码] + 修复指引
    exit 1 if errors else 0
```

复杂度 O(routes + anchors)；单次 <100ms，对「gates 全绿 ≤90s」预算零压力。

### 2.4 判据结果落盘（g21-runs.jsonl）、退出码与错误信息格式

**落盘**（2026-11-04 与数据建模工程师对齐定稿，采纳其 P2 §3 数据契约）：`tools/gate/audit/g21-runs.jsonl`——**JSONL 逐行、一次运行 = 一行完整快照**（原子性硬约束：portal `/api/orchestration` 读最后一行做 drift 展示，绝不按 route 拆行）、5MB 轮转（同 tasks.log 口径）；该目录已被 .gitignore 覆盖（数据建模已核实，勿改 .gitignore）。此前本稿的「单文件快照 agent-parity.json」方案**作废**，让步理由：① P1b 原文即「模式同 gate-runs」；② 追加写天然原子，覆写快照在 Windows 上有写一半损坏的窗口；③ 免费获得逐次漂移历史（日志即事实源）。gate-runs.jsonl 仍记 exit/耗时（run() 包装器），g21-runs.jsonl 记逐路由明细——互补不重复。

行 schema（`type:"g21-run"`）：

```json
{ "type": "g21-run", "checkedAt": "2026-11-04T12:00:00Z", "commit": "abc1234",
  "routesFile": "preset/allin/routes.yaml", "routesReadable": true,
  "results": [
    { "routeId": "c-drive-scan-clean", "side": "dsh", "ok": false, "severity": "error",
      "reason": "GOVERNANCE 段缺锚点 <!-- route:c-drive-scan-clean -->（0 次，期望 1 次）。修复: 在 preset/allin/allin.patch.yml GOVERNANCE 段路由清单补该行+锚点，跑 refresh-gov-block.py --write && --check 后复跑本门禁" },
    { "routeId": "pyglet-app-package-dist", "side": "workbuddy", "ok": true, "severity": "warn",
      "reason": "lastVerified 已 97 天（>90），建议实测复核后刷新日期" }
  ],
  "summary": { "total": 15, "ok": 14, "drift": 1, "warn": 1 } }
```

对数据契约的三点回应（已同步储海量）：

1. **severity 字段（采纳，请其 §3 增补）**：result 行增加 `severity: "error"|"warn"`（ok=true 且无告警时可省略）。仅 `severity:"error"` 计入 drift 并决定退出码非 0；`warn`（如 W301 lastVerified 超龄）不红。summary 增 `warn` 计数。没有它，我侧的 E1xx/W 两级判据在行结构里无法表达。
2. **side 枚举**：现值仅 `"workbuddy"|"dsh"`；出现第三形态属 P1b §6 演进触发条件，届时随 `version` 代数一起扩枚举，不提前预留。
3. **崩溃行的一个漏洞（请其 §3 修订）**：门禁自身崩溃（E2xx：routes.yaml 解析失败等）也须落一行 fail-loud，✅；但「results=[] + summary.drift=total」在 **total 不可知**（解析失败拿不到条目数，total=0）时会落成 `drift=0` 的行——对只读 summary 的消费方**看起来像全绿**，恰是 fail-loud 要防的假绿。修订建议：崩溃行加 `"error": {"code": "E201", "msg": "..."}` 字段且 `routesReadable:false`；platform/orchestration 与 `allin status` 的判红条件定为 **`routesReadable:false 或 error 字段存在 ⇒ 红`**，而不是 `drift>0 ⇒ 红`。

**错误信息格式**（人读与行内 reason 同构）：`[g21][<code>] route=<id> side=<form> | <事实> | 修复: <一句话指令>`；reason 失败时 ≤500 字符且必须带修复指引（P1b R2 裁决）。

| 退出码 | 含义 | 口径 |
|---|---|---|
| 0 | 绿（对账通过，可有 WARN） | run_all_gates 记 ok |
| 1 | 红·漂移（E1xx：锚点缺失/孤儿/重复、entry 缺失） | 可修复类，错误信息必须带 `fix` 字段 |
| 2 | 红·结构（E2xx：routes.yaml 超子集/解析失败、GOVERNANCE 标记不成对、SKILL.md 本体缺失、version 不认识） | fail-loud：判不了 ≠ 通过 |
| 3 | 环境错（解释器/编码） | 对齐 run_all_gates.sh 的 ENV ERROR=3 口径 |

**错误信息格式**（人读与 JSON 同构）：`[g21][<code>] route=<id> side=<form> | <事实> | 修复: <一句话指令>`。修复指令必须指名**文件与动作**（如上例），不留「自己看文档」。

**错误码表**：E101 WB 锚缺 / E102 DSH 锚缺 / E103 孤儿锚 / E104 锚重复 / E105 entry 缺失或空 / E106 trigger 超限或空 / E201 routes.yaml 解析或 schema 错 / E202 GOVERNANCE 标记不成对 / E203 routes 为空或 version 未知 / W301 lastVerified 超龄。

## 3. 双形态同步流程（改任一侧文本的标准操作序列 + CI 双路拦截）

### 3.1 标准操作序列（人改 → g21 → 修锚点 → 双绿）

**场景 A：只改 SKILL.md（WorkBuddy 侧）或只改路由相关文本**

```
1. 改 SKILL.md 对应行（措辞随意，但保留 <!-- route:<id> --> 锚点在原行）
2. python tools/gate/agent_parity.py
   ├─ 绿 → 完（若还动了别的门禁域，继续跑跑批）

4. g21 复跑 → 绿；powershell preset/allin/verify-mount.ps1 → 0/1（1=WARN 挂载层刷新提示）
5. 记账与改动同一笔提交（SKILL.md §5.1 铁律：退出码贴进提交信息，禁「应该绿了」）
```

**场景 B：改 GOVERNANCE 段正文（DSH 侧唯一正文）**

```
1. 改 allin.patch.yml GOVERNANCE 段（含路由清单则同步锚点）
2. refresh-gov-block.py --write && --check（三副本刷新，落后 exit 3）
3. python tools/gate/agent_parity.py（若动了路由清单行）+ npm run check:governance（g16 双载体等）
4. verify-mount.ps1 → 确认挂载段已同源（WARN=挂载层落后，重启 DSH 生效）
5. 若正文改动影响 SKILL.md 等价段落 → 同步 SKILL.md（对齐段落语义，非逐字）→ 回到场景 A 收口
```

**场景 C：新增/退役一个专项 skill**（路由表腐化的主入口，最需纪律）

```
1. 建/删 .workbuddy/skills/<name>/（SKILL.md 必须，frontmatter name = 目录名——§5 实测纪律）
2. routes.yaml 增/删一条（id/skill/entry/forms/trigger/lastVerified）
3. 双侧锚点同增/同删（SKILL.md §4 表行 + GOVERNANCE 段路由清单行）
4. g21 → refresh-gov-block --write/--check → verify-mount → 记忆卷记「已晋升/已退役」条目
   （SKILL.md §2.1 晋升通道要求：固化 skill 须「同步双载体→过门禁→记账」三连，本序列即其工程化）
```

## 4. `allin status` 子命令设计（kernel CLI，跨面只读汇总）

### 4.1 SERVICES 白名单扩法（已读 `kernel/registry.py`，按其注释纪律执行）

registry.py 头注释明确：「新增一个被内核调度的支柱/工具，**只改这张表 + 对应 services/*.py**，不再加样板文件」；短名必须命中封闭白名单才可挂载（防「配置即代码」任意 import）。

```python
# kernel/registry.py —— SERVICES 增一条（只读汇总服务）
SERVICES = {
    'docs': ..., 'platform': ..., 'preset': ..., 'tools': ...,
    'status': 'kernel.services.status_service:StatusService',   # ★新增：跨面只读汇总
}
```

配套三件（实施阶段做）：① 新建 `kernel/services/status_service.py`（class StatusService，**只读**，只 open/读文件，不 import platform/website 任何代码——「绝不 import 项目代码」纪律）；② `kernel/configs/cordis.allin.yml` 挂载树加 `status` entry（tree.load_tree 白名单解析才放行）；③ `kernel/tests/` 补一条导入冒烟（run_all_gates L189 的 unittest discover 会自动收）。

### 4.2 argparse 接线（伪代码）

```python
# allin_cli.py（既有 argparse 骨架内）
p = sub.add_parser('status', help='跨面治理状态只读汇总（文件级，不依赖任何服务在线）')
p.add_argument('--json', action='store_true', help='输出机器可读 JSON')
p.add_argument('--strict', action='store_true', help='任一段红/降级即非 0 退出【待确认口径】')
```

### 4.3 读哪些文件（全部仓根相对自发现，零盘符——g01 判据）

| 段 | 文件 | 读法 | 降级行为 |
|---|---|---|---|
| 平台 | `platform/data/running.json` | 读 JSON，取运行中条目计数 | 缺失 → `platform: 未运行/无记录`（G3 口径：platform 离线不影响本命令） |
| 门禁 | `tools/gate/audit/gate-runs.jsonl` | 尾部回读 ≤200 行，按 label 取各门禁**最近一次** exit；汇总绿/红/最红时间 | 缺失 → `gates: 从未跑批` |
| 编排 | `tools/gate/audit/g21-runs.jsonl` | 尾部回读取**最后一行**（一行=一次完整快照，数据契约硬约束）：`routesReadable:false` 或含 `error` 字段或 `summary.drift>0` → 红；文件缺失 → `orchestration: g21 从未运行（跑 python tools/gate/agent_parity.py）` |

**fail-loud 分界**：文件**缺失** = 降级显示、命令整体仍 exit 0（状态查询不是门禁）；文件**存在但解析失败** = 该段标 `corrupt` 且 `--strict` 下 exit 2、非 strict 下 exit 1 并打印段名——证据损坏是真实异常，不许静默当「缺失」【待确认：非 strict 时 corrupt 是否也非 0，见 §7】。

### 4.4 输出格式

```
$ python allin_cli.py status
allin 治理状态 @ <仓根>
  平台   : running 3 / registered 105（数据时间 2026-11-04T11:xx）
  门禁   : 最近跑批 2026-11-04T10:xx → 21/21 绿（最红项：无）
  编排   : g21 绿 · 路由 15/15 对账一致（2026-11-04T10:xx）

$ python allin_cli.py status --json
{"schema":1,"ts":"...","platform":{"readable":true,"running":3,"registered":105},
 "gates":{"readable":true,"lastRunAt":"...","ok":21,"fail":0},
 "orchestration":{"readable":true,"ok":true,"routesTotal":15,"errorCount":0}}
```

字段口径与 P1b §3.1 `/api/orchestration`、`/api/overview` 对齐（platform 读同一批文件，website 经代理读 platform——`allin status` 是 platform 离线时的同源降级视图，三者数字必须可互相对账）。
