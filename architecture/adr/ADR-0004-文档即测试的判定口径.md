# ADR-0004 —— 文档即测试的判定口径

- 状态：**accepted**（2026-10-28 落地：`tools/gate/governance/gates/g19_docs_refs.py`）
- 相关：调研线 4（Policy-as-Code）：「checks must be fast, high-signal, low false-positive」

## Problem

「文档即测试」听起来无懈可击：文档是断言集，那就跑断言。
真做起来第一条就撞墙——本仓 347 个 Markdown，只按「引用到的路径必须存在」去判，
首跑 157 条红，其中绝大多数**不是谎话**：

- `docs/记录/` 里的审计报告写 `pp_cli.py`（那是**兄弟仓**的工具，不在本仓），说的是它当时的样子；
- `docs/规范/SPEC-104` 写 `start-dsh-web.py`，随 DSH 分发版一起退役了；
- `.workbuddy/skills/*/SKILL.md` 描述的是**别仓**的脚本。

一刀切判红的后果是可预期的：红成一片的门禁会被关掉。
所以必须回答——**哪些文档的哪些主张，是本仓有资格判的？**

## Decision

判据按「谁在为当下作担保」分层，而不是按文件类型一刀切：

| 主张 | 覆盖范围 | 理由 |
| --- | --- | --- |
| 命令目标（`python x.py` / `node x.js` / `bash x.sh`） | **全部在范围内的文档**，含记录 | 命令是「照抄即可执行」的承诺。记录可以说某文件当时存在，但给出的命令现在跑不通就是误导 |
| `npm run <name>` | 同上 | 同上 |
| 路径引用 | **仅规范 / 事实源 / 各子树 README/AGENTS/SKILL** | 规范与事实源声明「现在为真」；记录是 dated 快照，声明「当时如此」 |

范围外的树**豁免但计数可见**（不静默）：`docs/md/`（冻结历史树，与 `docs_index` 同一口径）、
`vendor/`、`.workbuddy/skills/`、`tools/gate/audit/`（运行时产物，本就不入库）。

三条防误报设计，都是首跑踩出来的：

1. **解析基准放宽**。文档写命令可能相对仓根、相对自身目录，或带前导 `/` 表示仓根
   ——三种都接受，哪儿都不存在才红。
2. **扩展名按长优先 + 词尾边界**。`mcp-actions.jsonl` 曾被 `js` 分支截成 `.js`、
   `hooks.json` 被截成 `hooks.js`，凭空造出三条假红。
3. **存量进棘轮，不要求首日清零**。26 条存量发现中，当场修掉 10 条真错
   （`tools/README.md` 的 `check_ps1_bom.py` / `watchdog.py`、
   `tools/gate/governance/preset/README.md` 的 `g14_preset.py`
   —— 都是文件搬过家而文档没跟上），
   其余 20 键冻结进 `tools/gate/governance/baseline/g19-docs-refs.txt`，
   并在 `exceptions.yml` 登记为 EX-006（带到期日与补偿控制）。
   规范正文的修订是独立动作，不该由新增门禁夹带执行。

## Alternatives considered

| 方案 | 为什么没选 |
| --- | --- |
| 全部文档一视同仁判红 | 首日 157 红，其中多数是跨仓引用；红成一片的门禁会被关掉 |
| 只判命令，不判路径 | 放过 SPEC-102/104 这类「规范里挂着不存在文件」的情形，那正是文档腐烂的主战场 |
| 存量全部当场修 | 改规范正文属治理动作，需走 ADR 与「最后修订」；由门禁顺手改等于绕过流程 |
| 只报告不阻断（影子模式） | 本仓已有 `notes` 机制承载报告类信息；阻断类门禁一旦降级为提示，就不会有人再修 |

## Consequences

- 正：命令类承诺 100% 可执行验证；路径引用在「当下为真」的文档里被守住。
- 正：豁免全部计数可见（`exempted:` 行里能看到每棵树的篇数），不会静默放过。
- 负：`docs/记录/` 里的路径引用不再受检——新写的记录若引用错路径不会被拦。
  这是用「记录天然是快照」换来的，若日后需要，可改成「记录只判仓内前缀（`docs/`、`tools/gate/`）」。
- 负：基线键按「路径 + 文本 + 类型」去重，**同一文件内重复出现的同一失效引用只冻结一次**，
  因此基线行数（20）小于发现条数（26）。燃尽统计读的是发现条数，不是行数。
