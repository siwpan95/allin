## 一、调研输入（四条线，联网核实）

### 1. Cordis

| 事实 | 对 allin 的启示 |
| --- | --- |
| 官方 `cordis` 已发布 4.0.x（npm，ESM-first；scaffolder 需 Node 22） | allin `kernel/` 用的是 **Python 侧 vendored cordis**（`vendor/cordis` + `kernel/cordis` 重导出层）。**不迁 Node**——会毁掉 4 个 service 与全部 Python 门禁 |
| 配套 `@cordisjs/plugin-loader`(1.0.0-rc.3)、`plugin-include`(YAML/JSON 声明式)、`plugin-group`、`plugin-hmr`(热重载)、`plugin-logger-console`、`plugin-timer` | 做**能力对齐矩阵**即可：声明式配置 / 热重载 / 可逆副作用 / waterfall 事件 |
| 机制 = Context 依赖注入 + Fiber 可逆副作用 + waterfall 事件 + Schemastery schema + volatile 配置热更新 | 对齐度写进 `architecture/`，作为长期项（P2-2） |

### 2. DeepSeek Harness（DSH）

| 事实 | 对 allin 的启示 |
| --- | --- |
| 「Model + Harness = Agent」，基于 Cordis「一切皆插件」 | allin 的 preset 正是插进 DSH 的 agent-preset（`insert` 进 `@deepseek-ai/dsh-agent-preset`，id `allin`, order 5） |
| 扩展点三层 + 一层：plugin（进程内，可换 agent loop）/ MCP server（外部进程，只桥 Tools）/ skill（`/name`）/ subagent | 治理面不止"文本注入"这一种形态 |
| MCP 经 `@deepseek-ai/dsh-mcp-client`（stdio 或 streamable-http），工具名 `mcp__<serverName>__<tool>`，**受 DSH 工具治理（allow/deny、timeout、结果重写）** | 治理可作为**可调用工具**进入 agent（P1-1） |
| **Hook Protocol**：`SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / Stop`；钩子 **exit 2 = 阻断操作**，stderr 作阻断消息、stdout 可注入上下文 | 治理可作为**硬栅栏**（agent 写文件/提交前跑门禁，真的拦住）（P1-2）——比文本注入硬得多 |
| 四种模式含 **PTC**（模型写程序一次跑完长流程，中间数据留在执行环境，省 token） | 139 仓批量巡检可走 PTC（P2-4） |
| 插件打包 = npm 包 + `package.json` 声明 `dsh.bundle` + GitHub topic `dsh-plugin` + 标注验证过的 dsh 版本 | P1 落地后的发布面（P2-5） |
| 本仓 `preset/allin/agent.cordis.yml` **已写明 DSH 接入 MCP 的官方配方** | 最贴生态的那条路，配方已在手边 |

### 3. MCP（生态）

- 2026 年已成工具层的**事实传输标准**（不是替代 function calling，而是其下的传输层）。
- 实践：**一个 MCP server per bounded context**；**治理、配额、审计都落在 MCP 层**；安全基线 = 只读默认 + 秘密过滤 + 审计日志 + 限流。
- 叠加效应：**Rulesets = 标准，Skills = 模式，MCP = 现实**。allin 已有 SKILL.md（标准）+ 技能（模式），**缺 MCP（现实）**。

### 4. Policy-as-Code / 仓库治理

| 共识 | allin 现状 | 差距 |
| --- | --- | --- |
| 分层门禁：commit/PR → secrets+依赖；build → SCA+SBOM；package → 许可；publish → 签名+provenance | 有 16 道门禁，但偏"本仓规矩" | 缺供应链三件套（P1-3） |
| **secrets day-1 block**；**SBOM 先"只证明不 gate"** | g03 管本仓凭据 | 缺 gitleaks 通用库 + SBOM |
| 例外必须登记：ID / 控制项 / 业务理由 / 补偿控制 / 审批人 / **到期日** / 状态，周度三查 | baseline ratchet + 豁免表 | **例外不会过期** = 债务永久化（P0-4） |
| 指标：deny 数、误报率、MTTR、**门禁逃逸率**、**证据新鲜度**、**例外燃尽** | 门禁结果无时间序列 | 无法算三项指标（P0-2） |
| 反模式：别 day-1 block SAST、别绝对覆盖率阈值、别一次上 10 个扫描器、别全 blocking（先 shadow mode）、检查须 <60s | — | 列为"明确不做" |

## 四、本次调研的两条收获

1. **allin 的治理目前只是"写给 agent 看"**（SKILL.md + GOVERNANCE 文本注入）。DSH 官方已提供把它升级为"给 agent 用"（MCP）与"对 agent 生效"（Hook exit 2 阻断）的成熟路径，且 `agent.cordis.yml` 里已写好 MCP 配方。
2. **治理自身缺可观测性**：门禁结果没有时间序列，例外没有到期日——调研里的三项核心指标（逃逸率 / 证据新鲜度 / 例外燃尽）在 allin 里都算不出来。P0 四条正是补这两块。
