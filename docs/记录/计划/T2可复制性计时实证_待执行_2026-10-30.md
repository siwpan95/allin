## 2. 测什么（一个数字）

**一个没用过 allin 的人，只靠仓里的文档，从零到「20 道门禁跑绿」需要多少分钟。**

判据：**≤30 分钟、连续 3 人、全程不救场**。
30 分钟取自 OPC 行业公开的「上手断裂点」口径（非本仓自定）。

## 3. 怎么测（照做，别改良）

1. 找 3 名被试：**优先非本仓作者、最好是不熟 Windows 环境的人**；懂 AI 工具但不懂本仓更好。
2. 只给三样东西：
   - 仓地址 `https://gitee.com/siwpan/allin`
   - `docs/新人开发上手指南.md`
   - 一句任务：**「让门禁跑起来」**（不说门禁是什么、不说怎么跑）
3. 开秒表。**不提示、不救场、不替他 debug、不解释报错。**
4. 全程只记四件事：第几分钟 / 卡在哪一步 / 他说的原话 / 有没有主动求助。

## 4. 卡点必须分类（决定下一步做什么）

测完不是看"过没过"，而是看**卡点属于哪一类**：

| 类别 | 例子 | 说明什么 | 下一步 |
|---|---|---|---|
| **过期事实** | 照文档找 `D:\allin`、按文档用 PortableGit 路径、以为主 Python 在 PATH | `g20` 判据仍不够宽 | 回流加固 `g20`（扩到版本号/章节引用） |
| **环境缺失** | 没装 Python、没有 Git、PowerShell 版本不符 | 上手指南的前置检查不够 | 补「环境自检脚本」，不改判据 |
| **概念难懂** | 不懂"事实源/门禁/铁律"指什么 | 问题在**结构**不在保鲜 | 另立批次重估文档组织，别再堆条款 |
| **文档缺失** | 某步根本没写 | 补文档 | 补 `新人开发上手指南` 对应章节 |

## 5. 停止线（先写死，免得事后找解释）

- 3 人**全部 ≤30 分钟**独立跑通 ⇒ 可复制性成立，`SPEC-105` 的「可复制」主张可对外陈述
- 任一人 **>30 分钟**或需要救场 ⇒ 可复制性**暂不成立**，卡点即产品问题
- 三人卡在**同一处** ⇒ 那不是人的问题，是入口只有一处，改它收益最高
- 卡点**集中在「过期事实」** ⇒ `g20` 方向正确，继续加判据
- 卡点**集中在「概念难懂」** ⇒ **停止加判据**，问题在结构，`g20` 加再多也没用
