# 跑团 / 地城项目反向重构路线图（2026-08-27，R2 后续）

> 前提：D20 规则内核已并入 alloy（`alloy/trpg/`，an-engine 14e0109，套件 484 全绿）。
> 本路线图按用户 R2 拍板制定：**先有 alloy 内核，再靠它反向增强/重构这些跑团/地下城项目**。
> 状态：路线图（尚未逐仓开工，每仓开工时在此勾进度）。

## 总原则

1. **引用形态**：按治理准则「复制优于共享」+ alloy 既有机制——各仓以 `from alloy.trpg import Character, preset_trpg` 引用内核；
   若仓内需要随包分发，用 alloy 的 `sync`/`engine.patch.yaml` 机制（`python -m alloy sync <项目> --dry-run|--apply`）维护内联副本，定制保留、冲突可见。
2. **改造边界**：只替换「规则/数值/检定」层（骰点、属性、技能、成长、角色卡），不动各仓的玩法壳（地牢生成、战斗演出、叙事引擎）。
3. **数据单一事实来源**：各仓自有数值表（怪物、物品）逐步改为规则数据用 `alloy.trpg.data` 的常量，仓内特有数据留在仓内。
4. **行为钉住**：每仓重构前先跑其现有测试/黄金样例（如 D20 的 盗贼.txt、running-group-simulator 的 GURPS 用例），重构后逐字段对齐。
5. **借鉴必记账**：各仓 CHANGELOG/README 记录「规则内核改引 alloy.trpg（自 D20 并入，R2）」。
