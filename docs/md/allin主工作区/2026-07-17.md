# 2026-07-17

## 构建 G:\game ——「地牢冒险者」Roguelike（example + allin_engine 融合）

用户指令：`G:\example + G:\allin_engine = 一个完整的可以运行的游戏`。
- `G:\example` 原本只是 procgen 的「生成 PNG+报告」演示，不可玩。
- `G:\allin_engine` 是通用游戏引擎（ECS/世界模型/系统/渲染/音频/AI）。

做法（遵循"复制即复用、反对跨项目硬引用"哲学）：
- 把 `allin_engine` 源码（剔除 .git/__pycache__/fonts/.github/saves/test，~2.8M）和
  `procgen` 包（244K）**内联**进新项目 `G:\game`，运行时零依赖 G:\ 原目录。
- 引擎各层都被真实用到：MapData(地形)、Item/create_weapon/armor/consumable(loot)、
  PlayerState、SimpleCombat+MobTemplate+MobLibrary(战斗)、Inventory(背包)、
  ai.decision.GenericStateMachine(怪物 AI)、core.ecs World/Entity/Component(实体模型)。
- procgen 负责：generate_dungeon/generate_cave(几何)、NameGenerator(怪物/区域名)、LootTable(掉落风味)。

关键实现点 / 踩坑：
- `Position/Health/MobBrain` 必须统一从 `entities` 导入，不能混用 `allin_engine.core.ecs.Position`
  （类身份不同 → `entity.get()` 失效）。
- 内联引擎的顶层 `__init__` 仍 `import allin_engine.test`，故需把 `test/` 也一并内联。
- 实例属性 `self.log`（list）与方法 `def log()` 同名冲突 → 把列表改名为 `self.logs`。
- 自动演示机器人最初用贪心导航会卡死（局部最优），改为 BFS 寻路（`_bfs_step`，怪物格视为可通行→撞上触发战斗）后稳定通关/阵亡。
- `random.seed(seed)` 让战斗运气也由种子决定，种子可复现整局（world+combat）。

验证：managed Python 3.13（仅 numpy+PIL，无 pygame/scipy/asteval）与 system 3.14 均跑通；
`--auto` 模式 seed 7 稳定 `won`、seed 1 稳定 `lost`，无异常。交互渲染（ASCII 棋盘+选手/怪物/物品/楼梯/HUD）正常。

运行：`cd G:\game && python run.py`（交互）/ `python run.py --auto`（自检）/ `--seed` / `--floors`。
文件：G:\game\{entities.py, monster_ai.py, world_gen.py, game.py, run.py, README.md} + 内联 allin_engine/ procgen/。
