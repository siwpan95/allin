## 1. 为什么要建项

一条已经无人值守跑了一个多月的自动化（每周检测 `deepseek-ai/deepseek-harness` 的 release、
下载 zip 与 tar.gz 源码归档、校验、解压复核），此前**只存在于会话与 automation 记忆里**：

- 判据（「文件数 + 符号链接数 == zip 条目数」「失效链接 == 0」）写在提示词里，靠模型每次照读；
- 坑（目标盘校验假失败、并行 fork 失败、`tar` 不认 `C:/`、`symlink error` 良性与否）写在记忆文件的 Notes 里；
- 换一个执行者（人或 agent）就得分不清「无新增」与「API 失败」。

⇒ 建项的目标不是"再写一份脚本"，而是把**判据、坑、流程**三样东西变成**可复核的仓**：
判据落到唯一实现、坑落成台账、流程落成 runbook + 可粘贴提示词。

## 4. 建项过程本身抓到的缺陷（值得记）

首次跑 `verify_tag.sh` 直接判 `tar.gz 完整性校验不通过`，而同一文件手工用 `/tmp` 校验是好的。
根因：**Windows 上 `TMPDIR` 本身就是盘符形式**（`C:\Users\…\Temp`），
`${TMPDIR:-/tmp}` 的语义是「**未设置**才退 `/tmp`」⇒ 变量已设置，永远退不到 `/tmp`，
`C:\…` 喂给 `tar` 立刻复现「`Cannot connect to C: resolve failed`」。

**讽刺点**：LESSONS 第 1 条纪律是「在临时目录副本上校验」，而这里**临时目录本身不可用** ——
纪律执行了、判据却假失败。若不先做负向自测，这次会被当成「归档坏了」而白重下 45 MB。

处置：新增 `scripts/lib.sh` 的 `tmp_root()`（有 `cygpath` 转 `/c/...`，否则退 `/tmp`），
四个脚本只认这一个入口；台账补第 10 条。**教训：默认值写法要区分「未设置」与「设成了不可用的值」。**

## 补记 2 · 2026-11-02 20:05（用户定调：取消每周定时，改为人工触发）

用户原话：「dsh-release-archiver 应当从每周检测改为手动触发，每次主动运行都会走一遍流水线自动化流程；

### 判断

这不是「加个开关」，而是**把项目的运行前提换掉**：原设计有两个外部依赖 ——
① 平台调度负责「到点开始」；② AI 负责「看输出、决定下一步、判断算不算成功」。
独立成仓后两者都不在场，所以**必须把第 ② 项整个下沉进脚本**，否则人拿到输出仍然不会判断。

### 改造（仓内提交 `cf3ab4c`，tag `v1.1.0`）

| 新增/改动 | 作用 |
|---|---|
| `scripts/run.sh` | 一键入口，固定五步：检测 → 下载 → 校验 → 解压 → 复核 → 汇总；写 `logs/run-<时间>.log` |
| `run.cmd` | Windows 双击入口（ASCII / CRLF / 结束暂停），**不用开终端、不用记命令** |

### 补记 2.1 · 当晚追加：负向用例抓到真 bug（tag `v1.1.1`）

拿「不存在的 tag」跑失败路径时，暴露 `scripts/dl_one.sh` **仍用 `${TMPDIR:-/tmp}`**：本机 `TMPDIR` 是
`C:\Users\...\Temp`，`mkdir -p` 与 `curl -o` 落到 `C:\...\Temp/_ghd/...` 直接
`No such file or directory`。**这意味着 Windows 上真正有新 tag 时，下载必然失败**，而日志看起来只像网络问题。

- 修复：`DLDIR` 与三处「临时副本校验」统一走 `lib.sh::tmp_root()`；curl 失败分支不再对不存在的文件跑 `wc`；
- 仓内提交 `d55fd2d`，附注 tag `v1.1.1`（对象 `8421752`），已推送；匿名核对：浅克隆 16 文件、`DLDIR="$TS/_ghd"` 生效、raw 哈希一致；
- 台账第 10 条补记：**复制来的脚本最容易漏统一**，批量改路径解析必须 `grep -rn 'TMPDIR\|/tmp' scripts/` 全量搜。

> 这条 bug 是「负向用例」抓出来的，不是「跑通一次」抓出来的 —— 与 18.2 的结论互为印证。
