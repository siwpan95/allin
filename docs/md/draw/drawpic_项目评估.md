## 一、项目是什么

一个 **故障艺术 + 网络美学图像/视频生成器**，Python 实现：
- **21 个生成器**：基础 glitch（数学条纹、晶体破碎、图块错位、扫描线、像素排序、VHS 噪点、融化、切割毁脸…）+ 网络美学拓展（后室 / 阈限空间 / 梦核 / 中式梦核 / 池核 / 怪核 / 食核 / 纯画脸）。
- **双形态输出**：同一套算法既能出静态 PNG，也能用时序参数 `t` + 固定种子 `seed` 升级成动态 MP4。
- **三种入口**：`main.py`（tkinter GUI，一体化界面）、`video.py`（CLI 视频入口）、`views/console_view.py`（控制台视图，目前未被入口调用）。
- **规模**：37 个 .py 文件，约 1477 行（不含缓存），已产出大量示例图/视频在 `output/`。

## 三、架构亮点（值得肯定）

1. **真正的 MVVM 分层，且职责清晰**
   - `models/`：纯算法，每个生成器是一个 `GlitchGenerator` 子类，只实现 `generate()`。
   - `viewmodels/`：编排与 I/O 编排（图片 `GeneratorViewModel` / 视频 `VideoViewModel`），通过 `on_progress` / `on_fraction` 回调对外通信。
   - `views/`：GUI 与控制台视图，只管编排与展示。
   - `core/`：与领域无关的基础能力（路径、命名、图片/视频 I/O），可独立复用。
   - 这种分层对“一人项目”来说是**超出预期**的克制与规范。

2. **同一套算法同时驱动图片与视频** —— 这是全项目最漂亮的抽象。
   - `base.py` 的契约：“返回 `(H, W, 3)`、0–255 的 numpy 数组，额外接收 `t`、`seed`”。
   - `t` 让连续参数（相位、错位量、强度）写成时间函数，画面平滑动起来；`seed` 固定随机源，保证视频中结构稳定、只让参数演化。
   - 基类还提供统一的 `_time_fx()` 时间特效层（滚动/色差脉动/扫描线漂移/亮度呼吸），即使某生成器内部没做动画，视频里也有运动感。
   - **结论**：新增一个“会动”的效果，只需写一次 `generate()`，图片和视频自动都支持。

3. **可复现 + 不覆盖历史**
   - `core/naming.py`：`{前缀}_{日期}_{8位哈希}.png|mp4`，同一秒多次生成也不冲突，历史产物不丢失。
   - `core/paths.py`：相对路径一律基于项目根解析，绝对路径原样返回，迁移安全。

4. **GUI 工程细节到位**
   - 后台线程生成 + `queue` + `root.after` 轮询回显进度，线程安全；进度条/百分比/日志实时更新。
   - 视频标签文字做**精灵缓存**（`_LABEL_SPRITES`），逐帧用 numpy alpha 混合，避免每帧 PIL 往返开销。
   - 输出目录可选 + 一键打开文件夹（`os.startfile`）。

## 五、问题清单（按优先级）

### 🔴 P0 — 阻断性
1. **`imageio` 未安装，视频功能整体失效** —— ✅ **已修复（2026-07-10）**
   - `core/video_io.py` 在模块顶层 `import imageio.v2 as imageio`，缺失会直接导致 `VideoViewModel` 导入失败。
   - 影响：`video.py` 全部功能、GUI 的“视频”模式、展示卷轴全部崩溃。
   - 修复：已新增 `requirements.txt`（`numpy / Pillow / imageio / imageio-ffmpeg`）。
   - **验证**：在隔离虚拟环境中安装后，实测渲染一段 MP4（扫描线效果，0.5s @ 8fps，160×120）成功，文件 22.7KB，读回解码为 4 帧、fps 8、尺寸 160×120，视频链路完全打通。
   - **你这边要做的**：在运行项目的 Python 里执行 `pip install -r requirements.txt`（或 `pip install imageio imageio-ffmpeg`）即可让视频模式生效。

### 🟡 P1 — 工程化缺失
2. **无依赖清单**：没有 `requirements.txt` / `pyproject.toml` / `setup.py`，别人（含未来的你）拿到项目无法一键装齐依赖，只能靠报错猜。
3. **无 `README` / 使用说明**：没有文档说明三种入口如何运行、需要什么依赖、效果清单。对于“出活快”的项目，文档是复用的最大障碍。
4. **无版本控制元数据**：目录下没有 `.git`，不利于回溯与协作（即使是个人项目，建议至少 `git init`）。

### 🟡 P2 — 代码小瑕疵
5. **`views/console_view.py` 是“孤儿”**：`main.py` 入口是 GUI，`video.py` 是视频 CLI，控制台视图没被任何入口调用，属于遗留/未接线代码。要么接进 CLI，要么删掉避免误导。
6. **根目录遗留测试脚本 `_t_gui.py`**：里面 `import main` 并直接 `app._run_videos(...)` 跑冒烟，硬编码参数，放在项目根不像正式代码。建议移到 `tests/` 或删除。
7. **`video_viewmodel.py` 在方法内多次 `import os`**：模块顶部已 import `random`/`numpy`，却没统一 import `os`，风格不一致（功能无碍）。
8. **生成器默认尺寸不统一**（800×600 / 960×640 / 900×640 / 800×800…）：静态模式各自为政，展示卷轴会强制 960×600。若想做“统一尺寸图片集”需额外处理。

### 🟢 P3 — 可选项 / 增强
9. 缺单元测试：建议在 `tests/` 放一个“全量生成器形状+值域”断言（本次评估用的脚本稍加整理即可），作为回归保护。
10. 视频编码 `quality=8`（imageio 0–10，越大越好）尚可，但若要更小体积/更快编码可做成可配置。
11. GUI 仅 Windows（`os.startfile`、中文字体路径写死 `C:/Windows/Fonts/...`），跨平台需适配——但本项目定位 Windows，可接受。
