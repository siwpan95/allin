# ADR-0013 —— 判据读数契约（语言无关）

- 状态：**accepted**（2026-11-26 拍板）
- 时点：2026-11-26 ｜ 决策人：全哥（本轮「判据读数契约」立项）+ 工程保障团（系统架构师起草）
- 相关：ADR-0011（`scanned==0` 判盲门 + 双向棘轮 —— 本契约的直接前身）、ADR-0012（registry 外判据的 §12 登记纪律）、`tools/gate/README.md` §12 / §12.1（契约的现行载体）
- 上位约束：SPEC-003 §创新三原则 1「借鉴必记账」（本文 §借鉴记账 三条逐条记「来源 / 许可证 / 借用范围 / 我们改了什么」）；`RULES.md`（`allin_governance` 包内 `_gatesuite/RULES.md`，site-packages 分发件）的退出码词汇：`0` 干净 / `1` 基线之外的新阻断 / `2` 用法错误 / `3` 环境错误
- 范围：本文只定**语义与口径**，不写代码 —— 契约表的 self 列、类 ② 五支的读数登记、agent_parity 读数行改造，均属实现面，须按 §Consequences 单独落地并记账

## Problem

一句话：**本仓 34 支判据分三类，而「凭什么相信这次真的量到了」这一个问题，目前只有第一类有统一答案。**

### P1 三类判据，三种契约状态

| 类 | 是谁 | 现有读数 | 契约状态 |
| --- | --- | --- | --- |
| ① registry 20 道（g00–g20，缺 g02） | `registry.json` 契约 + `govlib.Report` | `scanned N file(s)`（强制形态） | ✅ 契约即 registry，读数与判定同源 |
| ② registry 外 Python 判据 **5 支**（`tools/gate/README.md` §12 机器可读块登记：conflict_markers / machine_ledger / machine_trailer / blind_gates / agent_parity） | 各写各的 | 有 `scanned N file(s)`（conflict_markers / machine_ledger），有 `summary: total=… ok=… drift=…`（agent_parity） | ❌ **§12.1 契约表只收非 Python** ⇒ 这 5 支的读数形态不受任何契约表约束 |
| ③ 外部脚本 **9 支**（pwsh / node / npm / powershell，经 `scripts/run_all_gates.sh` 的 `run` 行调用） | §12.1 external-script-criteria 表（2026-11-25 增量） | `scanned` / `count:<正则>` / `none:<理由>` 三选一 | ✅ 已覆盖，本轮只升格、不重开 |

### P2 类 ② 的缺口是契约层的，不是输出层的 —— 以 agent_parity 为实证

`tools/gate/agent_parity.py` 的现状（2026-11-26 读源码核实）：

- **空集守卫是有的，而且是对的**：`routes` 为空 ⇒ `E203` 结构错、exit 2 拒判 —— 「台账空了 refuse to judge」，不冒充绿；
- **读数行也是有的**：`summary: total=17 ok=17 drift=0 warn=0` —— 机器可 grep；
- **但契约不在**：§12.1 的契约表明文「只登记非 Python 的判据」，而 registry-external-gates 块只有三列（id / 入口文件 / 为什么不在 registry），**没有读数契约列**。于是从元判据（`tools/gate/check_blind_gates.py`）的视角看：这行读数是自由方言，不在任何已登记契约里 —— **元判据读不到「它量了什么」**。

⇒ 结论不是「agent_parity 写错了」，是**契约的覆盖面有一道缝**：§12.1 把「Python 判据归 registry / 主判定管」当默认，可 registry 外的 Python 判据恰恰两边都不管 —— registry 管不着它（不在 20 道契约里），§12.1 表又不收它。缝隙里站着 5 支真实在跑、真实会红的判据。

### P3 已实证的口径（本文不发明新词汇，只引用钉死的）

- **退出码词汇**（全部门禁统一，`RULES.md`）：`0` 干净 / `1` 基线之外的新阻断 / `2` 用法错误 / `3` 环境错误。判据不许自造「非 0 即失败」；
- **`ext-env` 不判红也绝不是通过**：exit 2/3 在 §12.1 元判据汇总里记 `ext-env` —— 不判红（判据没判，修的是环境不是代码），但也绝不计入通过（没量就是没量）。分错会骗人：把 exit 3 说成「判据自己已红」，会让人去修代码，而事实是这台机器根本判不了；
- **盲门的原始形态**（2026-11-25 实测、2026-11-26 源头修好）：`tools/gate/scan_hardcoded.ps1 -Quiet` 扫 0 个文件退 0，与扫 1013 个文件零阻断退 0 在退出码上**完全同形** —— 唯一能区分的读数行恰被 `-Quiet` 吞掉。修复后三种情形互不同义：PATH 含 git ⇒ `跟踪文件 1013 个` + exit 0；无 git ⇒ exit 3（拒绝判定）；注入真死根 ⇒ exit 1（判据自己已红）。它再也落不进 `scanned 0 + 退 0 + 无 SKIP` 那个三元组。

⇒ 要补的不是新发明，是把 §12.1 已实证的三选一通则**升格为覆盖三类的语言无关契约**，并把「守卫有、契约无」的 agent_parity 形态纳入。

## Decision

一条总原则，四条语义：

> **三类判据、一套契约：成功时输出可解析读数；给不出须登记「无扫描语义」及理由；二者皆无 ⇒ 元判据判红。读数只回答「量了什么」，判定只回答「过不过」，两者不许互相冒充。**

### D1 三类判据、一套契约 —— 同一个问题，同一个答案

三类判据都得回答同一个问题——**「凭什么相信这次真的量到了」**——答案统一为三选一，没有第四种：

1. 成功时给出**可解析的读数**（`scanned N file(s)` / `"scanned": N` / `跟踪文件 N` / `summary: total=N …`，或用契约表的 `count:<正则>` 声明本判据的计数方言）；
2. 给不出的，在 §12 契约表登记 `none:<理由>` —— 理由必须说清「为什么这道判据**天然**没有扫描语义」（如纯配置检查、纯对账且无对象数可报），理由过短视为没写；
3. 二者皆无 ⇒ `check_blind_gates.py` 判红。

三类各自的接法：

| 类 | 怎么接这套契约 |
| --- | --- |
| ① registry 20 道 | `govlib.Report` 已强制规则 1 的形态，**零改造**；契约由 registry 承载 |
| ② registry 外 Python 5 支 | §12 的 registry-external-gates 块升格为带读数契约列：conflict_markers / machine_ledger 登记 `scanned`；machine_trailer / blind_gates 按 D3 办理；agent_parity 把 `summary: total=N` 登记为它的读数方言 |
| ③ 外部脚本 9 支 | §12.1 external-script-criteria 表**原样升格为 ADR 级契约**，表义不变 |

方向纪律保持 §12.1 的原话：**不是「表里有什么就判什么」，而是从 `scripts/run_all_gates.sh` 与 §12 登记块推出全部判据，再逐条查契约**。新加一个判据而不登记，当场判红 —— 否则「新加一个没读数的脚本」这件事仍然不可见，那也是死门的生成方式。

### D2 扫描单位由判据自己定义，不由元判据猜

「量了多少」的**单位**是判据的语义的一部分，只有判据自己有权定义。合法单位包括但不限于：routes 条目数（agent_parity 的 `total`）、文本文件数（conflict_markers / machine_ledger 的 `scanned`）、锚点比对次数（g16/g21 族的对账对）—— **哪个都行，但必须满足两条**：

1. **单位写进 docstring**：半年后的读者不读代码就该知道「这个 N 数的是什么」；
2. **读数行与内部计数一致**：读数里的数字与判据内部计数不符 ⇒ **判据自身缺陷**（不是数据脏），且元判据必须配**负对照**证明这种不符抓得住 —— 否则「读数行」就是一份可以随便填的表格，契约等于没定。

元判据**不许猜单位**：它只验「读数行里有一个非负整数，且该判据在契约表里有登记的读数形态」。语义正确性（这个 N 真的数对了东西）归判据自己的 `--selfcheck` 与负对照，不归元判据 —— 分层与 §12.1「本判据不改判据本体，只负责在它没有读数时把红点亮」一致。

### D3 自指处理：元判据不探针自己，`--selfcheck` 承担覆盖

`check_blind_gates.py` 判「别的判据量了没有」；它自己量自己就是递归 —— 探针的探针的探针，没有底。约定三条：

1. **元判据不进被探针集合**：它在契约表里显式标 `self`（新增一列或一个值，实现面定），表示「本条目的读数契约由自己的 `--selfcheck` 承担，不接受外部探针」；
2. **覆盖由 `--selfcheck` 给**：87 例负对照（假盲门被抓、假正常被放、假 SKIP 不算红、无 scanned 字段记不可判定）—— 自证有效条款（`SELFCHECK {"caught":N,"clean":M,"misreports":K}`，`N≥1`、`M≥1`、`K==0`）沿用 `g00-meta` 既有口径，不另造；
3. **`self` 档是 not-a-pass 单列，不折叠**：汇总里它单独一行、逐条打印理由 —— 折叠进绿是免检章（「登记」变成新的免检章，正是 §12.1 已明令禁止的）；折叠进红是误报（元判据在跑、跑得对，只是结构上不归探针管）。

### D4 读数与判定分离 —— `scanned 0` + exit 0 仍红；`ext-env` 不判红也绝不是通过

- **盲门三元组不变**：`scanned 0` + `exit 0` + 无 SKIP ⇒ 判红。`scanned 0` 是「量过」的证据；它是 **0** 的时刻，它证明的是「没量到」，不是「量了且干净」（ADR-0011 §D3 的直接沿用）；
- **exit 2/3 永不通过**：`ext-env` 是「判定不成立」，既不是红（判据没机会判）也不是绿（没量就是没量）。空集守卫（如 agent_parity 的 E203）把「拒判」做得越诚实，这条就越重要——**诚实拒判的收益，全在下游不把拒判读成通过**；
- **读数不背判定**：`scanned N` 只证明「量过 N 个对象」；过不过由 findings / exit code 与基线棘轮决定。反向同理：exit 0 不证明量过 —— 这正是 P3 盲门形态的教训。

## 借鉴记账（SPEC-003 §创新三原则 1）

### 1. SARIF —— 借两条原则，不借格式

- **来源**：OASIS Static Analysis Results Interchange Format (SARIF) 2.1.0，规范 <https://docs.oasis-open.org/sarif/sarif/v2.1.0/sarif-v2.1.0.html>
- **许可证**：OASIS 规范文本按 OASIS IPR 模式公开可引用。**本文只引其设计原则与文档口径，不复制规范正文** ⇒ 不构成衍生作品，不占 `docs/事实源/来源与许可表.md` 的行（同 ADR-0012 §借鉴记账的许可表处理）。
- **借用范围**：两条原则，**不是格式**：
  1. **工具输出即契约** —— 分析结果必须以机器可解析的结构给出（SARIF 用 JSON `runs/results`；我们用一行方言 `scanned N … blocking M`，因为元判据的消费形态是 grep stdout，不上 JSON）；
  2. **「SARIF 本身不做门禁」** —— 规范明示格式只承载发现（results），判定在另一层策略（`--configuration`）。⇒ 我们的 `scanned N` 是「量过」的证据，**不承担「是否通过」**；`ext-env`（exit 2/3）正是这一原则的退出码形态：给不出读数时，退出码也不许冒充判定。
- **我们改了什么**：把「整份 JSON 报告」降为「一行可 grep 的读数」。这是**成本换覆盖面**的一次刻意贬值：一行方言让 9 支外部脚本 + 5 支 Python 判据全部纳入契约（各自改一行输出 / 登记一行声明），而上 SARIF 只覆盖接了 SARIF 平台的那一层 —— 9 支 pwsh/node 脚本改造不动，等于契约只管得住最不缺契约的那层，最缺的那层继续裸奔。**覆盖面优先于表达力**，是本契约与 SARIF 的根本分歧点，也是 §Alternatives 1 被否的理由。

### 2. grep / ripgrep / pytest 的退出码惯例 —— 引用既往记账

- **来源 / 许可证 / 借用范围**：上一轮（ADR-0011 借鉴记账）已记账，本文**引用不重开**；
- **引用的结论**：**未命中 / 无输入永远有自己的非零码**（grep 未命中 = 1、出错 = 2；ripgrep 无匹配 = 1；pytest 无用例被收集 = exit 5）。三者的共同点：**「没东西可查」从不冒充「查过且干净」**；
- **本文新增的对应**：本契约的 exit 3（环境错）与 pytest 的 exit 5（没有收集到用例）同构 —— 都是「拒绝判定」而非「判定通过」。`ext-env` 不判红也绝不是通过（§D4），是把这条惯例从测试框架扩展到判据词汇表。

### 3. 盲门三元组（引用 ADR-0011，不重开）

`scanned 0 + exit 0 + 无 SKIP ⇒ 判红` 的发明权在 ADR-0011 §D3；§12.1（2026-11-25）把它从 registry 20 道推广到外部脚本并实证；本文把它**推广到全部三类**并给出语言无关的表述。三段沿革一条线：先有判据（0011），后有方言表（§12.1），今天有契约（本文）。

## Alternatives considered

1. **全量上 SARIF / JSON** —— **否决，杀鸡用牛刀且改造不动大头。**
   元判据 `check_blind_gates.py` 的消费形态是 grep 判据 stdout 的一行 —— 给它造一个 JSON Schema + 逐判据接 SARIF 生产者，是把两行 print 的工作量做成一季度的工程。更硬的一条：**9 支外部脚本改造不动**（pwsh / node 各写各的，没有共享 Report 库），上了 SARIF 它们照样裸奔 —— 契约只覆盖了最不缺契约的 Python 层。**一个让缺口原样存活的升级方案，价值是负的**：它给人「已经有契约了」的错觉，而缝隙里的 14 支（5 + 9）一支没进。见 §借鉴记账 1「我们改了什么」。

2. **只靠 exit code，不要求读数** —— **否决，`0` 无法区分「量了 1013 个」与「量了 0 个」。**
   这是上轮 `scan_hardcoded` 盲门的**原始形态**：扫 0 个文件退 0、扫 1013 个退 0，退出码完全同形 —— 区分两者的唯一信息（读数行）恰是「只靠退出码」方案最先扔掉的。退出码是**一比特**的信息通道（结合词汇表最多两比特），而「量到了什么」至少需要 `log2(1013)` 比特。**用一比特的通道承载一封千比特的信，丢包是必然**，不是风险。

3. **把 registry 外判据全部升进 registry 20 道** —— **否决，一个为防漂移引入的漂移源是净负收益。**
   「20 道」这个计数被 `tools/gate/README.md`、ADR、`architecture/system-architecture.svg` 与 SPEC-204 多处引用，`tools/gate/check_arch_assets.py` 的 B 项把 SVG 门禁数钉在真身上 —— 升格 5 支 ⇒ 20 变 25 ⇒ SVG / 规范 / 契约三处数字联动改，且今后**每加一支 registry 外判据都要再滚一轮**。ADR-0012 §D2.7 已就同一取舍拍板（「两条路，选后者」），ADR-0010 的 g21 也是同款：**归属靠 §12 显式列出，不靠编号**。本文不重开裁定，只补一条技术理由：三类判据的契约统一**不需要**编号统一 —— 契约挂在 §12 表上，编号挂在 registry 上，两者正交。

## Consequences

### 变容易

- **「凭什么相信这次真的量到了」第一次有了覆盖三类的一句话答案** —— 新判据的作者不再需要逐案发明「怎么证明我量了」；
- **§12.1 从「一节好散文」升格为「一条 ADR 级契约」**：散文可以被悄悄改松，ADR 有状态闭集与索引管着；
- **agent_parity 的读数从「行在纸上」变成「契约在表上」** —— 元判据第一次能对类 ② 说「它量了什么」。

### 变困难 / 误伤面（逐条给退出路径）

| 语义 | 误伤面 | 退出路径 |
| --- | --- | --- |
| §D1 三选一 | 真没有扫描语义的判据被逼着编一个数 | `none:<理由>` 通道永远开着；理由过短会被元判据挑出来，逼人把「为什么天然无量」说清 |
| §D2 单位须写 docstring | 改判据忘了同步单位描述 ⇒ 读数与文档漂 | 属判据自身缺陷，元判据负对照抓数字不符；描述漂移归 `--selfcheck` 与评审 |
| §D3 `self` 单列 | 汇总行多一档，读起来多扫一眼 | 这是**诚实税**：not-a-pass 不折叠的代价就是可见性；折叠回去等于重新制造免检章 |
| §D4 `ext-env` 不算通过 | 干净检出里环境缺依赖 ⇒ 大量 `ext-env`，批跑「绿得很空」 | 逐条打印环境错原因（修环境方向明确）；CI 侧以「ext-env 计数」为健康度旁证，不作为阻断 |

### 今后新增判据（无论哪一类）的接入步骤

1. **进 §12 契约表**（registry 外的进 registry-external-gates 或 external-script-criteria 机器可读块；registry 内的进 `registry.json` + `govlib.Report`）—— 唯一登记点，不登记 ⇒ 元判据当场判红；
2. **定义扫描单位**：写进判据 docstring（§D2），单位合法（条目 / 文件 / 对账对 / 比对次数均可）；
3. **成功时输出读数行**（§D1 之 1）；天然无扫描语义的，登记 `none:<理由>`（§D1 之 2）；
4. **探针可选**：登记 `yes` 每批真跑，或 `no:<理由>`（成本 / 环境）—— `no:` 记 `declared_unprobed`，**声明不是实测，不算通过**（§12.1 原话，升格为契约）。

### 实现面（本文不做，落地须单独记账）

- §12 registry-external-gates 块增读数契约列；类 ② 五支逐条登记；
- 契约表增加 `self` 标记（D3）；元判据汇总增加 self 单列档；
- `agent_parity` 读数行保持 `summary: total=N …` 现状即可登记（无需改造），是否换 `scanned` 方言由实现轮定。

### 本 ADR 自身的可判性（写完即验）

```bash
python tools/gate/check_arch_assets.py
node scripts/gates.mjs --only g19-docs-refs
```
