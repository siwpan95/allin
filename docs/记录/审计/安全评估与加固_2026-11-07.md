### 1.2 方法

1. **源码通读**：加密层（`crypto/gcm.js`、`envelope.js`、`keystore.js`）、认证/会话/CSRF/限流、资源投递、代理 BFF、门户围栏、注册表加载、门禁实现、CI 工作流。
2. **危险原语定位**：grep `shell=True` / `exec` / `eval` / `yaml.load` / `child_process` / `innerHTML` / 弱哈希 / 明文口令，再逐处回读上下文确认**可达性**与**是否已有防御**——只报真实风险，不做模式匹配式刷分。
3. **凭据与历史**：`git ls-files`、`git grep --cached`、git 对象库与历史增删文件复查；核对 `.gitignore` 实际覆盖。
4. **依赖与 CI**：npm 依赖树审计、Python 依赖下限检查、action 钉版 / permissions / 触发事件 / 超时检查。
5. **实跑验证**：门禁自检、单测、加密自检、新增工具端到端。

### 1.3 逐面结论（无发现项也记，避免"没报=没查"）

- **加密实现**：HKDF-SHA256 派生每条数据独立 DEK → AES-256-GCM(96bit 随机 nonce) → AAD 绑定业务主键 → 明文 SHA-256 复核；取不到密钥 fail loud；密钥文件 0600；`backup-key` 拒绝明文备份、拒绝写进仓内。**未发现缺陷**。
- **认证/会话**：scrypt(N=32768) + 随机盐 + 参数随行、256bit 随机会话 ID、`timingSafeEqual`、用户不存在也跑等价 scrypt、httpOnly + SameSite=Lax；CSRF 令牌恒定时间比较；登录/注册/联系表单双维度限流。**未发现缺陷**。
- **注入/越权**：SQL 全为参数化 `prepare`；`/media/:key` 按 scope 授权且非位图强制下载（阻断 SVG 存储型 XSS）；`safeNext` 用 WHATWG URL 以 origin 相等为唯一放行条件；portal 代理的 id/action 白名单正则。**未发现缺陷**。
- **门户围栏**：Host 正则 + 回环 socket 检查 + `Sec-Fetch-Site`/`Origin` 状态变更围栏，GET 读取面同样受 Host 围栏覆盖。**未发现缺陷**。
- **CI 基线**：第三方 action 全部 SHA 钉版、`permissions: contents: read`、无 `pull_request_target`、无脚本插值注入、无 `curl | sh`，两侧调同一脚本。**仅缺超时**，已补。

## 2. 发现与定级

### 🔴 F-01 [High] 内联豁免注解把凭据门禁的豁免权交给了被扫描内容

- **位置**：`scripts/scan-secrets.sh` 原 74–76 行；`tools/gate/governance/gates/g03_credentials.py` 原 360–362 行
- **类型**：CWE-807（依赖不可信输入做安全判定）/ CWE-693（保护机制失效）
- **置信度**：High（两处代码路径均确认可达，无第二道独立防线覆盖外部 PR）
- **影响**：仓内为合成夹具设计了行内 `allow` 注解。**原实现是「任何文件里带注解的那一行整行跳过扫描」**，而注解本身正是被扫描内容的一部分。外部贡献者（不装 pre-commit）只要在新增行末尾追加一个二十来字符的注释，就能让 CI 增量扫描与 g03 全树门禁同时放行；真实 token 因此可进入公开的 Gitee/GitHub 仓且长期不被发现。这是本次评估中唯一「一次提交即可击穿防线」的问题。
- **修复**：见 3.1、3.2。豁免清单外移为**受评审的仓库配置**，不再由提交内容声明。

### 🟠 F-02 [Medium] 增量扫描「只扫新增行」的自述与实现不符

- **位置**：`scripts/scan-secrets.sh` 原 59–84 行
- **类型**：CWE-693 / 判据与实现漂移
- **置信度**：High
- **影响**：脚本把整个临时目录交给 gitleaks，而目录里同时有 `diff.raw`（完整 diff，含删除行）与 `added-lines.txt`。文件头注释明确写「删除行与上下文行都不扫」，实际删除行仍被扫描 —— 一个**删除硬编码密钥**的 PR 会被自己删掉的密钥判红，门禁给出与事实相反的结论。同时该实现也让 F-01 的实际效果依赖 gitleaks 对第二个文件的偶然行为，判定不可推理。
- **修复**：见 3.1。payload 子目录里只放过滤后的新增行；并加 5 条不变量自检。

### 🟠 F-03 [High] 备份目录同时含密文库与主密钥，且种子口令明文落盘

- **位置**：`website/data/allin-wdata-bak-442/`（含 `site.db*` 与 `keys/*.key`）；`website/data/seed-accounts.json`（`admin@allin.local` / `demo@allin.local` 明文口令）
- **类型**：CWE-522（凭据保护不足）/ CWE-312（明文存储敏感信息）
- **置信度**：High（已实测目录内容与账本明文；账本口令与库内 scrypt 哈希一致）
- **影响**：本站「全库密文」的安全前提是**密钥不与数据库同处一份可复制的快照**。整目录复制备份会同时带走两者，拿到该目录即可解开全部内容、邮箱与附件，加密等于没做。若这份快照曾外发/上云，应按全库泄露处置。明文种子口令是 0600 且 gitignore 的既有设计，本机单用户可接受，但共享主机或外发过 `data/` 时即成真实凭据泄露。
- **边界**：这些文件**未被 git 跟踪**，不构成公开仓泄露；属本机运行时数据面。
- **修复**：见 3.3、3.4、3.5。**脚本只读不删任何文件**，处置留待人工确认。

### 🟡 F-04 [Low] 固定命令仍经 shell 解释

- **位置**：`kernel/services/platform_service.py:31`
- **类型**：CWE-78（潜在面，当前参数全为常量）
- **置信度**：High（无外部输入，**不构成现时漏洞**，属纵深防御收敛）
- **影响**：`subprocess.run(['npm', ...], shell=True)` 无注入面，但多一层 shell 元字符解释与 `.cmd` 垫片隐式行为。
- **修复**：见 3.6。

### 🟡 F-05 [Low] CI 四个 job 均无 `timeout-minutes`

- **位置**：`.github/workflows/gates.yml` 四个 job
- **类型**：CWE-400（资源消耗无上界）
- **影响**：卡死步骤按平台默认上限（数小时）占用 runner；公开仓的外部 PR 可反复触发。
- **修复**：见 3.7。

### 🔵 F-06 [设计约束 / 需评审保护] 注册表条目以 shell 执行

- **位置**：`platform/packages/core/src/launch.js:193,258`、`platform/apps/portal/src/index.js:212–236`
- **说明**：`spawn(entry.launch.command, { shell: true })` 是平台既定能力（启动 100+ 本地项目），不是缺陷；但**改一条 registry YAML 等价于改一条可执行命令**。现有防护是 Host 围栏 + 回环 + 状态变更来源围栏 + 清单 `_valid` 校验，均为网络层，不覆盖「本地写入注册表」这一路径。
- **修复**：见 3.8（CODEOWNERS 评审保护），不改运行时行为，避免破坏既有能力。

### 🔵 F-07 [后续建议 / 本轮不改] 供应链残留项

- Python 依赖为宽松下限（`PyYAML>=6.0`、`pytest>=8.0`、`build>=1.2` 等），由 Dependabot 盯下限；`vendor/` 的 cordis 内联副本缺独立锁文件；PyPI 发布尚无 PEP 740 来源证明。
- **未改原因**：这些是发布流程与跨机可复现性的取舍，改动面大且需要联网核验，**不在本轮「代码可直接落地」范围内**。npm 两棵依赖树经 `npm audit` 与 OSV 复核为 0 漏洞，PyPI 包零运行时依赖，action 全 SHA 钉版 —— 供应链主体是健康的。

## 3. 已落地修复（按优先级）

### 3.1 P0 · 增量扫描器：路径感知过滤 + 越权即拒绝（F-01 + F-02）

`scripts/scan-secrets.sh` 重写过滤段：

- 新增共享白名单 `scripts/secret-scan-allowlist.txt`（10 个仓库自有夹具文件，UTF-8 路径，`#` 注释）。
- `filter_added_lines()` 用 awk 跟踪 `+++ b/<path>` 归属：**只有**白名单内的夹具文件（及 `*.example` / `*.sample` / `*.template` / `*.dist`）才剔除带注解的行。
- 注解出现在其它任何文件 → 该行**保留**给 gitleaks，并写入 `annotation-abuse.txt`；无论 gitleaks 结论如何，构建一律 `exit 2`（fail closed）。
- `payload/` 子目录只放过滤后的新增行，`diff.raw` 与越权记录放外层，不再进入扫描面；`git diff` 加 `core.quotepath=false` 保证中文路径可比。
- 新增 `--selftest`（不依赖 gitleaks/网络/git 历史），5 条不变量：越权注解不抹行 / 越权注解被记录 / 删除行不进扫描面 / 白名单夹具仍豁免 / diff 文件头不进扫描面。

### 3.2 P0 · 全树门禁：注解豁免改为配置授权（F-01）

`tools/gate/governance/gates/g03_credentials.py`：

- 新增 `annotation_allowlist()`，从**同一份** `scripts/secret-scan-allowlist.txt` 读取；文件缺失/不可读时返回空集合（fail closed，绝不退回旧的全局豁免）。
- `scan()` 增加 `annotation_paths` 参数，仅供门禁自身 selfcheck 沙箱声明夹具路径。
- 未登记文件里的注解不再 `continue`，照常走形状判定 —— 真实密钥即使挂了注解也必须报红。
- selfcheck 新增 2 组最小复现用例：未登记路径的注解**拦得住**真实 token；显式登记的夹具路径**仍保持安静**。
