## 2. 修正后的四类映射

### A 类：按既有治理文档推进（不新增决定）
1. **radio/video 簇**：M3（station-base/web-base 抽入 packages/core）→ M4（test/check.mjs 门禁推广到 apps/video）→ 再按 HARNESS_NOTES P4（schema 库）→ P5（invariants）→ P6/P7（Entry 行式配置 + patch 分层，与引擎补丁纪律汇合）。
2. **crawl_hub 纪律升级（保持聚合原则不动）**：
   - crawlers.json 增加字段校验 + 启动审计（工具缺入口/path 失效时 fail-loud，对齐 HARNESS P1）；
   - 底部日志升级为**任务事件日志**（JSONL：启动/退出/退出码/时长，与 WorldLog 同构），agent 审计可用；
   - 工具仍是子进程，**不进插件进程**。

### B 类：alloy 三件事模板（项目内部，不跨项目 import）
1. **audio_pipeline**（流水线编排器）：阶段=preset 插件（拆歌/导出/混音/重分离），任务日志断点续跑——收益最直接。
2. 管道/批量类：audio_separator 批量任务、ai\video_generator、ai\novel、crawler 三件——先任务日志（断点续跑+审计），后按需 preset。
3. station / musickit remix：仅在继续开发时顺手接入任务日志；不动架构。

### C 类：仓库级规范
1. **repocheck 规则库扩展**（工具已存在）：入口文件存在、零字节 `__init__.py` 非垃圾、资产/代码分离、README 约定、bat 旧路径检查（本次实测发现的 `D:\...` 硬编码就是一例）。
2. **每项目 SKILL.md 批量化**（活跃项目：audio_pipeline、crawl_hub、musickit、station、六件套等）。
3. 统一任务日志格式（JSONL，与 WorldLog/dump-log 同构）。

### D 类：不动
- games 单文件玩具；纯资产目录（music 660GB、crawler 资产）；外部源码转储；archive/_migration/_backup/trash（helminth 按 crawl_hub README 建议移隔离区——归入 P0 资产治理一并出清单）。
