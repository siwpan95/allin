# musickit 架构化立项报告（2026-08-25）

> 用户方向修正：musickit 完整流程 = **提示词 → 混音 → 电台**；此前把 radio 单独拉出讨论是错的。radio 已完成架构化（Node+Cordis monorepo），musickit 本体尚未架构化——本报告为架构化立项。铁律 1：已读 README/INTEGRATION/RADIO_MERGE/FIX_PLAN 等全部治理文档。

| 段 | 组件 | 现状 | 架构成熟度 |
|---|---|---|---|

| ② 混音 | remix/：run_remix + **24 位混音师签名注册表（burbidge_album/mixer_styles.py）** + pipelog 任务日志（WorldLog 同构 ✅）+ mixer_stream（8010 已登记 ✅）+ 双管线（随机×固定，共享 mixer_styles） | 最成熟段 | 🟨 半插件化（混音师注册表已是"24 插件"形态，缺正式插件协议/版本） |

## 二、架构化方案（照 radio 成功路径 = 装配不融合 + 三件事）

1. **三段收敛为「musickit 管线三插件」**：prompt / remix / broadcast，每段独立目录、独立版本、独立更新（子进程隔离——musickit/radio 的渲染器子进程模式已是现成样板）；
2. **混音师注册表 → 正式插件协议**（架构化起点）：mixer_styles.py 的 24 混音师 = 24 个插件，每个加 manifest（name/version/chain 声明），注册即回滚/补丁即差异照搬；
3. **任务日志全线同构**：pipelog（已有）→ 提示词段与电台段同款 JSONL，全链可审计（提示词生成→混音渲染→开播 一条流水线一份日志）；
4. **端口纪律**：8000（电台）/8010（mixer 流）已登记 ✅；新服务先查 ports.yaml；
5. **编排贯通**：提示词→混音→电台 一键链 = 编排器（候选落点：audio_pipeline 已是指挥式编排器，或 musickit 内建 orchestrator，拍板）；
6. **电台双轨定案**（拍板）：python musickit/radio = 随机渲染专属电台；Node 电台 = 通用转播电台——分工并存，不合并（M5 教训）。

1. **电台**：python musickit/radio **逐步退役**——随机渲染音源（musickit_source + 渲染器）迁为 Node 电台插件（musickit 音源插件），python 版归档；Node 电台为唯一电台运行时。
