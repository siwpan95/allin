## 4. P0 详情

### F-01 sdist 不可安装（已发布，SEV2）

- **为什么是 P0**：不是「体验差」，是 `pip install` 直接 exit 1。对没有 wheel 的平台/离线镜像/`--no-binary` 用户，这个包等于没有。
- **根因**：`pyproject.toml` 用跨目录 `package-dir`（`../../tools/repocheck` 等 6 条）。该映射只对 wheel 生效；setuptools 的 sdist 不收项目根之外的文件 ⇒ 包里没树、路径仍指向仓外。
- **为什么没被拦住**：`twine check` 判元数据（坏 sdist 也 PASSED）；干净 venv 验的是 wheel；pytest 当时另有红灯（F-02）却未被当作阻断。**三条检查各看一半，缺的那一半正是 sdist。**
- **修复**：见 §5 F-04；版本 1.0.1。事故全过程见 [`记录/事故/pypi-sdist不可安装_2026-11-24.md`](../事故/pypi-sdist不可安装_2026-11-24.md)。

### F-02 测试红灯下发布

- 原判据 `assert __version__.startswith("0.0.0a")` 护的是「发版前的占位命名」，1.0.0 一落定就自证为红。
- 危害不在这一条测试本身，而在**它让「全绿」这个信号失去意义**：红灯在场时，任何后续红灯都可以被解释成「已知问题」。
- 修复后判据回到原意：两处版本号不许对不上（`pyproject` 是唯一来源）。

## 5. P1 详情

### F-03 platform 用例钉死易变数据

- `idle 族应至少 5 个` / `arcade.gameplay` 依赖 `arcade`、`idle` 两条注册条目；2026-11-23「66 个冻结仓移入备份区」把它们移除了，用例没跟着改。

  凡是声明了 `gameplay` 的条目，API 必须原样回填且在受控枚举内；同族 `order` 有则必须 1..n 连续。
  保护面从「2 个写死 id」扩大到「全部声明条目」。

### F-04 发版链路缺可执行判据

- 现状：发版步骤写在 SOP 与人的记忆里；`twine check` + 装 wheel 给出「已验证」的错觉。
- 补两道：
  1. `scripts/release_preflight.py`：版本四处一致 / dist 只含当前版本 / 发布物齐备 / sdist 自包含 / sdist 已物化 / twine check /（`--install`）sdist 与 wheel 各装一次并跑五个子命令。退出码 0/1/3，`skip` 单独计数且**不算通过**。
  2. `tests/test_dist_artifacts.py`：`dist/` 里有当前版本 sdist 就逐棵核对映射树 + 核对 `package-dir` 已物化；干净检出自动 skip 并写明理由。
- **判据能判红**的证据（负对照）：人为摘掉 1.0.1 sdist 的 `_repocheck/` →
  `[FAIL] sdist 自包含  缺映射树：allin_governance._repocheck` + `RESULT: BLOCKED`，
  而同一次 `twine check` 仍 `[ok]` —— 精确复现了 1.0.0 的盲区。
