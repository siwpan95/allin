# 治理系统上手指南

> **这份文档写给谁**：想把「这套治理模式」搬到自己工作区的人 —— 无论是接手本工作区的新人
> （人或 AI 协作者），还是看到公开仓后想复刻这套做法的外部开发者。
>
> **一句话**：本仓（`allin`）是一套**为「一个人 + 多个 AI 协作者 + 上百个仓库」设计的、
> 可执行、可审计、事故驱动**的工程治理模式。它的核心不是文档写得多漂亮，而是
> **每条规矩都有事故来源、每个断言都有可复跑的证据、每次改动都留下可追溯的账**。
>
> **它不是什么**：它不是「某个游戏引擎」，也不是「一堆项目的集合」。
> 那些项目各自独立成仓、公开 + MIT；**本仓是管它们的那个中枢**。
> 换句话说：**repos 是被治理的对象，allin 是治理本身。**
>
> 📌 本仓文档契约：所有 `docs/` 下的文档都必须在 [`docs/INDEX.md`](INDEX.md) 登记。
> 本文件已登记为 `HUB-06`；本文的策略背景见 [`docs/记录/审计/allin自身做大做强方向修正_2026-10-31.md`](记录/审计/allin自身做大做强方向修正_2026-10-31.md)（REC-AU-21）。

## 第 0 章 · 10 分钟上手

> **目标**：在一台**没装过任何东西**的机器上，10 分钟内让本仓的门禁全绿。
> 这一章是全文的**唯一硬承诺**，其余章节都是它的展开。

### 0.1 三条命令

```bash
# ① 克隆（公开仓，匿名可 clone）
git clone https://gitee.com/siwpan/allin.git
cd allin

# ② 一条命令建环境：建 .venv + 装依赖 + 重建文档别名 + 打印下一步
bash scripts/bootstrap.sh

# ③ 跑全部门禁（期望：末尾「全部门禁通过。」、退出码 0）
bash scripts/run_all_gates.sh
```

**Windows 用户注意**：第 ② 步需要 **Git Bash**（或 WSL）—— `.sh` 脚本在 `cmd` 里跑不了。
如果你更习惯 PowerShell，等价路径是（**前提：这台机器已装 PowerShell 7 = `pwsh`**）：

```powershell
# 手动版 bootstrap（PowerShell 7 = pwsh）
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
pwsh -File tools/gate/make_doc_aliases.ps1
```

> 🔒 **2026-11-07 本机实测**：本机**没有 PowerShell 7**（`pwsh` 不在 PATH，系统里也查不到安装）。
> `bootstrap.sh` 因此打印「未找到 pwsh，跳过别名重建」，但**仍以 exit 0 结束** —— 别名是
> junction、不入库，本机此前已建过就还能用。**干净克隆的第一台机器必须装 PowerShell 7**
> 才能把别名建出来（否则 `g15` 的 D6 会红）。不要用 PowerShell 5.1 硬跑代替，见 FAQ 第 16/17 条。

### 0.2 三种终端下的命令差异

| 目的 | 🪟 cmd | 🐧 Git Bash / WSL | 💙 PowerShell 7 |
| --- | --- | --- | --- |
| 治理 CLI | `allin.bat tools skills` | `.venv/bin/python allin_cli.py tools skills` | `.\.venv\Scripts\python.exe allin_cli.py tools skills` |
| 跑全部门禁 | （用 Git Bash 跑 `scripts/run_all_gates.sh`） | `bash scripts/run_all_gates.sh` | `bash scripts/run_all_gates.sh`（仍需 bash） |
| 单道门禁 | `npm run check:governance` | 同左 | 同左 |
| 文档索引契约 | `python tools/gate/docs_index.py` | 同左 | 同左 |

> ⚠ **中文乱码**：`cmd`（cp936）下 Python 会写 GBK 字节导致中文乱码。
> 用 `allin.bat`（已强制 UTF-8）、或 `pwsh` 7、或设 `PYTHONIOENCODING=utf-8`。详见 FAQ 第 1 条。

### 0.3 怎么判断「装对了」

跑完第 ③ 步，你应当看到（**逐字对照**，这是本仓的验收基线）：

```
governance: 20/20 gate(s) clean
...
----------------------------------------
全部门禁通过。
```

且**退出码为 0**。如果看到的是 19/20 或任何一条红的，先看 FAQ 第 2 条
（最常见原因是解释器不一致 —— `PATH` 上的 python 没有 PyYAML）。

> **这一章是 2026-10-31 新增的**：在此之前本仓**没有** bootstrap 脚本，
> 新人只能从报错信息反推该装什么（`pyyaml` / `watchdog` 是从 `_cordis_locate.py`
> 的报错提示里猜出来的）。补齐这条链路的实测记录见
> [REC-AU-21](记录/审计/allin自身做大做强方向修正_2026-10-31.md) §七。

## 第 1 章 · 这是什么

### 1.1 五根支柱

```
                     ┌─────────────────────────────────────────────┐
                     │  ① 单一事实源（Single Source of Truth）      │
                     │  README / MEMORY / 会话交接 / 协作约定       │
                     └───────────────┬─────────────────────────────┘
                                     │  互相引用，不互相复制
   ┌─────────────────────────────────┼─────────────────────────────────┐
   │                                 │                                 │
┌──▼───────────────┐   ┌─────────────▼──────────────┐   ┌──────────────▼─────────┐
│ ② 铁律体系        │   │ ③ 门禁化（可执行）          │   │ ④ 记账化（可审计）      │
│ 每条都有事故来源   │   │ 死根门禁 / AST 检查 / 仓内   │   │ commit + MEMORY + 交接  │
│ 违反即"停手上报"  │   │ verify 门禁族 / 基线棘轮     │   │ + 计划文档 + 审计片段    │
└──────────────────┘   └─────────────────────┬──────┘   └────────────────────────┘
                                             │
                     ┌───────────────────────▼───────────────────────┐
                     │ ⑤ 透明化与复用（Open by default）                          │
                     │ 文档枢纽入库公开仓 → 他处可读、可复跑、可续做               │
                     └───────────────────────────────────────────────────────┘
```

（这张图出自 [`SPEC-105`](规范/SPEC-105-治理模式建设指南.md) §1，是本仓的原始设计说明。）

### 1.2 它解决什么真问题

一个人管上百个仓库，不是「不会写代码」，而是这七件事会塌方 —— **本工作区全都真实发生过**：

| 塌方 | 真实表现 |
| --- | --- |
| **事实源分裂** | 同一件事在 README、文档、聊天记录、脑子里各有一版；新人（或新的 AI 会话）拿到的是旧版 |
| **改动不留账** | 改完只在本地，或提交信息写「更新」；三个月后没人知道为什么这么改 |
| **假绿** | 验证脚本打印 `[PASS]` 但退出码是 0；只看重定向输出不看真控制台 |
| **门禁靠自觉** | 「记得别写死路径」—— 没有可执行的门禁，等于没有约束 |
| **冗余误判** | 按同名判定「A 已并入 B，可删」→ 删掉了 B 里没有的功能面（本工作区真删错过一次） |
| **许可失控** | 第三方 GPL/CC BY-SA 资产混进 MIT 公开仓，或反过来把必须 GPL 的仓「补成 MIT」 |
| **AI 协作者放大错误** | 一次错误的口径会被 AI 高速复制到几十个仓 —— 所以治理必须**机器可校验**，不能靠记忆 |

> **一句话结论**：**给人看的规矩要变成给机器跑的门禁，给机器跑的门禁要有给人看的账。**

## 第 2 章 · 环境准备

### 2.1 运行时

| 运行时 | 最低版本 | 查自己版本 | 依据 |
| --- | --- | --- | --- |
| Python | `>=3.12`（内核） / `>=3.11`（repocheck） | `python --version` | `kernel/pyproject.toml`、`tools/repocheck/pyproject.toml` 的 `requires-python` |
| Node.js | `>=22.18` | `node --version` | 根 `package.json` 的 `engines.node` |
| Git | 近期稳定版 | `git --version` | — |

> 🔒 **建议用版本管理器**（`pyenv` / `nvm` / `mise`）锁定版本。本仓门禁对解释器敏感
> —— 见 FAQ 第 2 条，这是本仓最常见的假红来源。

**2026-11-07 实测现值**（`@DESKTOP-KQABATS` 机）：PATH 上的 `python` 为 3.13.14、
Node 22.22.2、Git 2.55；`bootstrap.sh` 的候选探测命中 `python3.12`（3.12.15），
但本次**复用已有 `.venv`**（3.13.14），`run_all_gates.sh` 也把该解释器钉给整批门禁。
`packages/allin-governance/pyproject.toml` 的 `requires-python` 为 `>=3.11`。
⇒ 三者都满足最低版本；**关键是整批用同一个解释器**，不是挑最高版本。

**为什么门禁对解释器这么敏感**：门禁套件（Node 写的 `run.ts`）与 Python 写的工具
若各用各的解释器，同一次跑批的结论就不可复现。`run_all_gates.sh` 的做法是
**优先 `ALLIN_PYTHON` → 仓内 `.venv` → PATH 探测**，并且把选中的解释器
`export` 给整批门禁用。

### 2.2 依赖

**只需两个第三方包**：

| 包 | 必要性 | 谁需要它 |
| --- | --- | --- |
| `PyYAML>=6.0` | **硬依赖** | `g18-exceptions`（解析 `exceptions.yml`）、`kernel/tree.py`（读 cordis 配置树） |
| `watchdog>=4.0` | 可选增强 | cordis 的 `hmr`（热重载）。**缺它不崩**，cordis 退回 mtime 轮询 |

内核依赖以 `vendor/cordis` **内联形式**提供（离线、可审计），**不需要 pip 安装**。

```bash
# 装依赖（推荐：直接跑 bootstrap，它会一并建 venv）
.venv/bin/python -m pip install -r requirements-dev.txt
```

> ⚠ 本仓根**没有** `requirements.txt`（运行时依赖）；`requirements-dev.txt`（开发/门禁依赖，
> `bootstrap.sh` 装的就是它）之外还有两份**按生命周期单列**的文件：
> `requirements-release.txt`（发版期「能出包」的最小集，不进 CI 门禁路径）、
> `requirements-sast.txt`（CI 的 bandit / pip-audit 专用，钉版）。跑门禁只需要第一份。

**2026-11-07 实测**：`.venv` 内 PyYAML **6.0.3**、watchdog 已装；`bootstrap.sh` 判定

### 2.4 终端纪律（🔒 本仓特有坑）

- `.ps1` 脚本**建议用 PowerShell 7（`pwsh`）**跑；PowerShell 5.1 会把无 BOM 的
  中文注释读成乱码并报假语法错（`check_ps1_bom.py` 门禁保证本仓脚本带 UTF-8 BOM）。
  🔒 **2026-11-07 实测补充**：本机**未装 PowerShell 7**。`bootstrap.sh` 的 Windows 分支
  只认 `pwsh`，找不到就跳过别名重建（仍 exit 0，但干净克隆会缺别名）；而 CLI
  `docs aliases` 走系统自带 `powershell`（5.1），实测 **exit 0、4 个别名全 OK**，
  代价是中文输出乱码（cp936 / GBK 解码）。⇒ **带 BOM 的脚本在 5.1 下能跑但输出不可读；
  要干净输出、要在裸机上重建 junction，仍须装 PowerShell 7。**
- `.sh` 脚本（`bootstrap.sh` / `run_all_gates.sh`）用 **Git Bash** 或 **WSL** 跑。
- **行尾由仓库说了算**：本仓有 `.gitattributes`，`*.sh` / `*.ps1` / `*.md` / `*.yml`
  一律 LF，`*.bat` / `*.cmd` 保持 CRLF。
  ⇒ **为什么**：本仓开发机 `core.autocrlf=true`，若无此文件，Windows 检出时 `.sh`
  会变 CRLF，Linux CI 检出是 LF —— 实测 CRLF 版本的 shebang 变成
  `#!/usr/bin/env bash\r`，直接执行报 `env: 'bash\r': No such file or directory`。

- **fallback**：主模型 429/5xx/超时，或预算耗尽 → 按 `priority` 切到次高优先级 fallback 模型；
- **offline**：全部远程不可达 → 走本地 Ollama（若有）或纯确定性 MCP 工具面。

可执行的决策层：`platform/apps/mcp/src/model_route.js` 的 `decideRoute()` 纯函数（零外部依赖、可单测）。两个只读 MCP 工具可直接查：


- `model.route`：返回当前降级档位决策（可传 `preferTier=offline` 做离线演练）；
- `model.fallback-catalog`：列出模型不可用时仍可完成的确定性任务清单。

可观测：每次模型降级决策会落到 agent trace 的 `degradation.tier` / `.reason` / `.fallback_from` 字段（见 `platform/apps/mcp/src/agent-trace.js`），便于事后复盘为何落到 offline / fallback。知识库 QA 的三档降级封装见 `deploy/graphrag/qa_wrapper.py`（`--selfcheck` 验证三档不崩；`full` 缺 `GRAPHRAG_API_KEY` / `facts.sqlite` 时自动降级，不假装 full）。

> 下表是**本仓实测踩过的坑**，不是通用建议。

| # | 现象 | 原因 | 解决办法 |
| --- | --- | --- | --- |
| 1 | CLI 中文输出乱码 | cp936 控制台下 Python 写 GBK 字节 | 用 `allin.bat`（已强制 UTF-8）；或改用 `pwsh` 7；必要时设 `PYTHONIOENCODING=utf-8` |
| 2 | 门禁报 `ledger-unusable` / 假红，但提交信息写「19/19 clean」 | **解释器不一致**：PATH 上的便携 python 无 PyYAML，而门禁套件要解析 `exceptions.yml` | 用仓内 `.venv`（bootstrap 会建）；或 `ALLIN_PYTHON=<完整解释器路径> bash scripts/run_all_gates.sh` |
| 3 | `gitee_release.py` 取不到令牌，但 `git push` 能推 | 两条链路独立：脚本**不读** GCM | `export GITEE_TOKEN=<HEX>` 或加 `--token <HEX>`；见 [`SPEC-102`](规范/SPEC-102-发版指南.md) |
| 4 | `.ps1` 脚本中文乱码 / 报错 | PowerShell 5.1 把无 BOM 的文件中文注释读成乱码 | 优先用 **PowerShell 7（`pwsh`）**；本仓脚本已写 UTF-8 BOM（`check_ps1_bom` 门禁管），带 BOM 者在 5.1 下也能跑但输出乱码。本机未装 7 时见第 16/17 条 |
| 5 | 平台门户打不开 / 连 9000 失败 | 门户已改「临时端口（PORT=0）」模式，9000 不再常驻 | 双击 `platform/start-platform.bat`，自动分配临时端口并开浏览器 |
| 6 | 克隆后 `docs/spec`、`docs/facts` 等 ASCII 别名目录缺失 | 别名是 junction/symlink，**不入库**，换机/克隆后需重建 | `bash scripts/bootstrap.sh`（Windows 用 `pwsh` 或 `cmd` 内建 `mklink /J` 重建 junction，**无需 PowerShell 7**；POSIX 走 `ln -s`）；或 `pwsh -File tools/gate/make_doc_aliases.ps1`（校验加 `-Check`） |
| 7 | 提交被 gitleaks 拦截（含疑似密钥） | 代码/配置里出现 32-hex / `sk-` / `api_key` 等敏感串 | 移出真实密钥，改 example 值；密钥走 `.env` / `私人令牌.txt`（已 gitignore） |
| 8 | DSH 治理段没挂载 / 会话无治理段 | 上游破坏性变更导致 preset 挂载失败 | 会话会自动降级到 `standard`/`cordis`（不崩）；定位漂移跑 `pwsh -File preset/allin/verify-mount.ps1`，无 7 时可用 `npm run smoke:e2e`（CP6）与 `preset/allin/refresh-gov-block.py --check` 等价覆盖 |
| 9 | 源码写死 `G:\...` / `/Users/...` 被门禁 `g01` 拦 | 门禁 `g01-paths` 禁止硬编码绝对路径 | 改相对路径或约定变量（如 `$PROJECTS_ROOT` / `$DSH_HOME`）；见 [`SPEC-006`](规范/SPEC-006-机器与路径约定.md) |
| 10 | 根目录 `npm install` 后仍有依赖缺失 | 根 `package.json` **无第三方依赖**（脚本直调 `node` 跑 TS）；只有 `platform/` 需要装 | 只对 `platform/` 子目录装；根无需 `npm install` |
| 11 | Linux/macOS 上 `bash scripts/bootstrap.sh` 报 `env: 'bash\r'` | 检出时 `.sh` 被转成 CRLF（无 `.gitattributes` 时 `core.autocrlf=true` 的副作用） | 已是**历史问题**：本仓现在有 `.gitattributes` 钉死 `*.sh` 为 LF。若仍遇到，说明检出未用本仓的 `.gitattributes` |
| 12 | CI 上跑出 19/20 而不是 20/20 | `g20-facts` 是 **Windows 专属**（`platforms=["nt"]`），Linux 上按平台跳过 | **这是设计如此**，不是缺陷。GitHub Actions 另有一个 Windows job 补跑它（2026-11-07 复核：`registry.json` 里 `platforms` 仍为 `["nt"]`，`gates.yml` 的 Windows job 仍在） |
| 13 | 照抄本文旧版 `repocheck` 命令报 `error`、exit 1 | 排除项少了 `packages,scripts,website` —— 这三个后加的中间目录被当成独立项目扫 | 用现行口径 `--profile monorepo --exclude tools,vendor,preset,packages,scripts,website`（2026-11-07 起规则豁免收编为 `--profile`，与 `run_all_gates.sh` 逐字一致）；本次实测 exit 0 |
| 14 | `platform check-repos` / `cd platform && npm run check` exit 1 | 注册表 146 条里 123 条无本地克隆，另 3 个远端仓（`calculator` / `happy-childrens-day` / `sin-virtue-game`）已删；本机只检出 23 仓 | **环境事实，不是代码缺陷**。补齐发布区检出，或按形状校验设 `PLATFORM_PATH_CHECK=absolute`；`npm test` 仍 56/56 绿 |
| 15 | `run_all_gates.sh --with-platform` exit 1，但主链绿 | 该参数额外跑 `platform` 的 `check` / `harness`，二者同样因发布区未检出报红 | 第 0 章的硬承诺是**不带参数的主链**（exit 0）；扩展项是额外体检，红项按第 14 条处置，别拿它否定主链结论 |
| 16 | Windows 上 `bootstrap.sh` 不重建 ASCII 别名 | —— 已修复：2026-11-10 起 Windows 无 `pwsh` 时用 `cmd` 内建 `mklink /J` 建 junction，不再静默跳过；干净克隆也能自动建好，不会因缺 PowerShell 7 导致 `g15` 的 D6 红 | 无需额外动作；要重校验可 `pwsh -File tools/gate/make_doc_aliases.ps1 -Check` |
| 17 | `allin.bat docs aliases` 能跑但中文全是乱码 | CLI 走系统 `powershell`（5.1），输出是 GBK 字节；脚本带 UTF-8 BOM 所以不报语法错 | 用 `allin.bat`（已强制 UTF-8）跑 CLI，或设 `PYTHONIOENCODING=utf-8`；要干净输出仍装 PowerShell 7。与第 1 条同源 |
| 18 | 门户内点启动/停止没反应，或脚本调用 403 | 状态变更端点需 `X-Allin-Token` 令牌闸 + 来源闸双闸（2026-11-08 整改「无鉴权」已推翻） | CLI / website 代理自动读 `platform/data/portal.token`；纯脚本调用需带该令牌（或设 `ALLIN_PORTAL_TOKEN`）；跨站无令牌的请求按 g10 口径 403 拒绝 |
| 19 | 换机/克隆后 `npm install` 卡死在 `127.0.0.1:8899` | 本地镜像代理脚本在仓外（`%USERPROFILE%\.dsh\npm_local_mirror.py`），新机不存在即卡死 | 已修复：`start-platform.bat` 探测镜像，不可用即回退默认 registry；手动跑用 `npm install --registry=https://registry.npmmirror.com` 加速 |
| 20 | 大模型 LLM 不可用时怎么办 | 本仓 MCP 工具面全确定性、无 LLM 运行时，天然是降级终点 | 查 `model.route`（含 `preferTier=offline` 演练）/ `model.fallback-catalog`；策略见 `preset` GOVERNANCE 段与 `docs/事实源/模型凭据登记.yaml`；知识库 QA 走 `deploy/graphrag/qa_wrapper.py`（`full` 缺 key 自动降级） |
