## 3. 关键工程取舍（避免「看起来没问题」）

1. **没有盲目加 `--cov-fail-under=80`**：实测只有 61%，硬设阈值会让 CI 无谓变红。按 P3 §4「先实测后验收，两步走」，阈值留给您裁决。
2. **CI 未默认开 `ALLIN_STRICT_SKIP=1`**：CI runner 无发布区，`repo_hygiene` 按设计记 SKIP；开严格模式会把「环境不适用」误判为失败。准出侧已由 `ALLIN_GATE_SUMMARY status=clean` + PR 模板把关，严格模式在本机用可逆注入验证过（T8）。
3. **B602 不用 `# nosec` 压掉**：`tools/verify_projects.py:125` 的 `shell=True` 有真实设计约束，把它标成 `REVIEW_REQUIRED` 并显式 `continue-on-error`，比假装扫描全绿诚实。
4. **`mutmut` 移出仓内依赖集**：它依赖较旧 pytest 生态，会破坏已验证的 pytest 9 + pytest-cov；变异基线须在独立环境/干净副本上跑，本轮未实测。
5. **历史方案文档（P3/P2）数字保留**：按仓内约定「历史陈述按当时事实保留备查」，只同步现行 README / SPEC / 上手指南 / CI 注释。
