## 二、建议逐条落地

### 2.1 建议 1 · 门禁解释器应钉死

- **问题**：`tools/gate/governance/run.ts` 的 `discoverInterpreter()` 按 `python3 → python → py -3` 探测，
  落点随机器而异 ⇒ 同一提交一台绿一台红（实测：便携 3.13.14 无 PyYAML ⇒ `g18-exceptions` 报
  `ledger-unusable` 假红，而提交信息写着「19/19 clean」）。
  更隐蔽的一层：`scripts/run_all_gates.sh` **挑了**一个解释器却**不传给**门禁套件 —— 挑了解释器不用。
- **改法**：
  1. `run.ts`：`discoverInterpreter()` 的候选链改为 **显式覆盖 → 仓内 `.venv` → PATH**。
     仓内 venv 是**仓库自己钉住依赖集的唯一候选**（含 PyYAML），故优先；
  2. `scripts/run_all_gates.sh`：同样优先 `.venv`；把选中的解释器 `export DSH_GOVERNANCE_PYTHON="$PY"`
     **传给门禁套件**；Python 工具一律用 `"$PY"` 调（不再走 `npm run check:docs` 的裸 `python`）；
  3. 解释器选型判据从「能 import tkinter」换成「能 import yaml」——
     **PyYAML 才是门禁套件的真依赖**（只有 `g18-exceptions` 需要），tkinter 只是 repocheck GUI 的依赖。
     缺 yaml 时只告警不中止：宁可少跑一道，也别把已跑的 18 道一起丢掉。
- **证据**：
  ```
  $ node tools/gate/governance/run.ts --no-profile --only g00-meta
  governance: python 3.13 via E:\projects\allin\.venv\Scripts\python.exe; 1 gate(s); ...
  ```
  （**未设任何环境变量**即自动选中仓内 venv；此前落点是 PATH 上的便携 3.13.14。）

### 2.2 建议 2 · SELFCHECK 输出格式与契约统一

- **问题**：`govlib.SelfCheck.finish()` 用 `json.dumps` 默认分隔符，输出 `SELFCHECK {"caught": 4, ...}`（**带空格**），
  而契约（`tools/gate/governance/RULES.md` §自证有效）写的是 `SELFCHECK {"caught":N,"clean":M,"misreports":K}`（无空格）。
  `g15-docs-contract` 手写 `%d` 格式无空格 —— 仓内**两套格式并存**，契约当时只是文本约定、没被机检。
- **改法**：
  1. `govlib.py`：`json.dumps(..., separators=(",", ":"))` —— 6 道走 govlib 的门禁统一为契约格式；
  2. `g00_meta.py`：正则收紧为**契约文本本身**
     `^SELFCHECK (\{"caught":\d+,"clean":\d+,"misreports":\d+\})$`
     —— 从此格式偏差会被判「没打印摘要」，契约从文本约定变成可机检的退出码；
  3. `g00_meta.py` 自检夹具同步改为紧凑格式（否则元门禁会拿自己的夹具开刀）。
- **证据**：6 道门禁自检摘要现已全部为契约格式，例如
  `SELFCHECK {"caught":9,"clean":1,"misreports":0}`（g15）、`{"caught":4,"clean":1,"misreports":0}`（g18）。
- **一处自伤**：收紧正则时去掉了捕获组，`match.group(1)` 抛 `IndexError` —— 改完立刻单跑元门禁才发现，
  已改回保留捕获组。**收紧判据的改动必须自己先跑一遍被收紧的那道门禁。**

### 2.3 建议 3 · 提交前复跑门禁并贴退出码（双形态同步）

- **问题**：提交信息里的门禁结论不可复现 —— 「全绿」这句话没有绑定解释器，
  实测同一提交在两种解释器下一绿一红。
- **改法**：纪律**双形态同步**落地（README「治理 Agent 与内核」章的双形态要求）：
  1. **WorkBuddy 侧** `.workbuddy/skills/allin-governance-agent/SKILL.md` §5.1 第 4 步补：
     用与 CI 同一个解释器复跑（`bash scripts/run_all_gates.sh` 会把解释器钉死并传给门禁套件）、
     **把实际退出码贴进提交信息**、不写「应该绿了」；
  2. **DSH 侧** `preset/allin/allin.patch.yml` 的 `GOVERNANCE:BEGIN/END` 段补同一句（措辞对齐）；
  3. **刷新 bundle**：`preset/allin/bundle/cordis.patch.yml` 是源的派生副本，
     已跑 `preset/allin/make-bundle.ps1`（脚本自报「bundle 已落后」并覆盖），
     `-Check` 复验 `FRESH：bundle/cordis.patch.yml 与 allin.patch.yml 一致`。
- **证据**：`g16-skill-preset-parity` 通过（两侧载体事实一致）；
  `make-bundle.ps1 -Check` 退出码 0。

### 2.4 建议 4 · repocheck 的 tkinter 降为 GUI 可选依赖

- **问题**：`tools/repocheck/main.py` **模块级** `import tkinter`，CLI 模式同样被卡 ——
  而它自己的文件头写着「仅在 `build_gui()` 内实例化 `Tk()`；无显示器环境下 `import main` 不会创建 GUI」，
  **文档说的和代码做的不一致**。实测本机两个解释器（便携 3.13.14 与仓内 `.venv`）**都没有 tkinter**
  ⇒ README 声称的 repocheck 自检口径在本机**根本跑不起来**。
- **改法**：模块级导入改为 `try/except ModuleNotFoundError` 守卫（无 tkinter 时置 `None`）；
  `build_gui()` 在 `tk is None` 时**响亮报环境错并退出码 3**（GUI 不可用，但 CLI 可用）。
- **证据**：
  ```
  $ python tools/repocheck/main.py . --exclude tools,vendor --skip-rules 1,7 --fail-on error
  健康分：均值 6.0 / 最低 6.0　通过率 100%        # 无 tkinter 的解释器上，退出码 0
  ```

### 2.5 附带发现 · README「本仓自检口径」的 B 条口径不实

- **问题**：README §本仓自检口径 声称「`B)` 仅剩规则 1 固有项」。实测 **B 退出码是 1**，共 5 条 error：
  规则 1（缺 `.git`）×2、规则 2（缺 README）、规则 4（缺依赖声明）、规则 5（缺 LICENSE）。
- **根因**：`tools/` 下有两个子件 —— `tools/repocheck` 是**完整项目**（README/LICENSE/pyproject 齐备，
  只命中规则 1）；`tools/security` 是**单文件标准库脚本**（`venv_ca_audit.py`），缺 2/4/5 三项。
- **处置**：四条逐一核对确认**均属 monorepo 子件的结构固有项**（依据逐条写进 README 豁免表），
  B 的命令补 `--skip-rules 1,2,4,5`，实测退出码 **0**；README 的「现状」行同步改成实测口径，
  并加了一条注记：**规则口径变了就要改命令、改依据、改现状，三者一起改**。
- **顺带修正一处测量错误**：此前若干「退出码 0」取自管道末端的 `tail` 而非命令本身。
  已改用 `cmd > file; echo $?` 重测 A/B/docs_index —— **A=0、B=1（修正前）、docs_index=0**。
