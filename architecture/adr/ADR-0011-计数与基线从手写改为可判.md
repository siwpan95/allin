# ADR-0011 —— 计数与基线从手写/隐式改为可判

- 状态：**accepted**（2026-11-25 拍板；本文件定**语义与判据口径**，实现分工见 §Consequences 末段）
- 时点：2026-11-25 ｜ 决策人：全哥（本轮「把计数与基线从手写/隐式变成可判」立项）+ 工程保障团（系统架构师起草）
- 相关：ADR-0010（`tools/orchestration/routes.yaml` + g21 三方对账）、ADR-0009（架构资产对账门禁）、ADR-0004（文档即测试的判定口径）、ADR-0006（支柱清单以 yml 为唯一数据源推导）
- 记账准则：SPEC-003 §创新三原则 1「借鉴必记账」——本文借用的三条先例逐条记「来源 / 许可证 / 借用范围 / 我们改了什么」，见 §借鉴记账

## Problem

本仓有三处「数字只存在于人的记忆里」：基线的账、skill 的计数、门禁的量。三处都不是判据缺强度，而是**判据答不了「你现在到底量到了什么」**。

### P1 基线只有键列表：能禁新增，不能禁「账单长胖」，也不会自动作废

现场（2026-11-25 实测）：

- 两份基线**键数都是 0**：`tools/gate/ledger/docs_index_baseline.txt` 只有一行注释、`tools/gate/baseline/relative-refs.txt` 只有一行注释。也就是说「基线棘轮」这个机制**从来没被真正使用过**，一直在空转。
- `tools/gate/docs_index.py` 的 `emit()` 逻辑是：`new_block = 当下 − 基线`，`return EXIT_FAIL if new_block else EXIT_OK`；而 `--write-baseline` 把**当下全部阻断**写进文件后**无条件 `return EXIT_OK`**。
  由此三条漏洞，全部是结构性的、不是笔误：
  1. **`--write-baseline` 是一条命令就能把红变绿的静默通道** —— 增长速度不受任何限制，也不需要写原因。
  2. **过期账单永不消失**：`baseline − 当下` 这个差集**没有任何代码在算**。某条债修好之后，那个键永远留在文件里，谁也不知道还剩几条真债。
  3. **「挂了 12 条」与「一条都没有」在日志里长得一样**：输出只有 `blocking=0 baseline=0 new=0 reported=0 skipped=0` 五个数，没有任何一个数回答「你这次到底量了几份东西」。
- 第三份基线**根本不存在**：g19 跑批时自己打了一条 note —— `baseline 缺失 … 棘轮失效，本次按全量判定`。**它知道自己没棘轮，但它说的这句话不影响退出码**。这是本仓的一个通用形态：**判据能解释，但不能判**。
- 同一套台账里，**例外**已经有到期判据（g18 的 `expired-exception`：过期即红），**基线**没有。同类账单两种待遇，说明这不是能力问题，是漏做。

### P2 专项 skill 计数长期手写，且「少登一条」没有任何判据会响

三个时点，三个数，各说各话：

| 时点 | 发生了什么（git 事实） | 手写声明 |
| --- | --- | --- |
| 2026-11-04 `a3e5ba5c` | SPEC-204 迁入，写入「本仓已有 **15** 个专项 skill」 | 15 |
| 2026-11-10 `b9efab85` | `routes.yaml` 增加第 **16** 条（`allin-audit-doc-check`） | 三处「15」无人改 |
| 2026-11-24 `72252c86` | 新增 `.workbuddy/skills/github-sync-audit/` | 未入台账，无人发现 |

当下实测四个读数：

- `.workbuddy/skills/` = **18 个目录**（含路由者自身 `allin-governance-agent`）；
- `routes.yaml` = **16 条**；
- g21 实跑 = `total=16 ok=16 drift=0` **绿**；
- SPEC-204 三处仍写 **15**（架构图注释、「路由表」段、「编排事实源」段）。

⇒ 四个数互不相等，**却全绿**。原因不是判据写错了，是判据**视野不够**：g21 做的是「已登记者内部的三方对账」（routes.yaml ⇄ 路由者 SKILL.md 锚点 ⇄ GOVERNANCE 段锚点），**从不枚举 skills 目录**——`tools/gate/agent_parity.py` 里指到 skills 目录的只有 `SKILL_FILE` 一处常量，指向路由者自己。**缺席者不在任何判据的视野里**：少登一条，三面同时少，三方照样一致。

更险的一层（这条决定了 D2 的设计）：如果只把判据定成「声明数 == `len(routes) − 1`」，**今天 15 == 16 − 1 恰好成立，判据会绿**。因为两个错互相抵消了 —— 台账漏登 2 条（路由者 + `github-sync-audit`）、同时把路由者当成了第 16 个专项。**单一派生源可以被「漏登」骗过**，凡是「声明 ⇄ 台账」的判据，都必须再拿「真身」（目录）对一次账。

### P3 盲门：`scanned 0` 与 `scanned 88` 都能退 0

- **结构证据**：`Report.scanned` 默认 `0`，而 `Report.exit_code()`（`_gatesuite/runtime/govlib.py`）只看 findings 与严格模式下的 skipped，**从不读 `scanned`**。所以「什么都没量」的判据在无 findings 时恒绿 —— 这是编译期事实，不是推演。
- **现场 a（无字段）**：`tools/gate/docs_index.py` 的 Report **连 `scanned` 字段都不存在**，退 0 时只打印 `blocking=0 baseline=0 new=0 reported=0 skipped=0`。「一份没读」与「读完 141 份、零问题」字节级同形。
- **现场 b（有分子没分母）**：g19 在本仓 `scanned 88 file(s); blocking 0; exempted 350; exit 0`。88 是分子，**分母没有独立来源**（本应判多少份文档？没人知道），所以 88 掉到 8 也没人察觉。
- **现场 c（死门形态，2026-11-25 提仓后）**：`repocheck . --self --only-gates` 注册 **0 条门禁规则**，静默退化为 30 条仓体卫生规则，**退出码 0** —— 20 道治理判定一条没跑，结论是「绿」。
- **现场 d（同字段两值）**：g00 在包形态下 `scanned 0 file(s); blocking 43`（真红），修后 `scanned 20 file(s); blocking 0`。同一个字段既能是 0 又能是 20，**它不参与判定**，因此它既不能证明跑过、也不能证明没跑过。
- **现场 e（分母只数「已入索引」）**：g19 的语料来自 `tracked_files()` → `git ls-files`。**新建但未 `git add` 的文件不在它的视野里** —— 本 ADR 写完时实测 scanned 仍是 88（与新增前相同），因为 `architecture/adr/` 里多出的那一份没进索引。CI 在提交后跑没有这个问题，但「本地绿」不等于「新文件被看过」。（这一处**已有半个兜底**：索引为空时 `run_git` 直接抛 `refusing to judge an empty corpus`，退不出 0 —— 说明本仓已经懂这个道理，只是没推广。）

⇒ 一句话：**本仓大部分判据的退出码只回答「有没有发现问题」，不回答「有没有在量」。** 两者混同，等于把「没跑」当成最好的消息。

## Decision

一条总原则，三条语义：**「声明」必须由「真身」派生；不能派生的部分必须被量出来；任何判据都必须能区分「没跑」与「没发现问题」。**

三条语义共用既有退出码约定（`0 ok / 1 blocking / 2 usage / 3 env`），不新造码位。

### D1 基线双侧棘轮（不许长大，也不许留过期账单）

**D1.1 键必须带数量。** 基线行格式 `<code>|<message> count:<n>`；判定时把当下同一 key 的命中数记 m：**m > n ⇒ 判红并列出全部 m 条**（不许用旧账掩盖新账），m ≤ n 视为在账内。
理由：无数量的键，「同一处代码又新增 3 条同类问题」不改变键集合 ⇒ 增长不可见。这是 ESLint 明示的坑（原 2 条被抑制、现 5 条 ⇒ 5 条全报）。

**D1.2 `--check`（默认，CI 用）三态，逐条列差：**

- 新增（`当下 − 基线 ≠ ∅`）⇒ **exit 1**，逐条前缀 `+`；
- 过期（`基线 − 当下 ≠ ∅`）⇒ **exit 1**，逐条前缀 `-`，提示「改用 `--write-baseline` 收账」；
- 皆空 ⇒ exit 0，且**必须**打印 `scanned=<n> baseline=<n> stale=0 new=0`。

**D1.3 `--write-baseline`（人用）从「无条件写」收紧为「有前提的写」：**

- 若 `现基线 ⊆ 当下` 且 `现基线 ≠ 当下`（即**一条都没修好、纯粹长胖**）⇒ **拒绝写入，exit 1**，提示：「纯增长须显式 `--allow-baseline-growth --reason "..."`」；
- 其余情形（有修好、有新增，或纯瘦身）⇒ 允许写，但**先打印 `-fixed <n>` / `+new <n>` 两列**再落盘；
- 落盘时文件头必写 `# written: <ISO8601> commit:<sha> reason:<原话>`；**缺头部元数据的基线文件判红**（防手写、防无因写入）。

**D1.4 放行开关只给人用。** `--pass-on-stale` 与 `--allow-baseline-growth` 在 CI（`CI=1` 或 `--ci`）下出现 ⇒ **exit 2（用法错误）**，而不是 exit 0。宁可红在参数解析，不要绿在语义。

**D1.5 现在换格式，成本为零。** 两份基线当前键数都是 0 ⇒ 加 `count:` 不必写迁移脚本、不必一次性回归；等长到几十条再换，就要写迁移 + 全量对账。**这类格式债的利息随存量线性上涨，最佳迁移点是存量为零的今天。**

### D2 计数派生（声明数由台账派生；台账由目录对账）

**D2.1 `routes.yaml` 顶层加 `router: <route-id>`**，指向台账中「路由者自身」那一条。门禁**从台账读**这个 id，**不写死排除名单** —— 写死排除等于把「谁是路由者」变成第二份手写事实，下次改名就要改判据，而改判据的人不会知道有这条。

**D2.2 三条并行判据（缺一条都留缺口）：**

- **A 声明 ⇄ 台账**：SPEC-204 里的声明数包成锚点 `<!-- skills:count --><n><!-- /skills:count> -->`，g21 校验 `<n> == len(routes) − 1`（扣掉 `router` 指向的那条）。措辞仍人写，**只有数字受管**。
- **B 台账 ⇄ 真身**：`.workbuddy/skills/*/SKILL.md` 的目录集合 ⟺ `set(routes.skill)`，**双向差集非空即红**：目录有、台账无 ⇒ `unregistered-skill`（缺席者）；台账有、目录无 ⇒ `dangling-route`（死链）。
- **C router 自洽**：`router` 的值必须是台账中某条的 `id`，且该条 `entry` 指向 `.workbuddy/skills/<router>/SKILL.md`（防「router 字段写了个人名、台账里却没有」）。**⚠ 本条原文比实现窄**：实测本仓 `routerInLedger=false`（router 并不在 routes 里），两种形态均受支持，见下方 §实现注记（2）。

#### 实现注记（2026-11-25，Cody 落地）

落地形态与上文表述有两处不一致，**方向都是实现更宽**。按本仓纪律如实记下来，而不是反过来把实现改窄或把文档改了当没事 —— 文档与实现的差本身就是下一轮判据的输入。

**（1）D2.2-A 的「声明数」来源：多载体正则，不是单锚点。**

ADR 写的是「在 SPEC-204 里包一对 `<!-- skills:count -->` 锚点」。实际实现**没有做锚点**，而是用正则扫**三个载体的全部正文**，逐处核对：

| 载体 | 声明处 | 身份（人话） |
| --- | --- | --- |
| `preset/allin/allin.patch.yml` | 1 处（L89） | DSH 治理段正文（唯一手改源） |
| `.workbuddy/skills/allin-governance-agent/SKILL.md` | 3 处（L3 / L9 / L189） | WorkBuddy 治理载体 |
| `docs/规范/SPEC-204-系统架构.md` | 3 处（L39 / L90 / L332） | 架构规范 |

= **3 载体 / 7 处**（实测，取自 g21 产物 `reconciliation.declarations`），每处都必须等于派生值，任一不等即 `E106`。正则 `(\d+)\s*[个条]\s*(?:既有项目级|专项)\s*skill` —— **只放宽措辞，不放宽数值**：量词收 `个/条`、定语收 `专项/既有项目级`，因为三处原文措辞本来就不同（SPEC-204 §6 写「N **条**专项 skill 路由」，其余写「N **个**专项 skill」）；命中几处就核几处，**不因换一种说法就逃出判据**。

为什么这样比单锚点好，三条：

1. **覆盖 7 处 vs 1 处**：单锚点只守 SPEC-204，另两个载体（`SKILL.md` 3 处、`patch.yml` 是唯一手改源）仍会各自漂；
2. **不要求改人写正文**：锚点是给机器看的标记，往三处散文里各插一对是额外侵入，且下次有人重写段落时会连同标记一起丢 —— 判据依赖「人保留标记」是脆的；
3. **漂移可见面更大**：7 处任一处漂都红，锚点方案漏掉 6 处。

单锚点被否的理由：它把「这些地方在对人作同一个承诺」偷换成「只有我标了锚点的地方才管」。**只管一处等于宣布另两处可以自由发挥。**

代价（如实记）：正则是文本匹配，措辞再变（如「17 项专项 skill」）就退回「该载体不参与判据」。故实现补了 `W302`：**某载体一处都没命中 ⇒ WARN 并记入 `silentCarriers`**，不许静默 —— 否则删掉一句话就能让判据名存实亡而跑批全绿，这是 D3 同一条纪律在**载体维度**的落点。W302 只 WARN 不红，因为「撤掉声明」是合法修法；**但它必须被看见**。

**（2）D2.2-C 的 router 形态：本仓「router 不在 routes 里」。**

- **本仓实测**：`router=allin-governance-agent`、`routesTotal=17`、`routerInLedger=false`、`skillDirs=18`、`effective=17`。
- **为什么取这一形态**：给路由者自己在台账里立一条「路由到我自己」是**环** —— 锚点要对账到自己、`forms` 要声明自己、`lastVerified` 要自己维护自己；更重要的是**台账语义会变味**：台账讲「**被**路由的专项 skill」，路由者是**执行者**，两者不是同一类东西。实测后果就是 `effective = len(routes) − 0 = 17`，与「18 个目录 − 1 个 router」一致。
- **「两种都支持」是刻意的，不是偶然**。判据分两支，各一支都有明确校验：

  | 形态 | 结构校验 | 派生值 `effective` | 目录差集 |
  | --- | --- | --- | --- |
  | router **不在** routes（**本仓**） | router 必须是 skills 目录下的真目录，否则 `E109` | `len(routes)` | `dirs − registered − {router}` |
  | router **在** routes | 额外要求该条 `entry == .workbuddy/skills/<router>/SKILL.md`，否则 `E203`（防「router 字段写了某条路由」张冠李戴） | `len(routes) − 1` | 同上 |

  刻意支持两形态的理由：D2.1 的原始动机是「**排除项必须从台账读，不能写死在门禁里**」；而「路由者要不要在台账里」是各仓的组织选择，判据不该替人决定。判据只保证一件事：**无论哪种形态，`effective` 与目录差集都由台账字面值算出，不由代码里的名单算出。**
- **与原文的关系**：D2.2-C 原文把一种组织选择写成了硬要求，实现把它降级为「被显式支持的两种形态之一」并保留自洽校验。这**是放宽，但不是变松** —— 形态自相矛盾（router 在台账里却 `entry` 不指自己）原文根本没覆盖，现在会红 `E203`。

**D2.3 A 为什么不能单用 —— B 是 A 的分母校验。** A 管「声明没落后于台账」，B 管「台账没落后于真身」。只有 A 时，**漏登会让两个错互相抵消**（P2 末段：今天 15 == 16 − 1 恰好成立）。这两半的关系与 RuboCop 的「todo 文件 ⇄ 规则集耦合测试」同构：耦合测试不是验证 todo 好看，而是验证 todo 与真身同步。

**D2.4 接上即红的三处（预期，不是缺陷）**：`allin-governance-agent`（router，未入台账）、`github-sync-audit`（目录在、台账无）、SPEC-204 三处「15」（补登记后派生值应为 17 = 18 目录 − 1 router）。**红是我们想要的第一个读数**；一个刚接上就绿的新判据，先怀疑它没接线。

### D3 盲门判据：`scanned == 0` 且退 0 且非 SKIP ⇒ 判红

**D3.1 每条判据必须自报三个数**：`scanned`（量到几份）、`exempted`（豁免几份、按原因分）、`skipped`（没能量几份、按原因分）。三者缺一即判红（缺字段 = 不可解释）。

**D3.2 `scanned == 0` 且无 findings 且无 skip 原因 ⇒ exit 1**，并必须打一条 `BLOCK blind-gate: scanned 0, 判据没有量到任何对象`。这是「跑完了、退 0、什么都没量」的唯一出口。

**D3.3 「没跑」必须可区分（两步都判）**：
- `--only <id>` 未命中任何门禁 id ⇒ **exit 2**（用法错误）。拼错门禁名以前静默绿，这是实质假绿。
- `--selfcheck` 若用例数 == 0 ⇒ **exit 2**（无用例 = 未运行，不是通过）。与 pytest 无用例收集退 5、Jest 默认无测试即失败同口径。

**D3.4 「变异没落上去」必须响（负对照）**：自检注入必须证明**改动真的生效** —— 用例里要断言注入物确实存在于沙箱，否则锚点漂移会让「注入了缺陷」变成「什么都没注入」而仍然报「已捕获」。本仓已有正确的形态（g19 的 `other-machine-facts` 必放 + `own-machine-drift` 必红）：**只验「必放」等于只证明豁免存在、没证明豁免有边界；只验「必红」等于没有豁免机制**。新增判据必须带这种**成对**用例。

**D3.5 存量即违规，本文只约束增改。** g19（有 scanned 无分母）、docs_index（无 scanned 字段）、g00（scanned 可为 0）当下都不满足 D3；本 ADR 要求**新增或改造**的判据满足 D3，存量按 D4 的批次收敛。

#### Implementation hazard（D3-H）：兜底正则成了盲门遮羞布

这一节不是设计推演，是**本轮实现盲门判据时自己踩的坑**。写在 ADR 里而不是只留在会话记录里，是因为它属于「判据设计」层面的教训，与 D3 的三条语义同级 —— 下一个写判据的人应当从 ADR 读到它。

**现场**：盲门判据的第一版，为了兼容「输出不走 govlib 格式」的判据，加了一条宽松兜底正则去文本里抓 scanned 数。真实仓首跑，它把 `g15-docs-contract` 判成 `measured (scanned 1)` —— 那个 `1` 根本不是扫描计数，而是 g15 输出里的一行**豁免标签** `D16-plan-scanned=1`。后果很具体：统计口径变成「19 道有量」，而真相是「18 道有量 + 1 道不可判定」。

**判据失败的方向是「看起来更好」—— 这是最坏的失败方向。** 盲门判据本来要防的是「假装量过了」，它自己却先假装了一次；而且假装得比真相更好看，所以**没有任何人会有动机去查**。这与 §Alternatives 2（整片豁免换绿）是同一个动作，只是尺度从「一个目录」缩小到「一行正则」：**都是为了让某处闭嘴而扩大了匹配面**。

**三条要求：**

1. **兜底匹配的匹配面必须显式排除四类行**：豁免/跳过标签（`…-scanned=` / `exempted:` / `SKIPPED`）、统计摘要行、注释、以及「别人记录自己的工作」（如 `D16-*` 这类 D 编号前缀）。判据**不许把别人的豁免记录当成自己的工作量** —— 那既不是它量的，也不是它有权量的。
2. **收紧之后必须留成对反例**（与 D3.4 同款纪律）：同一段文本，以 `D16-plan-scanned=1` 形态伪装成 scanned ⇒ 必须判 `undetermined`；真输出 `scanned 3` ⇒ 必须判 `measured`。**只留正例的判据，不知道自己会不会放过。** 这就是 D3.4「只验一侧不算」在文本解析层的复现。
3. **`undetermined` 必须是一等结论**：与 `measured` / `blind` 并列输出并计数，**不许在统计时被折叠** —— 折进「未量」会与 SKIP 混账，折进「有量」就是本次事故。三个状态各自可数，才谈得上「可判」。

**本节结论（引用时请连这句一起用）**：**「判据为了更好地兼容而放宽的那一处，往往就是它失灵的那一处。」**

### D4 试点与批次

- 本轮**只对 g19 试点 D1 + D3**（它是唯一同时具备 `scanned` 与 `exempted` 明细的判据，一次改动能证完三面：量到了、豁免了、过期了）；
- **D2 由 g21 试接**（它本来就在做三方对账，加「目录枚举」是同一处的第四个方向，不是新门禁）；
- 其余 **19 道**（`registry.json` 实测 20 道，去掉试点 g19；g21 不在 registry 内，单独走 D2 试点）留 **2.4.x 同批**收敛。
- **为什么不分批铺**：分批只对**新增**判据成立，对**改既有判据语义**不成立。门禁是一个**整体结论**，半接线状态最坏 —— 已接的按新语义红、未接的按旧语义绿，跑批结果无法解释；`scripts/run_all_gates.sh` 的聚合口径会被两套语义同时污染，最后得到的不是 19 个进度，而是 19 个「现在这道到底算不算数」的争论。

## 借鉴记账（SPEC-003 §创新三原则 1）

### 1. ESLint bulk suppressions（2025-04 发布，v9.24 起）

- **来源**：ESLint 官方博客《Introducing bulk suppressions》（2025-04，`eslint.org/blog/2025/04/introducing-bulk-suppressions/`）+ 文档 `eslint.org/docs/latest/use/suppressions`
- **许可证**：MIT（eslint 仓库）
- **借用范围**：**只借语义，不借代码、不借文件格式**。① 抑制项按「文件 + 规则」记**数量**；② 数量变多即全部报出（旧账不能掩盖新账）；③ 修完后残留的抑制项让命令**非 0 退出**，逼人 prune。对应本 ADR **D1.1 / D1.2**。
- **我们改了什么**：
  1. 键粒度从「文件 + 规则」改为「判据码 + 消息」（本仓基线的天然粒度是 `code|message`，不是文件级规则）；
  2. prune 由 ESLint 的**显式子命令**（`--prune-suppressions`）改为 `--check` **默认就在算**、过期即非 0 —— 不让「记得 prune」成为人的义务（本仓的教训正是「靠人记得」会漂）；
  3. 加了一条 ESLint 没有的：**纯增长必须显式 `--allow-baseline-growth` + reason**（ESLint 允许随时重新生成抑制文件；本仓不允许无记录重生成）。

### 2. RuboCop `--auto-gen-config` / `.rubocop_todo.yml`

- **来源**：RuboCop 官方文档 `docs.rubocop.org/rubocop/usage/auto_gen_config.html`；Gusto 的实践见 daily.dev 博文《The case for AI guardrails…》（**仅引用观点，不复制文本**；其违规清单 289 → 157）
- **许可证**：MIT（rubocop 仓库）
- **借用范围**：① 冻结存量、新违规立即失败；② `--auto-gen-only-exclude --exclude-limit N` **保留逐文件粒度**，而不是整条关掉；③ 用**耦合测试**保证 todo 文件与规则集同步。对应本 ADR **D1（棘轮）/ D2.2-A+B（耦合判据）**，以及 §Alternatives 里「不整片豁免」那条。
- **我们改了什么**：
  1. RuboCop 的耦合测试在**上游测试套件**里，本仓把耦合**做成门禁本身**（跑批即验，不依赖有人记得跑测试）——本仓的门禁与测试是两套入口，靠测试守耦合等于只守一半；
  2. **不采纳**「超过 `--exclude-limit N` 就退化为整条 exclude」：本仓触发上限时**判红要求拆分**，而不是把粒度降级为「整条关掉」——粒度降级就是 §Alternatives 中被否的「整片豁免」的温和版本。

### 3. 「A gate that only ever passes is no gate」/「A check that cannot fail tells you nothing」

- **来源**：`494group` 的 field notes《A gate that only ever passes》（2026-08-28）、`synthetixis` 的《A check that cannot fail tells you nothing》。**均为博文，仅引用观点、不复制文本**（无可援引的许可证声明，故按「引用观点」而非「借用作品」记账）。
- **借用范围**：三种静默失效的**命名与识别口径** —— **死门**（从不被调用）、**环境坏门**（跑了但环境错被吞成 0）、**盲门**（跑完、退 0、什么都没量）；两条硬约束：**「没跑」与「没发现问题」必须可区分**（pytest 无用例收集退 5、Jest 默认无测试即失败）、**「变异没能落上去」必须响**。对应本 ADR **D3.1–D3.4**。
- **我们改了什么**：
  1. 把「盲门」从识别口径做成**机器判据**（`scanned==0 && exit==0 && 非 SKIP ⇒ exit 1`），原文只到「怎么看出来」；
  2. 码位分层：盲门走 blocking（1）、「未命中/无用例」走 usage（2），沿用本仓既有约定，原文不规定码位；
  3. 「变异落没落上」落成**成对自检用例**（必放 + 必红各一条）——这是本仓 g19 已有形态，属复用而非新发明。

> 后续动作（不属本 ADR 改动面）：两条 MIT 先例建议在同批于 `docs/事实源/来源与许可表.md` 补登两行；该表在 `docs/` 契约体系内（过 D1/D8 登记），不在本次「只改 ADR」的范围。

## Alternatives considered

1. **只禁增长、不禁过期（单向棘轮）** —— **否决**。三条理由：① 过期账单本身是**假信号**：文件里 12 条、实际剩 3 条，下一个人会以为存量还有 12 条债；② 它让基线变成**只增不减的纪念碑**，越老越不可信，最终没人敢动 —— 与两份基线文件注释里写的「清完后应重写为空」正相反；③ **债的利息是判据失效**：过期键与新键混在一起，`--list-all` 的读数不再能回答「还有多少真问题」。ESLint 的 `--prune-suppressions` 与 g18 的 `expired-exception` 是同一判断：**账单必须会自己到期**。

2. **整片豁免作用域换绿** —— **否决，且有本仓实例**。2026-11-25 治理内核仓的 `ae1517b` 为了让 g19 在提仓后转绿，把 `docs/事实源/` **整目录**塞进 `SNAPSHOT_SCOPES`（与 `docs/记录/` 同款：只免 path-ref、命令断言照判）。代价立刻出现：`docs/事实源/` 里的**本机分区**也一起不判了 —— 而 g19 刚刚才为「异机分区不该由本机改」加了按 hostname 的精确豁免（`MACHINE_FACTS`）。两个决定方向相反：一个按 hostname 精确开窗，一个把整层楼的门全拆了。后续 `d973702` 把 6 元组改回 2 元组 + `MACHINE_FACTS` 精确判定，并补 `own-machine-drift` 必红用例，才算收口。
   ⇒ 结论：**豁免必须与「谁有权改」同宽**。整片豁免把边界让给「图省事」，且**副作用落在别的判据身上**（本机漂移检测静默消失）。本 ADR 里同一条纪律的三个落点：D1.4（开关 CI 禁用）、D3.2（跳过不等于绿）、D2.1（禁止写死排除名单）。

3. **计数交给「人记得同步」** —— **否决**。本仓已有三次反例：P2 的 15/16/18 三时序；ADR-0009 记录的 SVG 数字漂移两代；ADR-0006 的支柱清单手写。人记得的事必须变成「跑批记得」。

4. **给每条判据写死「应收份数」常量** —— **否决**。常量就是第二份手写声明，会与真身再漂一次，正是本 ADR 反对的东西。分母必须由**枚举规则**给出（`tracked_files` + 过滤规则），不是常量。

5. **`scanned == 0` 一律判红（含 SKIP）** —— **否决**。合法的「今天无事可判」（如只存在于某台机的分区）会被误伤成人祸，逼人写假数据填 scanned。改为「非 SKIP 才红」+「SKIP 必须带原因且被计数」。

6. **本轮一次铺满全部 21 道** —— **否决**。见 D4：会造出 19 个半接线状态；且只有先在 g19/g21 上拿到「同一判据在真实仓上红在哪」的第一个读数，后续批量收敛才有可复制的改法。

## Consequences

### 变容易

- 「基线里还剩多少债」「今年欠了几条」从人肉变成两个数（`baseline` / `stale`），且`--write-baseline` 再也不能无记录地长胖；
- **「少登一条 skill」第一次有了判据**（D2.2-B 双向差集）—— 三类漂移里最隐蔽的一种，因为缺席者在任何「内部一致性」判据里都不存在；
- 「绿」的可信度提高：`scanned` 必须报、0 必红、`--only` 打错名字不再静默通过、SKIP 与 pass 分家。

### 变困难 / 误伤面（逐条给退出路径）

| 语义 | 误伤面 | 退出路径 |
| --- | --- | --- |
| D1.1 数量键 | 同一 key 在同一文档多处命中会 m > n，报出全量，噪声变大 | 一次性 `--write-baseline --reason` 收账；本 ADR 不以「降噪」为目标，噪声是价格的另一半 |
| D1.2 过期即红 | 有人本地刚修好 3 条、还没重写基线 ⇒ 跑批红 | `--pass-on-stale` 本地放行；`--write-baseline` 收账；**CI 不许用**（D1.4 硬拦 exit 2） |
| D1.3 纯增长拒绝 | 合法新增（新增一类检查）被拦 | `--allow-baseline-growth --reason "..."`，头部留痕，审阅时能看到「为什么长了」 |
| D2.2-B 目录对账 | **当前即红 2 处**（`allin-governance-agent` / `github-sync-audit`） | 补台账（router 条目 + 缺登条目）并把 SPEC-204 的 15 改成派生值 17；这是本 ADR 期望的第一次红 |
| D2.2-B 集合严格相等 | 「实验性 skill 先建目录后登记」会被拦 | 先登记后建目录；**不接受临时目录例外**（例外会变成常态，见 Alternatives 2） |
| D3.2 scanned==0 必红 | 仓里真的没有对象可判（新仓 / 裁剪过的消费仓） | 记 SKIP + 原因（`exempted` 与 `skipped` 分开计数）；带原因的 SKIP 不算盲门。仅 `ALLIN_GATE_STRICT_SKIP=1` 时 SKIP 也算红（沿用既有开关，不新增） |
| D3.3 `--only` 未命中 | 拼错门禁名以前静默绿、现在 exit 2 | 这是修正不是误伤：写死门禁名的脚本跑一次就暴露 |

### 需要重新审视的既有决定

- **ADR-0010 的 g21 口径要扩一方**：现行 g21 是「三方对账」，属**内部一致性**判据，不是**完整性**判据 —— 三面同时少一条，它照样绿。D2.2-B 补的「目录真身」是第四方，缺它则 g21 永远无法回答「有没有漏」。
- **ADR-0009 的对账六项没有覆盖「ADR 正文里的数字」**：本 ADR 不扩面，但记下这个缺口（ADR 与 SPEC 正文里的「20 道门禁」「141 份文档」这类数字目前仍无判据，只有 SVG 图内的数字受管）。

### 落地与验收（谁做）

- 本 ADR **不写代码**，只定语义。分工：**Cody**（判据实现：g19 试点 D1+D3、g21 加第四方）、**Rex**（配置面：`routes.yaml` 的 `router` 字段与两条补登、SPEC-204 三处改锚点）、**Tessa**（把三条语义的「必须红 / 必须静默」落成成对用例，尤其 D3.4 的负对照必须证明注入生效）。
- 本 ADR 自身的可判性（写完即验，已实测）：
  ```bash
  python tools/gate/check_arch_assets.py          # 必须 RESULT: 架构资产对账全绿
  node scripts/gates.mjs --only g19-docs-refs     # 必须 exit 0（本文路径引用零死链）
  ```
