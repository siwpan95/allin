# 爬虫插件化复盘（2026-08-27）

> 复盘对象：①「爬虫类适合插件化」判定链；②「把更多站点族按 B 模式接进 crawl-hub」的执行。
> 目的：核对执行与判定是否出现偏误；已发现的问题当场修正并推送。

## 一、判定链复盘（「爬虫类适合插件化」）

| 环节 | 内容 | 复核结论 |
|---|---|---|
| 前提教训 | D20（E:\D20 实验）：单机 GUI 小游戏整体插件化/WebExtension 化不适合（用户拍板） | ✅ 成立（教训已入 MEMORY 插件化选型） |
| 判定标准 | 宿主是否天然「多能力组合 + 频繁增删 + 生命周期可逆」→ 是则插件化 | ✅ 成立，且与 D20 反例自洽 |

**结论**：判定链本身无偏误；「爬虫类适合插件化」是**分层适用**（A 源族 / B 重工具 / 归档脚本），此前执行与之一致。

## 二、B 模式接入复盘（发现 3 处偏误，已修正）

### 偏误 1：manifest 声明了未实际引用的 kit 依赖（已修正）

- image-scraper 的 `kit: {downloader: ^1}` 与 bilibili-helper-py 的 `kit: {session: ^1}` 是**声明了但代码未引用**的依赖——两应用保留内联副本（复制优于共享），并未 import crawler_kit。
- 违反 PLUGIN_SPEC「引用不融合：库有版本，插件声明依赖版本」——声明以引用为前提。
- **修正**：两 manifest 移除 kit 字段（`image-scraper`、`bilibili-helper-py` 已推送）。kit 供**未来新插件**引用，现有应用迁移时再声明。

### 偏误 2：midjourney-video 的 entry 指向 CLI 而非 GUI（已修正）

- manifest/crawlers.json 的 entry 原为 `run.py`（CLI 统一启动器）；crawl-hub 面板「▶启动」语义与其它条目一致应启动 GUI。
- **修正**：entry → `gui.py`；crawlers.json 同步。

### 偏误 3：midjourney-video 的 category 归类为「图片」（已修正）

- MJ 视频助手应归「视频」。**修正**：crawlers.json category → 视频。

## 三、粒度澄清（重要表述勘误）

- 此前汇报用「站点族接入 B 模式」**表述偏误**：实际落地的是 **5 个工具级 B 模式清单**（webcopier / image-scraper / bilibili-helper-py / midjourney-video / sign-in-simulator）——粒度在**工具**，不在**站点**。
- **站点级插件化**实际存在于 image-scraper 内部（A 模式：29 源 JSON 注册表，新增源=一条配置）——那才是「站点族」的插件化落点。
- 修正后的准确表述：**「爬虫工具按 B 模式接入 crawl-hub 启动清单（工具级）；站点族插件化由 image-scraper 的 A 模式源注册表承载（站点级）」**。

## 四、验证

- 修正后 crawl-hub harness 4 用例全绿（config-audit / task-log / plugin-audit / photo-smoke skipped，exit 0）。
- 推送：image-scraper、bilibili-helper-py、midjourney_video、crawl-hub 四仓本地=远端。

## 五、结论

- 判定链 ✅ 无偏误；执行存在 3 处**事实级偏误**（虚标依赖、入口/归类错误）与 1 处**表述级偏误**（站点族/工具级粒度混淆），已全部修正并推送。
- 教训：manifest 是**声明即事实**的清单（组合即数据），写进去的每个字段都必须与代码事实一致——本次「声明未引用的 kit」即是反例；今后接入新插件时，manifest 每个字段先核对代码再用。
