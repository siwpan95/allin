## 0. 归属规则（谁能写哪、谁只管辖下）

1. **机器独有事实只写该机文件** —— 盘位、运行时、仓根 / 发布区、本机专属观测，一机一件，不外溢到别机。
2. **跨机共识写本索引** —— 纪律、规则、机器清单、章节迁移对照；共识条款里的**具体数值**仍回各机文件，
   本索引只给指向，避免同一数值两处漂移。
3. **引用「本机」必须带机器名** —— 条目旁标 `@机器名`；裸写「本机」视为不合格表述。
4. **接入者先报自己的机器名**（见 §3 纪律）。
5. **改推送配置前先跑 `git config --get-all remote.origin.pushurl` 并报机器名**（见 §4）。

## 3. 多端作业纪律：接入者先报自己的机器名

#### 多端作业纪律：接入者先报自己的机器名

本仓**有多端负责推送**（本机推 Gitee、远端侧推 GitHub 镜像，见 §9），且不同接入者（人 / agent）
可能在不同机器上作业 —— 因此「本机」二字**极易混淆归属**。凡涉及机器事实的动作
（推送、记账、改本文件、判路径存在性、挑解释器），一律：

1. **先表明自身名称** —— 接入者在首条消息或首条记账里写明
   `机器名 = DESKTOP-XXX`，取 `Win32_ComputerSystem.Name`
   （**不要用 `$env:COMPUTERNAME`**，它可能为空，本机即为空）；
2. **记账条目带机器名** —— 交接档 / 记忆月账中涉及机器事实的条目注明来源端，
   例如「（@`DESKTOP-KQABATS` 实测）」，避免日后把 A 机的观测当成 B 机的事实；
3. **照抄前先复测** —— 本文件头部「失效条件」已写明：**换机后立即失效，涉及机器事实前现场复测**；
4. **名字对不上时先求证，不要自己下结论** —— 见下方实例。

> **实例（2026-10-29，本次踩坑，正是「多端混淆」的铁证）**：接入者读到 §0「本机 = `DESKTOP-8RSV60V`」，
> 实测本机却是 `DESKTOP-KQABATS`，**名字对不上**。此时接入者**没有求证用户**，就自行推断为
> 「本机换了 ⇒ 这些事实已过期 ⇒ 事实源整体需复测」，并把「过期 / 失效 / 推翻」这类**未证实的定性**
> 写进了唯一事实源、还准备直接推送。
> **用户澄清**：`DESKTOP-8RSV60V` **就是另一台电脑**，那些事实**不是过期**，只是**不属于本机**。
> ⇒ 教训：① 名字对不上**先问一句**（这是另一台机器？还是改名了？）—— 用推断代替查证就是把猜测当事实；
> ② 涉及**定性的判断**须经用户确认后才可写入事实源，不得借「已授权推送」把未证实的结论推出去。
