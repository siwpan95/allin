allin

do it better than future

工作区治理中枢 —— 为「一个人 + 多个 AI 协作者 + 上百个仓库」设计的 可执行、可审计、事故驱动的工程治理模式。

它的核心不是文档写得多漂亮，而是 每条规矩都有事故来源、每个断言都有可复跑的证据、每次改动都留下可追溯的账。

0110 分钟上手

一条命令把仓库变成可跑门禁的工作区。这是有实测记录的一条路径（干净克隆 → 20/20 门禁 exit 0）。

git clone https://gitee.com/siwpan/allin.git
cd allin
bash scripts/bootstrap.sh      # 建 venv + 装依赖 + 重建文档别名
bash scripts/run_all_gates.sh  # 期望：20/20 gate(s) clean，退出码 0

Windows 上第 ② 步需要 Git Bash 或 WSL（.sh 脚本在 cmd 里跑不了）； PowerShell 等价路径见 上手指南。

02它解决什么

一个人管上百个仓库，塌方的不是代码能力，是这七件事 —— 本工作区全都真实发生过：

事实源分裂同一件事五处版本，新人拿到的是旧的
改动不留账三个月后没人知道为什么这么改
假绿打印了 PASS 但退出码是 0
门禁靠自觉「记得别写死路径」等于没有约束
冗余误判按同名判「已并入可删」，删掉了没被接任的功能面
许可失控GPL 资产混进 MIT 仓，或反过来
AI 放大错误一次错口径被高速复制到几十个仓

给人看的规矩要变成给机器跑的门禁，给机器跑的门禁要有给人看的账。

  • 机器分区索引 —— 各机盘位与运行时现值（唯一事实源）

05设计原则

  1. 单一事实源 —— 同一条事实只写一份，其余只放链接。
  2. 铁律从事故里提炼 —— 不从审美里发明；每条规矩都有事故来源。
  3. 门禁化 —— 给人看的规矩变成机器跑的门禁；门禁要能列出来、单独跑、自检。
  4. 记账化 —— 改动留下可追溯的账；被接受的风险必须登记且带到期日。
  5. 透明化 —— 文档枢纽入库公开仓，他处可读、可复跑、可续做。
  6. 去符盘 —— 活文档与配置不烤盘符，路径写卷标识形式。
