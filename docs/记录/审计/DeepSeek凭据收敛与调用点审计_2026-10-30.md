## 四、受管密钥库设计（`C:\Users\psw\.dsvault`）

```
C:\Users\psw\.dsvault\
  ├── deepseek_vault.py   独立 CLI（只此一处依赖 cryptography）
  └── vault.enc           AES-256-GCM 密文：[salt 16B][nonce 12B][ct+tag]
```

- **双层防护**：① 解锁口令经 Git Credential Manager 存 **Windows 凭据管理器**（wincred/DPAPI，当前用户可解、他用户/他机无效）；
  ② 库体 `vault.enc` 用 **AES-256-GCM** 加密，主密钥由口令经 **PBKDF2-HMAC-SHA256**（200 000 轮）派生。
- **仅手动触发**：不注册任何计划任务/后台进程。消费方在用户主动运行时以子进程
  `python3 deepseek_vault.py get <key>` 取明文，进程退出即清零，**不落盘**。
- **依赖解耦**：只有 vault CLI 需要 `cryptography`；消费方（write-agent/ollama 各自 venv）
  统一以**绝对路径**调用已装该库的解释器，无需各自安装。
- **防挂起**：`git credential fill` 在凭据缺失时会转交互式提示而挂起，
  故 CLI 内用 `subprocess.run(timeout=8)` 截断，并转成明确的"未初始化"错误。
- 子命令：`init / set / get / list / delete / rotate-passphrase`。

### 实抄验证（本次实测）

- `init` → `set` 两把 → `get` 往返一致；
- **明文确认不在密文中**（对 `vault.enc` 做字节级检索，两把旧 key 与新 key 均 `not present`）；
- 轮换后旧 key 亦不可恢复；
- 消费方（ollama、write-agent venv 解释器）**实测解析到新 key**。

## 九、事故：`icacls` 破坏 `.deepseek-vault`（根因已订正，遗留一项）

- **经过**：为做"仅属主可访问"加固，在 `C:\Users\psw\.deepseek-vault` 上执行了 `icacls`；
  一次 `/inheritance:r` 生效而后续 `/grant` 失败 ⇒ 目录下文件**ACL 被清空成空 DACL**。
- **后果**：`deepseek_vault.py`、`vault.enc` 变为**不可读、不可改、不可删**
  （`rm`、`Remove-Item`、`Set-Acl`、`icacls /reset /T` 均"访问被拒绝"；
  `.py` 属主为 `BUILTIN\Administrators`）。
- **⚠️ 根因订正（2026-10-30 实测，推翻初判）**：
  初判"本机 `icacls`/`takeown` 是 PortableGit 残缺实现"**是错的**。
  真凶是 **Git Bash (MSYS) 的 POSIX→Windows 路径自动转换** ——
  `/grant`、`/F`、`/T` 形似 POSIX 绝对路径，被改写成
  `F:/workbuddy/resources/vendor/PortableGit/grant` ⇒ 报"非法开关"。
  ⇒ **解法：`export MSYS_NO_PATHCONV=1` 后再调 `C:/Windows/System32/icacls.exe`**，
  开关即可正常解析（实测 `/grant`、`/reset /T` 均被正确识别）。
- **但开关修好后仍清不掉**：`/grant` 仍"拒绝访问"、`/reset /T` 只处理了目录本身、子元素仍拒 ——
  因**空 DACL + 非提权令牌**，连属主的隐式 `WRITE_DAC` 都不生效 ⇒ **必须提权会话**。
- **处置**：密钥安全未受影响（库体是密文，口令在 DPAPI 凭据管理器；旧口令已被覆盖、
  旧密文成**不可恢复的死数据**），故**弃用旧目录、在 `C:\Users\psw\.dsvault` 重建**。
- **教训**：① 在 Git Bash 调 Windows 命令行工具且参数含 `/xxx` 开关时，**必加 `MSYS_NO_PATHCONV=1`**；
  ② **不要对凭据目录做 ACL 加固** —— 安全由"密文 + DPAPI 口令"保证，文件 ACL 非必需。
