### 架构重构：消除全部硬编码注册表，实现零修改添加新效果
**目标**: 确保可以仅通过增加JSON来增加内容，无需逐个修改Python文件

**改造内容**:
- `render_system.py`: 
  - 新增 `@register_effect(id, name, category, background)` 装饰器 + `_EFFECT_META` 全局字典，在类定义时自动收集元数据
  - 新增 `@register_theme(id, name, description)` 装饰器 + `_THEME_META`，同样自动收集
  - 删除硬编码 `_CLASS_MAP` (47条目)，改为 `_build_class_map()` 使用 `VisualEffect.__subclasses__()` 自动构建
  - 删除硬编码 `_THEME_CLASS_MAP` (3条目)，改为 `_build_theme_map()` 使用 `BackgroundTheme.__subclasses__()` 自动构建
  - 所有47个效果类添加 `@register_effect(...)` 装饰器，3个主题类添加 `@register_theme(...)` 装饰器
  - `BACKGROUND_THEMES` 改为空字典，由 `load_background_themes()` 填充
  - 导出 `get_effect_meta()` / `get_theme_meta()` 给工具使用

- `effects/generate.py`: 完全重写
  - 不再维护 EFFECTS 列表(47条目)和 CLASS_NAME_MAP(47条目)
  - 通过 `get_effect_meta()` 自动发现所有已注册效果
  - 按 effect_id 去重匹配现有JSON，仅生成缺失项
  - `--force` 模式重新生成所有
  - 保留原效果编号顺序（按类定义顺序）

- `tools/auto_registry.py`: 新建
  - 扫描 effects/*.json 与 Python 类双向对齐检查
  - 报告: 多余JSON、缺失JSON、类名拼写错误、分类统计
  - 全自动，无需手动维护任何检查规则

**添加新效果的两种方式**:
  1. 全新效果: 定义 `@register_effect(...)` 类 → 运行 `python effects/generate.py` → 完成
  2. 参数化变体: 在 effects/ 创建JSON，`class` 指向已有类名 → 自动加载

**测试结果**:
- auto_registry.py: 47 Python类 ↔ 47 JSON文件 完全对齐
- generate.py: 正确跳过47个已有，仅生成缺失项
- 端到端测试5项全部通过（类发现、元数据、注册表加载、动态新类+JSON、参数化变体）
- 结论: 添加新效果无需修改任何注册表或映射字典
