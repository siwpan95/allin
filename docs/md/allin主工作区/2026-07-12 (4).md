### 关键路径陷阱（已解决）
- import 独立引擎必须把**父目录 `D:\allin`** 注入 sys.path，不能塞 `D:\allin\allin_engine`（否则找 `D:\allin\allin_engine\allin_engine` → ModuleNotFoundError）。

- 可选依赖只在函数内部 import，缺则调用期 ImportError，不是 import 期失败。

### 发现的真实引擎缺陷（重要）
- `synth.note_to_freq` 归一化 `name.replace("B","b")` 把大写 B（自然音）整体转小写，而查表字典键是大写 `"B"` → **自然音 B（B3/B4…）与降 B（Bb）全部查表失败 ValueError**。
- 影响：MENU/BATTLE/BOSS/VICTORY 四个音乐预设含 B 音列，**全无法生成 WAV**；仅 DUNGEON/AMBIENT（不含 B）可跑。
- 比之前误判的"不支持重降"严重得多——是整个 B 音列崩溃。
- 探针里用不含 B 的自然音+升号旋律（且 melody 单遍压到 0.5s 使 load 秒数=真实音频秒数）绕开该 bug 测出正常路径吞吐。

## 针对 5 项架构短板做增强（测试台内扩展，不碰共享核）

用户明确落点：**在 engine_limit_probe 内新增扩展模块，不修改 D:\allin\allin_engine 共享核**（契合"复制即复用 / 不碰共享核"哲学，零耦合风险）。

### 增强模块（`engine_limit_probe/enhancements/`）
- `e1_pathfinding.py`：GraphPathFinder（图 BFS/Dijkstra/A*）+ grid_astar（MapData 网格 A*，4/8 连通）。
- `e2_world_serial.py`：SerializableWorld(World)，对齐引擎 to_dict/from_dict 契约，可直接交 SaveLoadManager 存档；catalog 注册组件/系统类反序列化。
- `e3_particles_np.py`：NumpyParticleSystem，numpy 向量化物理+力场，对齐 ParticleSystem 核心 API。
- `e4_deps.py`：feature_flags() / require() / MissingDependencyError（带安装提示），替代散落调用期 ImportError。
- `e5_note_parser.py`：fixed_note_to_freq（按"字母+升降号计数"算半音，根治 B 音列 bug）+ patch_synth() 热补丁（同时替换 synth.note_to_freq 与 music_gen.note_to_freq，因 music_gen 用 `from ... import` 绑定了名字）。

### 验证结果（verify_enhancements.py，5/5 通过）
- E1：图/网格路径合法，加权 Dijkstra 正确避高价边选最廉路径。
- E2：World 存档往返一致，系统重建后 update 正常自增。
- E3：20 万粒子 120 帧，引擎 1.80s vs numpy 0.13s ≈ **13.6x** 加速（活跃数一致，验证 faithful）。
- E4：依赖探测正常，缺失抛干净 MissingDependencyError。
- E5：B3/B4/Bb4/bb2 解析正确，patch 后 MENU 成功生成 WAV。
- 结果写入 `results/enhancement_results.json`；报告新增"增强实现"章节，5 项短板标记〔已增强/已修复〕。

### 关键实现注意
- 引擎已有 `Serializable` 基类（core/serializable.py，dataclass 用），但 World 是普通类没继承——增强用独立 to_dict/from_dict，不强行继承。
