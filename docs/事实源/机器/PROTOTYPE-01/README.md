## 为什么有这个目录

2026-10-30 之前，本仓只有一份 `本机事实.md` —— 「本机」指的就是「当时干活的那台」，
**没有机器维度可归**。2026-09 与 2026-10-01 ~ 10-29 的活确实干过、也有交接卷为证，
但**归不到三台真机的任何一台**（作者身份全同、提交信息无机器字段、交接卷 23 节全无标注）。

把这些活摊给三台里任意一台，都是**替该机认领它没做的活**；全部丢掉，则**该月的历史凭空消失**。
⇒ 设一台**虚构的归档机**承载它们，并在本目录把「它是虚构的」写死，让后来者不可能误会。

## 三律（读本目录前先读这三条）

1. **它不是机器**：无 hostname / 无硬件 / 无运行时 —— **以本卷为主体自测**的判据只能答「不适用」。
   但它的**残留可以在承载机上被他测**：`F:\` / `G:\` 现接于 `@DESKTOP-8RSV60V`，
   该机是本机最权威的原型机残留载体，实测清单见 [`PROTOTYPE-01.md`](PROTOTYPE-01.md) §5.1。
2. **它不是第四台机**：机器清单里排在真机之后、标 `kind: archive`；「三台机」的表述不因它改口。
3. **它是虚构的**：代号 `PROTOTYPE-01`（ASCII，避免路径与判据在 CJK 上出岔），中文名「原型机」。

## 承接边界

**只承载 `< 2026-10-30`**；分机之后的一切工作不得记入本卷。

## 与 `DESKTOP-8RSV60V` 的关系：承载 ≠ 产出

原型机的外置盘（`F:` / `G:`）现接于 `@DESKTOP-8RSV60V`。在该机上能看到 `G:\repos`、`G:\archive`、
`G:\nodejs` 等痕迹 —— **那是「盘在谁那儿」，不是「活是谁干的」**。
8RSV60V 的产出以该机自己的分区文件时点块与月账为准，**不以盘上存量为准**；
`G:` 上的仓数**不是该机的业绩指标**。
