# Bee Idle RPG 完善方案（精简版）

> **完善对象**：`C:/Users/13122/Desktop/stay/bee`（全自动挂机放置游戏）  
> **参考来源**：末日危机1 + 末日危机2 中文版  
> **核心原则**：最小侵入，保留原有自动挂机特色，不改变玩家「只观看」的体验  
> **关键参考机制**：末日危机2 的 re-infestation（入侵/滋生）——"If there are no infested dungeons to clear, a cleared, unsecured dungeon will be re-infested." 地牢买不起城堡就滋生怪物，无通关，永无终点

## 零、Bee 现有的自动循环（不能破坏）

```
┌─────────────────────────────────────────────────┐
│  50ms tick 主循环                                │
│  ┌─────────┐  ┌──────────┐  ┌───────────────┐  │
│  │ 自动战斗 │→│ 自动拾取  │→│ 自动区域切换   │  │
│  │1.5s间隔 │  │8s间隔掉落│  │30s间隔,30%概率 │  │
│  └─────────┘  └──────────┘  └───────────────┘  │
│  ┌─────────┐  ┌──────────┐  ┌───────────────┐  │
│  │ 自动回血 │  │ 自动任务  │  │ 地标/历史发现 │  │
│  │2%/3%每秒│  │接取+进度  │  │30s/60s间隔    │  │
│  └─────────┘  └──────────┘  └───────────────┘  │
│                    ↓                            │
│              重绘 Canvas UI                     │

```

**原则**：所有 6 个新增系统都作为这个循环的**旁路挂载**，不修改主循环结构，不增加玩家必选操作。

## 一、组队系统 —— 最小侵入方案

### 不做什么
- ❌ 不让玩家手动控制队员
- ❌ 不增加复杂的队伍编队 UI
- ❌ 不改变"战斗 → 掉落 → 升级"的内核

### 做什么

```
已有逻辑：单角色自动攻击怪物，1.5s 间隔
改动方案：在战斗 tick 中追加队友攻击，不改动玩家角色的逻辑
```

**具体实现**：

```
M1.1  角色创建后自动招募
      ├── 第一次进入游戏时，创建完主角后
      ├── 自动生成 2-3 名队友（随机种族+职业，当前区域等级适配）
      ├── 玩家无需选择，队友自动加入
      └── 后续在定居点可花金币「替换」队友（非强制）

M1.2  队友战斗逻辑
      ├── 共享玩家角色的攻击间隔计时器（1.5s）
      ├── 每次 tick 时：
      │   ├── 玩家角色执行原有攻击逻辑（不变）
      │   ├── 遍历每个存活队友，各自攻击当前敌人
      │   └── 队友伤害 = 自身属性计算（复用现有 combat_service）
      ├── 队友死亡后自动复活（50% HP，3s 后），复用现有逻辑
      └── 队友不触发任务进度（只有玩家角色才计数，保持任务系统不变）

M1.3  UI 影响（最小）
      ├── 右侧面板增加「队伍」折叠区域
      │   └── 显示队友名称+HP条，默认折叠不打扰
      ├── 战斗日志自动标注发言者：
      │   └── 「[法师·莉莉] 对 哥布林 造成 12 点伤害」
      └── 原有主面板不变
```

**侵入性评估**：combat_service.py 增加 ~30 行循环，game_controller.py 增加 ~50 行 UI

## 二、地牢系统 —— 替换"区域切换"

### 核心思路

Bee 现有的「30s 自动区域切换」本质上就是一个**无视觉的自动地牢探索**。用地牢系统替换它，但不改变自动性质。

```
已有逻辑：30s 间隔 → 30% 概率切换区域 → 更新敌人 + 地标发现
改动方案：30s 间隔 → 自动进入下一个房间 → 房间清空后自动去下一地牢
```

### 做什么

```
M2.1  概念替换（不改代码结构）
      ├── 原「区域切换」→ 改为「地牢内房间推进」
      ├── 原「区域清空」→ 改为「地牢清空」
      └── 原 Bee 的 15 个程序化区域保持不变，只是重新解释

M2.2  地牢与房间的自动流转
      │   当前区域有 2-4 个地牢
      │   ↓ 自动进入第一个地牢
      │   地牢有 5-15 个房间（危险等级决定）
      │   ↓ 每 30s 自动进入下一房间
      │   每个房间随机敌人（复用现有敌人模板）
      │   ↓ 清空所有房间 → 地牢清空
      │   自动进入下一个地牢
      │   ↓ 清空所有地牢 → 区域清空
      │   自动进入相邻区域
      └── 玩家全程观看日志，不需要点任何按钮

M2.3  房间内容（自动触发）
      ├── 30% 概率房间有宝箱 → 自动打开 → 装备掉落（复用现有 loot 逻辑）
      ├── 20% 概率房间有药水架 → 自动拾取药水
      └── 10% 概率精英房 → 怪物数量翻倍

M2.4  UI 改动
      ├── 左侧日志顶部加一行状态条：
      │   └── 「黑岩山脉 ▸ 暗影洞穴 [房间 3/8] ▸▸▸」
      └── 替换原有简单的区域名称显示
```

**侵入性评估**：world_service.py 增加 ~60 行地牢生成，game_controller.py 修改 ~40 行区域切换逻辑

## 三、药水系统 —— 全自动生效

### 核心思路

既然 Bee 是全自动挂机游戏，药水也应该**拾取即自动使用**，而不是让玩家手动点击。这符合 Bee 的设计哲学。

```
已有逻辑：怪物掉落装备 → 自动拾取 → 自动装备
新增逻辑：怪物掉落药水 → 自动拾取 → 自动激活 → 持续时间内生效
```

### 做什么

```
M3.1  自动药水循环
      ├── 怪物掉落药水（5% 概率，复用装备掉落体系）
      ├── 拾取后自动激活，立即生效
      ├── 持续时间结束后自动消失
      └── 同时只能激活 3 种药水（多余的存入背包，自动替换）

M3.2  保留的 10 种全自动友好药水
      │   双倍金币         │ 怪物多掉一堆金币         │ 自动生效，无需玩家操作 │
      │   双倍物品         │ 怪物多掉一件装备         │ 自动生效               │
      │   脆弱怪物         │ 怪物属性降低             │ 自动生效               │
      │   温顺怪物         │ 怪物几乎不还手           │ 自动生效               │
      │   物品价值提升     │ 品质权重上移             │ 自动生效               │
      │   100% 物品掉落    │ 每只怪物必掉装备         │ 自动生效               │
      │   更多怪物         │ 每个房间怪物+10          │ 自动生效               │
      │   免费施法         │ 技能不耗精神力           │ 自动生效               │
      │   加速探索         │ 房间推进间隔减半(15s)    │ 自动生效               │
      │   更多经验         │ 经验获取 +50%            │ 自动生效               │

M3.3  被砍掉的药水（需要手动操作，不符 Bee 理念）
      ├── 自动发射卷轴 → Bee 没有卷轴系统，先不做
      ├── 随机宝藏房间 → 并入地牢房间内容生成
      ├── 随机Boss战    → 并入精英房机制
      ├── 无限卷轴       → 同上，无卷轴
      └── 药水延长       → 通过冒险点数实现

M3.4  UI 改动
      ├── 右侧面板显示当前激活的药水 + 剩余时间
      ├── 纯信息展示，无操作按钮
      └── 日志播报：「✨ 自动使用了【双倍金币】药水（剩余 120s）」
```

**侵入性评估**：新增 potion_service.py ~100 行，game_controller.py UI 增加 ~30 行

## 四、城堡农场 + 入侵循环 —— 永无止境的自动征战

### 核心思路

末日危机系列没有「通关」，核心是 **re-infestation（入侵/滋生）** 机制：已清空但未购买城堡守护的地牢，会重新滋生怪物，队伍需要折返清理。城堡的作用是「锁死」该区域不让怪物回来，而非胜利条件。

Bee 的程序化世界恰好适合这个模型：可以不断生成更高等级的新区域，永无止境。

```
已有逻辑：区域切换 → 永远往前推进 → 无回头
新增逻辑：
  清空地牢 → 金币够 → 自动买城堡守护 → 该区域锁死
           → 金币不够 → 跳过 → 地牢随后被入侵滋生 → 折返再清理
  无休止循环：更高的区域 → 更贵的城堡 → 更多滋生 → 更强的队伍
```

### 做什么

```
M4.1  区域清空自动触发
      ├── 某个区域所有地牢清空后
      ├── 自动扣除金币购买城堡（金额 = 区域危险等级 × 500）
      ├── 如果金币不够 → 跳过，后续区域清空时再试
      ├── 购买后该区域自动变为农场
      └── 全自动，不需要玩家确认

M4.2  农场自动收益（tick 内挂载）
      ├── 每个已转化的农场区域
      ├── 每秒产出：金币 × (危险等级 × 0.5)
      ├── 产出直接加到玩家金币，不做单独结算
      └── 日志每 60s 汇总一次：「🏰 农场产出：+125 金币（来自 3 个农场）」

M4.3  城堡守护者（Boss 自动战）
      ├── 购买城堡后自动触发守护者战
      ├── 守护者 = 该区域最高等级敌人模板 × 1.5 属性
      ├── 战斗逻辑复用现有自动战斗（无特殊处理）
      └── 击败后区域变为「已征服」，农场效率 +50%

M4.4  入侵/滋生循环（核心无限玩法）
      ├── 参考末日危机系列的 re-infestation 机制
      ├── 有城堡守护的区域 → 永久安全，不会滋生怪物
      ├── 无城堡守护的已清空地牢 → 会自动滋生怪物（入侵）
      │   ├── 触发条件：当前无怪物可打 且 不存在未清空地牢时
      │   ├── 随机选择一个已清空但未守护的地牢，标记为「被入侵」
      │   └── 队伍自动返回该地牢重新清理
      ├── 这创造了一个无限循环：
      │   └── 清空 → 买不起城堡 → 滋生 → 再清空 → 攒钱买城堡 → 继续推进
      ├── 持续增加新区域（Bee 程序化世界可不断生成更高等级区域）
      └── 没有「通关」概念，只有「当前最高征服区域」记录
```

**侵入性评估**：新增 castle_service.py ~80 行，game_controller.py tick 增加 ~5 行农场结算

## 五、成就系统 —— 纯被动追踪

### 核心思路

成就是最不侵入的系统：只读、只记录、只在达成时弹一条消息。

```
新增逻辑：在关键事件点插入成就检查 → 达成时播报 → 给予奖励
```

### 做什么

```
M5.1  成就检查点（在现有逻辑上挂钩子）
      ├── 击杀怪物时  → 检查「总击杀数」类成就

M5.2  成就奖励（全自动发放）

      ├── 奖励自动发放：金币/经验/冒险点数
      └── 不打断游戏流程，弹窗 3s 后自动消失

M5.3  初始设计 20 个成就
```

## 六、神器系统 —— 纯被动 Buff 池

### 核心思路

神器就是永久被动 Buff，获得后自动生效，不改变任何操作。

```
新增逻辑：特定事件触发神器掉落 → 自动加入神器池 → 永久生效
```

### 做什么

```
M6.1  神器获取（全部自动触发）
      ├── 守卫者 Boss 击杀 → 100% 掉落 1 件
      └── 地牢清空 → 5% 概率掉落

M6.2  神器效果（纯被动，自动生效）
      │   战神拳套     │ 物理伤害 +15%         │ 守卫者掉落           │
      │   魔法残页     │ 法术伤害 +15%         │ 守卫者掉落           │
      │   幸运硬币     │ 掉落率 +10%           │ 地牢清空             │
      │   守财奴钱袋   │ 金币 +20%             │ 地牢清空             │
      │   贤者之石     │ 经验 +25%             │ 守卫者掉落           │
      │   猎人之眼     │ 农场产出 +50%         │ 地牢清空             │
      │   不朽之盾     │ 全队防御 +15%         │ 守卫者掉落           │
      │   商人之证     │ 城堡价格 -30%         │ 地牢清空             │

M6.3  生效方式
      ├── 神器池是一个 dict[str, bool]，key = 神器名, value = 是否已获得
      ├── 战斗计算时自动读取神器池，应用对应加成
      │   └── 例如：combat_service 中 if '战神拳套' in artifacts: damage *= 1.15
      ├── 不需要装备，不占槽位
      └── 获得时日志播报：「🏺 获得神器：战神拳套 — 物理伤害永久 +15%」

M6.4  UI 改动
      ├── 右侧面板增加「神器」折叠区域
      │   └── 显示已获得神器列表（名称 + 效果），默认折叠
      └── 纯信息展示
```

**侵入性评估**：新增 artifact_service.py ~60 行，combat_service.py 增加 ~10 行加成计算
