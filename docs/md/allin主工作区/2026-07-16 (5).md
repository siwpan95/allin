## 修复 slideshow/kenburns 黑场频闪（真·交叉淡入淡出）
- 症状：用户反馈淡入淡出「闪烁频率太快」。根因：旧实现每张段都 `fade=t=in`+`fade=t=out` 再 concat 拼接 → 每张图之间都闪一下黑场（dip-to-black），多图连放成频闪；KenBurns 推镜也被黑缝切断。
- 正确做法（联网核对 ffmpeg 官方 xfade 配方）：改用 xfade 滤镜链做真交叉淡入淡出——上一张淡出时下一张同时淡入，全程无黑场。
  - 两遍：Pass1 逐张编码为统一 W×H/fps/yuv420p 片段（KB 推镜烤进片段、不加 fade）；Pass2 用 `[i-1][i]xfade=transition=fade:duration=T:offset=i*(D-T)` 链式拼接。
  - offset 公式 offset_i = i*(D-T)，总时长 = N*D-(N-1)*T（实测吻合：5图→8.4s、4图KB→9.0s）。
  - D、T 量化到帧网格（round(x*fps)/fps）避免 xfade 边界四舍五入抖动/黑缝。
  - ffmpeg 11 必带：所有 xfade 输入同分辨率/fps/sar + 显式 `-map "[outv]"`；首尾各加一次温和 fade（仅边界，不引起频闪）。
  - 进度：Pass1 按张数推进到 80%，Pass2 用 `-progress pipe:1` 推到 100%。
- 验证（blackdetect d=0.01）：输出仅 t=0 处 0.08s 黑（开场淡入），**中段零黑场**；旧实现会在每张图间隙都出现黑闪。py_compile 通过。样本：t_xfade.mp4(640x360/8.4s)、t_kb2.mp4(640x360/9.0s)。

## 修复 横向/纵向滚动 频闪 + 视觉错觉（h/v 模式）
- 用户反馈：内容多了之后快速闪频、甚至错觉以为一直是相同内容。根因（联网核对，两个独立问题）：
  1. **平移速度失控**：时长被 `_read_common` 固定为 10s，与内容长度无关。内容一长，travel/10 达数百~上千 px/s → 车轮效应/频闪 + 错觉。crop 数学本身正确，错在速度无上限。
  2. **逐帧重采样抖动**（videofoot.xyz 记载的「panning/zoom 抖动」）：大图平移时每帧重采样 → 闪烁。标准解法是**超采样**（高分辨率上平移、结尾降采样）。
- 修法：
  - 新增「滚动速度(px/秒)」滑块（h/v 各一个，默认 160px/s）。`_scroll_duration(travel, speed_var, fallback)`：travel<=0 用共享时长；设了速度则 duration=travel/speed（匀速、每格停留可控）；速度=0(自动)则按安全上限 300px/s 推算。
  - `_cmd_static` h/v：先 `scale=iw*S:ih*S`（S=2 若单边<=8000，否则 1 防内存爆）再 `crop` 平移，结尾 `scale=ow:oh` 降采样 + `setsar=1`。grid 分支也补 `setsar=1`。
- 验证：154 张图目录下取 N=9/25。实际滚动速度精确=160px/s（旧：225/875/**1634**px/s，纵向 1634 正是频闪元凶）。输出：t_hscroll 1280x520/54.72s、t_vscroll 520x720/102.12s、t_hs2(超采样S=2) 1280x520/14.08s 均 h264 yuv420p。py_compile 通过。
- 六模式体检：grid(静止定格,无闪)、h/v(已修)、slideshow/kenburns(已修xfade)、highlight(逐格叠加+enable 顺序高亮,复查无闪) —— 其余模式未见遗留频闪类问题。
