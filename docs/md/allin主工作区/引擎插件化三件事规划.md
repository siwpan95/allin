## 1. 三件事总览

源自 deepseek-harness/Cordis 的三个核心机制，对应关系与总路线：

| # | 机制 | 一句话 | 引擎落点 | 解决的真实痛点 |
|---|---|---|---|---|
| A | **注册即回滚**（可逆装配） | 每个系统声明依赖、注册能力、卸载自动撤销 | 微型内核 + GameEngine 兼容层 | add_* 硬编码装配、shutdown 手写遍历、G:\game 的 Position 类身份错乱 |
| B | **补丁即差异**（分层组合） | 引擎=基础层，项目改动=显式 patch 文件 | preset 数据化 + patch 覆盖 + `--dump-profile` | 两个全量副本 17 文件漂移（全为 games 侧更新）、内联副本升级无从对齐、改动沉在副本里不可见 |
| C | **日志即事实源**（事件源） | 世界事件追加日志是唯一事实源，存档/回放/审计都是它的投影 | EventBus 升级 + WorldLog + SaveLoad 接入 | debug 历史只是调试功能、存档=快照孤立、无回放、AI 代理定位 bug 靠读代码 |

**优先级：P0 对比整合 → P1 A → P2 B → P3 C → P4 改名 alloy**（A 是地基，B 依赖 A 的装配能力，C 独立但受益于 A 的作用域；双副本整合提前为 P0 止血；改名按要求放在最后，作为"补丁重放 + 全仓库引用迁移"的总演练）。

**硬约束（贯穿三件事）**：
- 全部**纯标准库**实现，不引入第三方依赖（内核约 150~250 行）；
- 现有 `GameEngine.add_*`、`EventBus`、`World` 等公开 API **全部保持兼容**，新能力并行新增；
- 不动 100+ 存量项目，只有引擎本体变化；
- 尊重"复制优于共享"：patch 机制给"复制"加**差异可见性**，不是改成共享依赖。

## 2. 第一件事 A：注册即回滚（可逆装配内核）

> ✅ **已完成（2026-08-23）**。落地：`core/context.py`（Context/provide/get/effect/dispose 栈/child/unload/install）、`core/plugins.py`（插件协议 + 6 个标准 preset）、`GameEngine` 全部 add_* 改为 preset 装配并新增 `mount()/unload()`、`EventBus` 新增 waterfall/serial 分派模式。验证：全量测试 352 项 351 通过（唯一失败 = 基线既有的无头 Tk 测试），26 个新内核测试全绿，example_quickstart 6 个示例全过。

### 2.1 目标

把 `GameEngine` 从"硬编码装配器"升级为"上下文（Context）+ 声明式插件"，同时 100% 兼容现有 `add_*` 用法。核心算子只有三个：**provide（注册服务）→ inject（声明依赖）→ dispose 栈（注册自动可回滚）**。

### 2.2 设计要点

```python
# 新增 core/context.py（草案，仅规划）
class Context:
    def provide(self, key, service, *, dispose=None) -> None: ...  # 注册并压入 dispose 栈
    def get(self, key): ...                                          # 依赖查找，缺失即装配期报错
    def effect(self, fn) -> None: ...                                # 注册可逆副作用，随作用域销毁自动撤销
    def child(self) -> "Context": ...                                # 作用域：子上下文，销毁时回滚全部注册

# 插件形态：模块级 name/inject/apply —— 与 harness 插件同构
#   name = "inventory"; inject = ["world"]
#   def apply(ctx, config): ctx.provide("inventory", Inventory(), dispose=inv.flush)

# GameEngine 兼容层：add_* 变成预设（preset）函数，内部调同一套注册原语
#   engine.add_systems()  ≈  preset_systems(engine.ctx)
# 新增卸载能力：engine.unload("audio") —— 自动执行其 dispose，世界状态不脏
```

配套两件事（同一内核内）：
- **事件分派模式**（与 C 合用）：在 EventBus 上增加 `waterfall`（中间件：可拦截/改写，如"伤害结算"允许 Mod 挂拦截器）与 `serial`（可短路投票，如"能否通过这扇门"）；现有 `emit` 语义不变。
- **装配期校验**：inject 缺失、循环依赖、重复 provide，全部在装配期报清晰错误（而非运行时 AttributeError）。

### 2.3 落点文件（新模块，不动旧文件）

- `core/context.py` —— Context/provide/inject/effect/dispose 栈（~100 行）
- `core/plugins.py` —— 插件协议（name/inject/apply）与 preset 定义（~80 行）
- `core/context_test.py` 或并入 test/ —— 行为测试
- `__init__.py` 仅新增导出；`GameEngine` 内部改挂到 Context，**公开方法签名不变**

### 2.4 阶段

1. **A1 内核**：Context + dispose 栈 + child 作用域，纯标准库，含测试（挂载/卸载/嵌套回滚）。
2. **A2 兼容桥**：GameEngine 改为 Context 持有者，`add_*` 全部改为 preset 函数；现有 292 个引擎测试全绿。
3. **A3 分派模式**：EventBus 增加 waterfall/serial（供 C 使用），emit 语义不变；补行为测试。

### 2.5 验收

- 292 个现有测试零回归；新增 ≥20 个内核行为测试；
- 演示：`engine.unload("audio")` 后音频资源被释放且引擎继续运行（对应现在 shutdown 只能整机关停）；
- 演示：一个"伤害结算" waterfall 插件能在不改引擎代码的情况下把攻击力翻倍。

### 2.6 风险与对策

- **风险**：String-key 注册失去类型检查。**对策**：常量类集中定义 key（现有 EventTypes 的做法），装配期校验防拼写错误。
- **风险**：dispose 顺序错误（依赖方先于被依赖方销毁）。**对策**：dispose 栈按注册逆序自动回滚（Cordis 同款语义），不需要手写顺序。

> ✅ **已完成（2026-08-23）**。落地：`core/config_loader.py`（纯标准库 YAML 子集，BOM 容忍）、`core/profiles.py`（4 个 profile + 装配报告）、`cli.py`+`__main__.py`（`dump-profile` 文本/JSON、`sync` dry-run/apply + `--reference` 区分"过期/定制" + `--take-base`）、`engine.patch.yaml` 落盘。试点结果：**dwarf_scrolls**（sync 53 文件：新增 23/过期 16/以本体为准 14；回灌 Snapshotable + SHARD_HIDDEN/QUEST_COMPLETE + 默认字体稳定化到本体；项目 pytest 86/86、内联引擎 352/353）；**mahjong**（sync 37+3 文件，定制仅 2 个自有字体；项目 pytest 11/11、内联引擎 352/353）。唯一失败均为基线既有的无头 Tk 测试。

### 3.1 目标

引擎本体的改动与**每个项目的定制改动**分离：项目内联引擎时只保留一份**显式 patch 清单**，引擎升级 = 换新本体 + 重放 patch，冲突可见、可 diff、可审计。

### 3.2 设计要点

- **preset（预设）数据化**：`engine.yaml` 列出本项目装配的插件清单（复用 A 的插件协议）：

  ```yaml
  # 项目根 engine.yaml（草案）
  profile: rogue-lite
  plugins: [core, world, systems, combat, ai-brain]
  config:
    combat.enemy_scale: 1.2        # 覆盖引擎默认
  ```

- **patch 文件**：`engine.patch.yaml` 记录"本项目对引擎副本做过哪些修改"（文件级 diff 摘要 + 配置覆盖）。引擎本体保持"原样可再生成"，项目定制全部落在这一个文件里。
- **`--dump-profile`**：`python -m <新名> --dump-profile` 打印实际装配树（挂了哪些系统、哪些配置被覆盖、哪些可选能力因缺依赖未挂载）。**这是给 AI 代理审计项目时的标准入口**，替代"读源码猜结构"。
- **与 git 的关系**：G:\ 已是单一 git 仓库，副本漂移本可用 `git diff` 观察；patch 文件的价值在于**把跨项目漂移从"仓库历史"抬升为"项目内显式事实"**——一个项目该不该升级引擎、改了引擎什么，看一个文件就清楚，不用翻 git log。

### 3.3 落点文件

- 引擎侧：`core/presets.py`（preset 注册）+ `cli.py`（`--dump-profile`）
- 项目侧模板：`engine.yaml` / `engine.patch.yaml` 两份模板文件（随引擎示例分发）
- 脚本侧（仓库层，可选）：`scripts/engine_sync.py` —— 用 patch 重放方式把某项目内联副本升级到指定引擎版本（这是"复制优于共享"下的升级工具）

## 4. 第三件事 C：日志即事实源（事件源）

> ✅ **已完成（2026-08-23）**。落地：`core/world_log.py`（追加日志/快照点/投影/事件总线桥/JSON 持久化/确定性转储）、`preset_core` 提供 "log" 服务 + GameEngine.log 镜像、`SaveLoadManager.save_with_log/load_with_log`（快照+日志增量模式，旧格式兼容）、CLI `dump-log`（agent 审计入口：按类型统计+采样+JSON）。验证：16 个新测试全绿，全量 369 项 368 通过（唯一失败=基线无头 Tk）；同 seed 确定性、快照+投影重建==直接运行、存档往返均有测试覆盖；quickstart 示例无回归。

### 4.1 目标

把 EventBus 的 debug 历史升格为**追加式世界事件日志（WorldLog）**——唯一事实源。存档、回放、AI 代理审计都是它的**投影**，三者永不互相矛盾。

对应 harness 的纪律："**Model-visible means logged**"（凡影响状态的事实必须先入日志）→ 引擎版："**凡影响世界状态的事实必须先入 WorldLog**"。

### 4.2 设计要点

- **WorldLog**：追加式事件流（`(seq, ts, type, payload)`），可裁剪（旧段快照化），支持子作用域（每局/每层一个 scope）。
- **投影（projection）**：`SaveLoadManager` 的存档 = 快照 + 日志增量投影；UI/HUD 从投影渲染；回放 = 重放日志（配合已有 `random.seed(seed)` 确定性，事件流应逐字节一致）。
- **三类事件分层**（对应 harness 的 session/agent/capability 三层）：
  - **世界事实事件**（入日志，参与存档/回放）：移动、战斗、拾取、flag 变更……
  - **运行时事件**（不入日志）：渲染帧、音频触发等派生事件；
  - **元事件**（可选）：系统装配/卸载、诊断——供 agent 审计，不参与回放。
- **审计投影**：`--dump-log <存档>` 输出人机可读的事件摘要——**AI 代理定位 bug 时先读日志投影，再读代码**；这同时是未来"规则检查"（如：零字节 __init__.py 不是垃圾）的挂载点。

### 4.3 落点文件

- `core/world_log.py`（追加日志 + 投影原语，~150 行，纯标准库）
- `systems/save_load.py` 增加"快照+增量"模式（保留旧的全量模式，双轨）
- `core/event_bus.py` 增加分派模式（与 A3 合并实现）
- 引擎内关键系统（combat/inventory/puzzle）逐步接入日志（先核心后边缘）

### 4.4 阶段

1. **C1 WorldLog 原语**：追加流 + 快照点 + 投影接口 + 行为测试。
2. **C2 确定性回放**：接入 `random.seed` 确定的现有路径，实现"同 seed → 同事件流"的回归测试（直接复用 G:\game 的 seed 7 必赢 / seed 1 必输案例）。
3. **C3 存档投影**：SaveLoadManager 增加快照+增量模式，旧存档格式兼容读取。
4. **C4 审计工具（已确认纳入）**：`--dump-log` 摘要输出；主工作区 agent 流程接入（定位 bug 先看日志投影）；审计命令与 `--dump-profile` 同挂一个 CLI，作为 AI 代理审计项目的标准入口。

### 4.5 验收

- 确定性测试：同 seed 两次运行，WorldLog 逐事件一致；
- 崩溃恢复：从"快照+日志"重建的世界状态 == 直接运行的世界状态；
- 性能回归：EventBus 现测 400 万次/秒，接入日志后开销 < 20%（日志批量刷盘，不逐事件同步写）。

### 4.6 风险与对策

- **风险**：日志体积膨胀。**对策**：快照点滚动（每层/每 N 事件落一次快照，旧段可丢弃）；日志按局隔离。
- **风险**：系统未接入日志 → 事件源不完整，存档与事实源脱节。**对策**：接入顺序按"先核心（combat/inventory/flag）后边缘"，未接入系统先保持全量序列化兜底，最终目标一致但不强求一步到位。
