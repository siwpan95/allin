## 2. 三成员结论摘要

### 2.1 关屿（优先级① · B602 / verify 字段语法集合）
- **合法语法集合远窄于预设**：98 条 `verify.command` 中 **97 条是线性 `程序 + 参数`**，**仅 1 条含 shell 元字符** —— `dsh-release-archiver.yaml:30` 的 4 段 `bash -n ... && ...`。
- **B602 可消除**：推荐**方案 A**——`prepare()` 返回 `list[str]`、`run()` 收 argv 且 `shell=False`、`cmd /c` 改显式 argv、`import_check():152` 一并改 argv、`record["command"]` 保留字符串兼容报告。bandit 复扫 High=0。
- **唯一硬阻塞（C4）**：那条 `&&` 复合命令需业务裁决——(a) 新增受评审的 `verify.commands: [...]` 列表字段（语义等价，但需扩 `load_entry()` 内建读取器）；(b) 语义收窄为单条 `bash -n scripts/run.sh`。推荐 (a)。
- **其他需确认**：Windows `.bat`/`cmd /c` 在无 shell 下处置、`ALLIN_PYTHON` 环境变量是否白名单、47 个无 verify 文件的 launch fallback（`ls`/`test.html`/`explorer .`/`dse` 等占位命令在 `shell=False` 下会失败 → 是否接受退化为 `T4`）、报告字段格式。
- **CI 实证交叉验证**：B602 HIGH 在 Python SAST job 的 annotation 中被点名到同一 `tools/verify_projects.py:125`，与本地复扫（T17）一致 —— **L1∩L2 一致，非环境偶发**。
- **B310 / B108 复核**：`gitee_release.py:95` scheme 被常量固定非 SSRF，但 `access_token` 拼进 URL query 且默认跟随重定向（跨主机外带面，**待核实**）；`g01_paths.py:97` 的 `"/tmp"` 是路径分类白名单常量，无临时目录操作 → **LES-005 型规则串假阳性**，应走受评审豁免而非改判据。

### 2.2 闻朔（优先级② · 双 CI 证据链）
- **三层判定**：配置存在＝已证实；本机实跑＝部分证实（工具直跑层）；CI 实跑＝联网后**已证实**（三 job success + annotations 证明输出被消费）。
- **七条五要素问题**：Q-01 仓内零 CI 证据/T19 冒 ci 名；Q-02 T9 空文件；Q-03 `unreachable` 与 `ok` 同码（严重）；Q-04 shadow 绿灯（一般，既定决策）；Q-05 `scan-secrets` 无新增行静默绿（严重）；Q-06 Gitee 仅配置（成立）；Q-07 `osv` 境内 runner 可达性（待核实）。
- **六条负向判红**：注入高危须发现数≠0、改坏 `requirements-sast.txt` 须 exit 3 红、越权注解须 exit 2 红、`unreachable` 不得写成 ok、合成令牌须 exit 2 红、无新增行 push 须可见 skip 标记。
