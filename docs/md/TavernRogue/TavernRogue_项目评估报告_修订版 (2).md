# TavernRogue 项目评估报告（修订版）

> 定位：以《酒馆战棋》为核心机制（铸币运营、招募、站位、自动战斗），以《杀戮尖塔》式单人爬塔为循环框架，使用 D&D SRD 5.1 内容做版权安全包装的单人 Roguelike 自走棋。
>
> 评估时间：2026-06-19
> 评估范围：代码仓库 `D:/allin/not/OK/TavernRogue`，对照方案《TavernRogue 2.0：基于 D&D SRD 的 Roguelike 自走棋制作方案》

---

## 一、定位澄清后的评估视角

原方案设想的是“八人循环赛 PvP”，项目实际已将多人对战替换为**单人爬塔**。因此评估不应再以“PvP 是否实现”作为未完成项，而应关注：

1. 酒馆战棋的核心机制（招募/铸币/站位/自动战斗）是否被正确保留；
2. 单人爬塔循环（地图→招募→节点→战斗→奖励）是否跑通；
3. D&D SRD 包装（职业、种族、怪物、宝物）是否落地；
4. 可玩版本需要的最低内容量是否足够。

**一句话结论**：本会话修复了三个阻断性问题（运行时 bug、状态不同步、战斗未接引擎）后，项目已经从“能启动的 pygame 原型”升级为“机制基本闭环、能完整打完一局”的**早期可玩版本**。但内容量（卡池、Boss、事件）仍显著不足，需要继续填充。

## 三、各模块详细评估

### 3.1 英雄与职业（5/5 实现）

已实现：战士、游荡者、牧师、法师、术士，技能效果符合方案描述。

- 战士/游荡者/法师技能在战斗准备阶段直接生效；
- 牧师“治疗祷言”需要在战斗引擎中真正接入死亡回调（当前只在 `Hero.on_ally_death` 中占位，战斗引擎没有调用它）；
- 术士“生命分流”在招募购买时只有提示，没有独立的 UI 按钮，需要靠命令行或后续 UI 扩展；
- 所有职业默认 unlocked，局外解锁逻辑未做。

### 3.2 冒险者与种族（15 个，最高 3 星）

数据文件 `adventurers.json` 现有 15 个冒险者：
- 1 星：6 个
- 2 星：6 个
- 3 星：3 个
- 4~6 星：0 个

六个种族（human/elf/dwarf/dragonborn/half_orc/tiefling）已在数据中分配，种族共鸣在 `BattleEngine.apply_tribe_effects()` 中实现：
- 人类：免费刷新（RecruitSystem 已接入）
- 精灵：获得 DODGE（战斗引擎未实现闪避判定，只有关键词）
- 矮人：获得 ARMOR（战斗引擎已接入减伤）
- 龙裔：战斗开始火焰伤害（只有日志，没有实际伤害）
- 半兽人：25% 双倍伤害（战斗引擎未接入）
- 提夫林：友军死亡暗影伤害（战斗引擎未接入）

关键词实现状态：
- 已生效：GUARD、ARMOR、SHIELD、POISON、FRENZY（连击）、deathrattle（亡语，部分效果）
- 未生效或仅占位：DODGE（闪避）、横扫、过杀、血怒/复仇、部分亡语召唤/伤害

### 3.3 战斗系统（已切换为自动战斗）

本次修复后，`ui/scenes/battle.py` 不再使用手动点击打人，而是：
1. 在 `enter()` 中深拷贝当前阵容生成敌人；
2. 调用 `BattleEngine.apply_tribe_effects()` 应用种族共鸣；
3. 调用 `RelicSystem.apply_battle_start_effects()` 应用宝物战斗开始效果；
4. 玩家点击“开始战斗”后调用 `BattleEngine.simulate_battle()` 自动结算；
5. 根据胜负切换奖励或扣除英雄生命。

这是从“原型”到“可玩”最关键的一步。目前战斗引擎仍存在的缺口：
- 牧师技能死亡回调未接入；
- 宝物“速度之靴”的 double_attack_chance、”移位斗篷“的 dodge_chance 未在战斗引擎中使用；
- 龙裔/半兽人/提夫林种族共鸣只有日志没有实际结算；
- 亡语的伤害/召唤效果需要外部传入敌我列表，当前是占位实现。

### 3.4 地图与节点（结构完整，内容少）

`MapManager` 生成 9 层地图，节点类型完整：monster/elite/boss/shop/event/camp/treasure。`MapScene` 正确路由到对应场景。

问题：
- `map_templates.json` 只有 2 个模板，随机性不足；
- 第 8 层 Boss 固定为 `ancient_red_dragon`，但普通敌人池只有 7 个，精英池为空（没有标记 `is_elite` 的敌人）；
- 第 9 层宝藏密室没有实际进入条件判断（方案要求“携带特定物品”）。

### 3.5 宝物（7/7 实现数据，效果部分生效）

`relics.json` 包含方案中的 7 件宝物：再生护符、速度之靴、力场戒指、火球魔杖、亡灵法书、巨人力量腰带、移位斗篷。

已生效：
- 力场戒指：`battle_shield_once`（战斗开始给友军加护盾）
- 火球魔杖：`battle_start_damage`（战斗开始随机伤害）
- 再生护符：`heal_per_turn`（每回合恢复英雄，但只在 node_handler 中调用，BattleScene 未调用）

未生效：
- 速度之靴：`double_attack_chance`（战斗引擎未使用）
- 移位斗篷：`dodge_chance`（战斗引擎未使用）
- 巨人力量腰带：`global_attack_bonus`（战斗引擎未使用，只在 `Hero.get_relic_effects` 中汇总）
- 亡灵法书：`deathrattle_double`（战斗引擎未使用）

### 3.6 事件（5 个，系统基本可用）

`events.json` 有 5 个事件，支持 heal/damage/gain_gold/cost_gold/gain_adventurer/gain_relic/lose_relic/coin_flip/sacrifice_adventurer 等效果。

本次修复了 `events.py` 中 `reics` 拼写错误导致的 `NameError`。事件获得宝物现在能正常执行。

问题：
- 事件节点在 UI 中只是显示文本，没有真正的选择分支（`event_scene.py` 看起来是单选项）；
- `start_battle` 效果只是设置 `trigger_battle` 标记，没有后续处理；
- 事件数量少，重复可玩性不足。

### 3.7 局外成长（0%）

完全未实现：职业解锁、进阶地城、冒险日志、本地存档。这是从“可玩一局”到“可持续游玩”的最大缺口。

## 四、本次修复的核心问题（已验证）

| 问题 | 影响 | 修复位置 | 验证结果 |
|------|------|----------|----------|
| `events.py` 中 `reics` 拼写错误 | 事件获得宝物时 `NameError` 崩溃 | 改为 `relics_data` / `relics` | 事件获得宝物正常 |

- 关键模块导入测试；
- 英雄生命/铸币同步测试；
- 事件获得宝物测试；

## 五、仍然存在的核心差距

按对“可玩版本”的影响排序：

1. **内容量不足**（最影响重复可玩性）
   - 冒险者只有 15 个，最高 3 星；方案要求至少 30 个、1-6 星；
   - 敌人只有 7 个，精英池为空，Boss 只有 1 个；
   - 事件只有 5 个；
   - 地图模板只有 2 个。

2. **战斗引擎关键词未完全生效**
   - 闪避（DODGE）、双倍伤害、血怒/复仇、横扫、过杀、部分亡语效果仍为占位；
   - 牧师技能死亡回调未接入；
   - 部分宝物效果（速度之靴、移位斗篷、巨人腰带、亡灵法书）未在战斗中生效。

3. **局外成长缺失**
   - 没有存档、没有职业解锁、没有进阶难度；
   - 失败/通关后没有继续游玩的动力。

4. **UI 细节不完整**
   - 招募场景没有手动调整站位按钮；
   - 术士生命分流没有 UI 按钮；
   - 事件选择没有真正分支；
   - 部分场景（如商店）可能只是占位/简化版。

5. **平衡性未验证**
   - 自动战斗接入后，数值曲线是否成立还需要多局测试；
   - 当前敌人只有 7 个，后期层级可能直接碾压或 trivial。

## 六、建议的优先级

### 阶段 A：让一局游戏真正好玩（2~3 周）
1. **补齐战斗引擎缺失的关键词**：优先 DODGE、deathrattle 伤害/召唤、半兽人双倍伤害、提夫林复仇、龙裔火焰伤害。
2. **让宝物效果在 BattleScene 中全部生效**：在 `BattleEngine` 中接入 global_attack_bonus、double_attack_chance、dodge_chance、deathrattle_double。
3. **补内容**：至少把冒险者扩到 25~30 个（4~5 星若干），敌人扩到 12~15 个（含 2~3 个 Boss、3~5 个精英），事件扩到 10~15 个。
4. **牧师技能接入战斗引擎**：死亡时触发 `Hero.on_ally_death()` 将单位移回手牌。

### 阶段 B：重复可玩性（2 周）
5. **实现局外成长**：本地 JSON 存档、职业解锁、通关统计、最佳阵容记录。
6. **增加进阶难度**：通关后解锁更高难度，敌人 + 攻击/生命。
7. **丰富地图模板**：至少 5~8 个不同层模板，增加节点多样性。

### 阶段 C：打磨与扩展（可选）
8. **招募 UI 完善**：站位调整、术士生命分流按钮、手动三连提示。
9. **事件 UI 真正分支**：支持多选项选择及后果展示。
10. **平衡性测试**：记录多局数据，调整数值。

## 七、总体评价

| 维度 | 评分 | 说明 |
|------|------|------|
| 架构设计 | 7/10 | 分层清晰（Model/View/Scene），数据驱动，子系统职责分明 |
| 核心机制 | 6/10 | 酒馆战棋核心机制已落地，但部分关键词和宝物效果未接入战斗 |
| 单人爬塔循环 | 7/10 | 地图→招募→战斗→奖励循环已跑通 |
| 内容量 | 3/10 | 卡池、敌人、事件、Boss 都偏少 |
| 稳定性 | 6/10 | 修复前有两个崩溃 bug 和健康不同步问题；修复后基础运行稳定 |
| 可玩性 | 5/10 | 能打完一局，但重复游玩动力不足，局外成长缺失 |
| 版权安全 | 8/10 | 使用 D&D SRD 包装，命名和数据均避开了直接复制 |

**最终结论**：

TavernRogue 已经完成了从“想法”到“可运行原型”的关键跨越。在修复了本报告中的三个核心问题后，**它已经是一个可以启动、招募、战斗、爬塔、通关/失败的最小可玩版本**。接下来最大的投入方向不是继续修补架构，而是**填充内容**（更多冒险者、敌人、Boss、事件）和**完善战斗引擎的剩余关键词/宝物效果**。完成这两块之后，再补局外成长，就能成为一个有重复可玩性的独立小游戏。
