## 位置为什么在这里

`docs/规范/SPEC-204-系统架构.md` 是**权威架构叙事**（2026-11-04 由 ADR-0007 自本目录
的正文迁入：进 INDEX 登记、受 D3 头部契约 / D9 章节锚点 / g19 文档即测试判据约束——
「权威叙事必须可机检」，数字漂移不再能静默存活）。
ADR 仍留在 `docs/` 之外：ADR 属工程视图，不属四分类文档体系，进 `docs/` 就必须过
`docs_index` 的 D1/D8 登记税；它与架构图（二进制资产，同在判据之外）放在一起。
可发现性由 `docs/INDEX.md` §6「外部事实源」表登记本目录来保证。

## 编号与状态

- 编号：`ADR-0001` 起，**只增不复用**。作废不删号，改状态为 `superseded` 并在正文写明被谁取代。
- 状态闭集：`proposed`（已提出未落地）/ `accepted`（已落地）/ `superseded`（已被取代）。
  闭集是为了能排序、能统计；自由填写的状态等于没有状态。
- 体例：`Problem` / `Decision` / `Alternatives considered` / `Consequences` 四段，与冻结件同源。

## 何时必须写 ADR

改动满足任一条件即需留下记录：换栈或换执行面、新增/取消一条门禁、放宽一项既有约束、
引入会长期存在的例外、以及任何「半年后有人问为什么」的取舍。
一次性调研不写 ADR，写 `docs/记录/审计/` 的一次性记录。
