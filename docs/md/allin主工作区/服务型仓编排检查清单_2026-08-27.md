## A 架构边界（依赖方向唯一）

- [x] A1 服务目录零依赖、编排框架无感知；胶水只在 harness 侧。（lab：E:/lab/*Chess 无任何 cordis/JSON-stdio 代码，适配器都在 drivers/<lang>/）
- [x] A2 适配器单向 import/spawn 服务，服务绝不反向 import 编排层。
- [x] A3 编排框架用正本依赖（npm 包），不 vendor 源码副本。

## B 组合即数据（空间维）

- [x] B1 组件清单 = 声明式 manifest（plugins: 映射）：加一个组件 = 加一条数据，零代码改动（lab：cordis.yml）。
- [x] B2 enabled:false = 运行时下架；loader 级 disable(id) 同样成立（时间维热插拔）。
- [x] B3 每个条目带完整启动参数：kind（native/subprocess）、cmd/args/cwd/timeout、语言标识。

## C 生命周期（时间维可逆）

- [x] C1 每个子进程在挂载时登记 ctx.effect(() => () => kill)——卸载/停服即回收，无孤儿进程。
- [x] C2 alive() = !killed && exitCode === null；每个请求有超时（默认 15s），慢组件在 manifest 单独调大（lab：ts 120s，py 更慢）。
- [x] C3 ready 握手：子进程启动后先回 {ready:true} 再接受业务请求。
- [x] C4 杀进程只按注册表记录的确切 PID/子进程句柄，禁用宽匹配（对齐「宽匹配误杀门户」教训）。

## D 契约（JSON-lines stdio，无网络面）

- [x] D1 请求 {id, cmd, ...} 一行一帧；响应按 id 关联；坏帧静默跳过。
- [x] D2 pending Map 逐 id 登记 + 定时器超时清理（防挂起泄漏）。
- [x] D3 stderr 必须消费（即使丢弃）——否则管道写满死锁（lab：proc.stderr.on('data', () => {})）。
- [x] D4 服务进程只走 stdio，不监听端口（无网络攻击面；对外暴露由编排层统一收口）。

## E 验证与健康（空间维对齐 + 黄金值）

- [x] E1 规格单一真相源：port_spec.txt 式 canonical spec，权威实现为准 + 自测清单（lab：97 项）。
- [x] E2 黄金值共识：语言无关真值（lab：perft 节点数）→ 服务仓对应固定 fixture 的输出哈希/时长/行数/连通性。
- [x] E3 众数共识 + divergence 名单；每用例 PASS/FAIL + 每实现逐值打印（formatReport 式）。
- [x] E4 eval-invariant 断言：expectConsensus:true 的用例出现任何分歧 = 真 bug；informational 用例区分预期分歧（lab：FreeQueen d1d5）。
- [x] E5 分歧发事件（chess/divergence 式）供上层订阅/告警；registry snapshot() 供健康面板。
- [x] E6 退出码与结论绑定：全绿 = exit 0；压力/计时脚本（stress.js/timing.js 式）常驻回归。
