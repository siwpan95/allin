# 一条命令上手

> 目标：**在一个空目录里得到一套能跑、能红、能自己证明自己的治理骨架。**
> 前提：Python ≥ 3.11。想跑聚合命令还需要 Node ≥ 22.18；不想装 Node 也能逐道单跑（见下文）。

---

## 一、三条命令

```bash
pip install allin-governance
allin-governance init my-repo
cd my-repo && npm run check:governance
```

第三条命令正常结束时最后一行是：

```
governance: 14/14 gate(s) clean
```

`init` 自己会打印它做了什么，包括**新建 / 保留 / 覆盖**三个数字，以及要你注意的事：

```
allin-governance init -> .../my-repo
  新建 43；保留 0；覆盖 0
  · 已按 MIT-0 生成 LICENSE（默认值，按需替换）
  · 已建立首个提交（门禁需要可解析的 HEAD 与已跟踪文件）
```

---

## 二、它往目录里放了什么

```
my-repo/
├── README.md                     ← 缺失才创建
├── LICENSE                       ← 缺失才创建（默认 MIT-0，可 --license 改）
├── .gitignore                    ← 只补齐凭据面，不改你已有条目
├── package.json                  ← 只加 scripts.check:governance
├── docs/
│   ├── INDEX.md                  ← 文档枢纽的唯一入口
│   ├── 规范/README.md            ← 约束性规范放这里
│   ├── 事实源/README.md          ← 活台账放这里（必须带观测时点）
│   └── 记录/README.md            ← 证据流水放这里（只增不改）
└── tools/gate/governance/
    ├── run.ts                    ← 聚合运行器
    ├── package.json              ← {"type":"module"}，让 Node 按 ESM 解析
    ├── registry.json             ← 14 道门禁的注册表
    ├── RULES.md                  ← 规则 → 门禁 的映射表（人能读）
    ├── README.md                 ← 怎么跑 / SKIP 是什么意思 / 怎么升级
    ├── GENERATED.json            ← 快照清单：版本 + 每个文件的 sha256
    ├── baseline/*.txt            ← 14 个空基线（棘轮起点）
    ├── gates/*.py                ← 14 道门禁本体（纯标准库）
    └── runtime/govlib.py         ← 门禁共用运行时
```

**40 多个文件里没有一个是你需要先读懂的。** 想读的话，从 `RULES.md` 开始 —— 它是唯一一份"我这个仓库在被什么管着"的完整答案。

## 三、`init` 的四个开关

| 开关 | 做什么 | 什么时候用 |
| --- | --- | --- |
| `--force` | 覆盖 `tools/gate/governance/**`（升级套装） | 装了新版包之后 |
| `--dry-run` | 只打印计划，不落盘 | 想先看看会动哪些文件 |
| `--no-git` | 不初始化仓库、不建首个提交 | 目标在一个已有仓库的子目录里，且你不想建嵌套仓 |
| `--license MIT-0` | 缺 LICENSE 时生成的许可证标识；传 `none` 则不生成 | 你有自己选定的许可证 |
| `--with-exceptions` | 多带 `g18-exceptions` 与 `exceptions.yml` 台账模板（15 道门禁） | 你需要「被接受的风险必须有审批人、补偿控制、到期日」这条 |

>`--with-exceptions` 的代价要提前知道：g18 需要 **PyYAML**（`pip install pyyaml`）。
>缺它时 g18 会报 `ledger-unusable` 并阻断 —— 这是刻意的，判据跑不了就不许装作通过。
>所以默认不带：本包对运行时的承诺是零第三方依赖。

三条不会变的行为（都有单测锁定）：

- **`--force` 不覆盖你的内容**：`README.md` / `LICENSE` / `docs/**` 只在缺失时创建。
- **`package.json` 与 `.gitignore` 只合并**：你已有的 `scripts` 与忽略规则不会丢。
- **二次 `--force` 零改动**：新建 0 / 保留 43 / 覆盖 0，`git status` 干净。因为"升级"和"什么都没变"必须在 git 里长得不一样。

### 关于 git

门禁靠 `git ls-files` 判断"什么在被治理"，靠 `git rev-parse HEAD` 判断对象完整性。所以：

- 目标目录**不是** git 仓库 → `init` 会 `git init`；
- 目标目录在**别的**仓库里、自己没有 `.git` → `init` 会建一个独立仓（否则门禁会以那个外层仓为根，判错对象）；
- 仓库**零提交** → `init` 会补一个初始提交（否则 `g00` exit 3、`g12` exit 1、`g08` exit 3，开局就一屏红）；
- 仓库**已有历史** → 只暂存，不提交（提交信息由你定）。

## 四、不想装 Node 怎么办

14 道门禁是纯 Python 标准库，逐道单跑完全可行：

```bash
python tools/gate/governance/gates/g05_hygiene.py
python tools/gate/governance/gates/g00_meta.py --selfcheck
```

`npm run check:governance` 只是把 14 道按顺序跑一遍并汇总退出码的便利壳：

```bash
node tools/gate/governance/run.ts --list        # 列出 id / 档位 / 覆盖规则
node tools/gate/governance/run.ts --only g01-paths,g05-hygiene
node tools/gate/governance/run.ts --tier P0     # 只跑 P0 档（适合 pre-commit）
```

## 五、`SKIPPED (not a pass)` 是什么意思

新仓库第一次跑，会看到几条 SKIP。**它不是失败，也不是通过** —— 它是"这条判据在当前条件下没有语义"。

| 门禁 | 什么时候 SKIP | 怎么让它真跑起来 |
| --- | --- | --- |
| `g04-push-evidence` | 还没配远端 | `git remote add origin <url>` |
| `g12-integrity` | `--deep` 未开（默认只验 HEAD 可达对象可读） | 加 `--deep` 追加 `git fsck --connectivity-only` |
| `g20-facts` | 没有 `docs/事实源/机器/` 台账；或当前不在 Windows 上 | 建台账 / 换 Windows 跑 |

为什么坚持区分这三态（通过 / 阻断 / 跳过）：

> 如果一道门禁"跑不了"时静默退 0，那么它在半个平台上永远是绿的，而它本该判的东西一次都没被检查过。你得到的是安全感的幻觉。

## 六、退出码

| 码 | 含义 |
| --- | --- |
| `0` | 干净 |
| `1` | 基线之外的新阻断 |
| `2` | 用法错误 |
| `3` | 环境错误（缺解释器、缺 git 工作树等） |

**基线棘轮**：`baseline/<gate>.txt` 里列的存量不阻断，新增即阻断。刷新基线意味着"我确认这些我接受"，所以要留理由：

```bash
python tools/gate/governance/gates/g09_python_hygiene.py --no-baseline --list-all
```

## 七、加一道自己的门禁

三步，加一步自证：

**1. 写脚本** 放进 `tools/gate/governance/gates/`，必须暴露这六个开关：

```
--selfcheck  --quiet  --baseline  --no-baseline  --write-baseline  --list-all
```

自己不想实现这几条的话，直接用 `runtime/govlib.py` 里的 `add_baseline_argument(parser)` 与 `run_gate(main)`。

**2. 写自检** 往沙箱里注入一个必然违规的样本，验证它真的会红，并打印契约行：

```
SELFCHECK {"caught":N,"clean":M,"misreports":K}
```

要求 `N≥1`、`M≥1`、`K==0`。**只打印 PASS 不算自检。**

**3. 注册** 在 `registry.json` 加一条八字段齐全的条目：

```json
{ "id": "g21-mine", "title": "...", "script": "governance/gates/g21_mine.py",
  "tier": "P1", "rules": ["my-rule"], "platforms": ["nt", "posix"],
  "requires": ["python>=3.9"], "selfcheck": true }
```

**4. 写进 `RULES.md`** 一行就行 —— 但必须有，否则 `g00-meta` 会拦住它。

做完跑一次 `npm run check:governance`，`g00-meta` 会立刻替你验一遍新门禁是否真的能自证。

## 八、升级

套装是**快照**，不会自动跟随上游。升级方式：

```bash
pip install -U allin-governance
allin-governance init my-repo --force
```

覆盖前先看两个东西：

1. `init` 打印的**覆盖清单**（哪些文件会被换掉）；
2. 你自己的改动 —— 如果你手改过 `gates/` 下的文件，它会被覆盖。想长期保留就先把它挪成**你自己的门禁**（新 id、新脚本、新注册条目），不要改在快照文件里：下次覆盖就没了，而且没人知道判据变过。

不必自己 `sha256sum`，有命令：

```bash
allin-governance verify my-repo
```

| 退出码 | 含义 |
| --- | --- |
| `0` | 快照未被改动 |
| `1` | 有文件被改动或缺失（**不一定是坏事**：可能是你有意改的，但那就意味着它不再是快照） |
| `3` | 找不到 `GENERATED.json`，这里不是 `init` 生成的骨架 |

它**不**把「你自己加的门禁」算成漂移 —— 给自家仓加门禁是正常行为。
