## 一、一个文件不能身兼两职

`$HOME/.env` 曾同时是两件不相容的事：它是凭据 provider **托管、隔离的存储**（因此任何表面都不能把它提升进 `process.env`，否则存进去的 key 都变成只读启动覆盖、无法轮换），但它的名字与 dotenv 格式又承诺"这是个环境文件"，于是用户把非密配置也放进去——而那些值什么也到不了（只有凭据 provider 读这份文档，且只认凭据引用）。**一个文件无法既是 Harness 拥有并隔离的存储，又是按普通环境规则传播的层。**

> 对 allin：本机的 Gitee token、各 LLM key 不要和"普通环境变量"混在同一个文件里，也不要因为"反正不进仓"就放松对本地存储的隔离要求。

## 二、拆成两份

**`.credentials.yaml` = provider 托管的存储**。严格 YAML 映射（`CredentialRef` → 非空字符串），无 `version` 字段、无包裹层：

```yaml
DEEPSEEK_API_KEY: sk-…
OPENAI_API_KEY: sk-…
```

**`$HOME/.env` = 用户的普通环境层**。普通加载器按"user < project < inherited"分层，只有 product CLI 叠加这些文件，SDK/示例 bin 不继承开发者的 home。

## 三、严格格式即安全

因为文档**只**装凭据、别的什么都不装，所以每个偏差都是拒绝、而非跳过：

- 非 mapping 根、非 POSIX 标识符的 key、非字符串值、空字符串、重复 key、坏 YAML —— **全部失败**，在 boot 与写入时**响亮报错**，实时重载时保留上次好快照并告警。
- 一个被静默忽略的 key 会被读作"我存的密钥没生效"——这正是本改动要消除的失败模式。

写入用解析后 patch（而非 dotenv 逐行编辑器）：注释与未动条目保留格式，任何字符串值（含多行）可往返，没有任何条目因缺引号风格而不可写。

## 四、0600 在读时也强制（POSIX）

provider 写入的 `0600` 同样在**读取时**强制：文档若带任何 group/other 权限位，在读取内容**之前**就启动失败，诊断信息指明 `chmod 600` 修复。Windows 无可表达的模式位可查——其 ACL 在此不可表达——故该检查**跳过而非伪造**。

> 对 allin：本机凭据文件应为 `0600` 且置于 `0700` 目录；读时校验权限，不在权限过宽时悄悄读取。

## 五、分层优先级

凭据优先级区分继承环境与发现文件：

```
inherited env（只读的每次运行覆盖） > .credentials.yaml（托管文档） > project .env > user .env（可写回退）
```

- 留在 `.env` 的旧 key 仍作为回退解析，但一旦 Models 页存了该引用，托管文档即胜出。
- 故意放弃：留在 `.env` 的 key 会被 materialize 进 `process.env`，从而落到子进程（在凭据擦除之下），而不是留在 provider 内隔离；真正应由 Harness 拥有并隔离的密，必须进托管文档——**托管文档永不 materialize**。

## 六、不做迁移

不为旧 `.env` 里的凭据形 key 做首跑迁移：迁移代码会把一个短命格式变成长期维护面，而"分类未知文件里哪些 key 是密"正是本拆分要消除的模糊性。旧文件继续作为环境层工作，是诚实的结果，而非静默的结果。

## 七、与 g03-credentials 门禁的对位

| 层 | 机制 | 守什么 |
| --- | --- | --- |
| 不入库 | `g03-credentials` | 凭据不进仓、不进 `.git/config` remote |
| 本地隔离存储 | 本文原则 | 托管文档 vs 环境层分离；严格拒绝；`0600` 读时强制；永不 materialize |
| 红线 | `SPEC-003` | 敏感信息不得明文出现在文档/日志/提交 |

**判定口诀**：密与配置分文件；密文件只装密、非法即拒；`0600` 读时校验；优先级 inherited > 托管 > project > user；托管文档永不 materialize 进子进程环境。
