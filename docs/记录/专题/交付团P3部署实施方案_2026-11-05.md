## 2. 计划任务注册配方（3 个任务，前缀 ALLIN-*）

### 2.1 portal 两形态取舍与推荐（先定 ② 的形态）

| 形态 | 做法 | 优点 | 缺点 | 裁决 |
|---|---|---|---|---|
| (a) 登录拉起常驻 | 登录即 `npm run portal`（**PORT=0**，临时端口 + portal.port 发现） | 看板开箱即用；无冷启动；portal.port 竞态窗口（P1-R1）基本消失；崩溃 1 分钟内被拉起 | 进程常驻内存（≤80MB 预算内）——但**端口仍是临时的**，不违「零新增常驻端口」红线 | ✅ **已拍板（2026-11-04 主理人）** |
| (b) 纯按需（不注册任务） | 用户需要看板时双击 start-platform.bat | 与现行形态零偏离 | 每次重启机器后看板都是「平台未运行」，E3/G1–G4 的日常价值打折；portal.port 竞态照旧 | 备选，随时可切换 |

**推荐理由**：拍板红线是「零新增**常驻端口**」（端口面），不是「零常驻进程」（进程面）；portal 以 PORT=0 常驻不碰 ports.yaml、不登记任何固定端口，与红线零冲突，同时把 website 治理看板变成登录即用。以下按形态 (a) 给配方；若裁决改 (b)，删除任务 ② 即可（website 侧降级文案已兜底）。

### 2.3 任务 ①：ALLIN-website-autostart（登录拉起 website 常驻 9042）

包装器 `tools/deploy/start-website-task.ps1`（仓内、UTF-8 BOM、无盘符，全文见 §3.4 同款规范；要点：校验 `ALLIN_ROOT`/`node -v ≥22.5` → `& npm.cmd start 2>&1 | Out-File -Append` 到 `$env:ALLIN_LOG_DIR\website-<yyyy-MM-dd>.log` → `exit $LASTEXITCODE`）：

```powershell
# —— 免管理员（当前用户、登录触发、不提权）——
$a1 = New-ScheduledTaskAction -Execute 'powershell.exe' `
  -Argument '-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\projects\allin\tools\deploy\start-website-task.ps1"' `
  -WorkingDirectory 'C:\projects\allin\website'
$t1 = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
$s1 = New-ScheduledTaskSettingsSet -RestartCount 5 -RestartInterval (New-TimeSpan -Minutes 1) `
  -ExecutionTimeLimit ([TimeSpan]::Zero) -MultipleInstances IgnoreNew -StartWhenAvailable
Register-ScheduledTask -TaskName 'ALLIN-website-autostart' -Action $a1 -Trigger $t1 -Settings $s1 `
  -Description 'allin 官网 9042 登录自启 + 失败重启（P3 部署方案 §2）'
```

要点：`-RestartCount 5 -RestartInterval 1min` = 失败后每分钟拉起、最多 5 次（E3 守护故事的落地）；`-ExecutionTimeLimit ([TimeSpan]::Zero)` **必须显式给**——计划任务默认 72h 时限会到点杀掉常驻 website；`-MultipleInstances IgnoreNew` 防重复拉起。node 崩溃 → npm 非零退出 → 包装器非零退出 → 任务判失败 → 触发重启。

## 3. 备份脚本设计（tools/deploy/backup-allin.ps1 设计稿）

### 3.1 落点与纪律

- 入仓 `tools/deploy/backup-allin.ps1`（连同 §2 两个包装器），**无密钥、无盘符字面量（g01）、MIT 头**；执行产物全部落仓外（备份根 / 日志目录）。
- **必须存 UTF-8 with BOM**（仓内 `check_ps1_bom` 门禁；中文注释尤其如此）。
- 密钥**绝不进本脚本**：`website/data/keys/` 由 robocopy `/XD keys` 显式排除，密钥灾备唯一通道 = 既有 `npm run backup-key`（0600 + 口令包 + 月度演练）。

### 3.2 执行链（checkpoint → robocopy → manifest → 轮转 → 日志清理）

```powershell
# backup-allin.ps1 设计稿（落地时保存为 UTF-8 BOM）
param(
  [string]$BackupRoot = $env:ALLIN_BACKUP_ROOT,
  [string]$RepoRoot   = $env:ALLIN_ROOT,
  [int]$KeepDays = 7, [int]$LogKeepDays = 14
)
$ErrorActionPreference = 'Stop'
function Fail([string]$m) { throw "backup-allin: $m" }
if (-not $BackupRoot) { Fail 'ALLIN_BACKUP_ROOT 未设置（见 P3 §2.2）' }
if (-not $RepoRoot)   { Fail 'ALLIN_ROOT 未设置' }
$platformData = Join-Path $RepoRoot 'platform\data'
$websiteData  = Join-Path $RepoRoot 'website\data'
foreach ($p in @($platformData, $websiteData)) { if (-not (Test-Path $p)) { Fail "源目录不存在: $p" } }

$stamp = Get-Date -Format 'yyyy-MM-dd'
$dest  = Join-Path $BackupRoot $stamp
New-Item -ItemType Directory -Force -Path $dest | Out-Null

# 1) WAL checkpoint（已拍板做）：把 WAL 合回主库再拷，快照确定性；website 在线执行免停机
& node -e "const{DatabaseSync}=require('node:sqlite');const db=new DatabaseSync(process.argv[1]);db.exec('PRAGMA wal_checkpoint(TRUNCATE)');db.close();console.log('checkpoint-ok')" (Join-Path $websiteData 'site.db')
if ($LASTEXITCODE -ne 0) { Fail 'wal_checkpoint 失败（node:sqlite 需 >=22.5）' }   # node 22.x stderr 的 experimental 警告属预期

# 2) robocopy /MIR；退出码 0-7=成功（含复制）、>=8=失败——不能按传统退出码判
& robocopy $platformData (Join-Path $dest 'platform-data') /MIR /NFL /NDL /NJH /R:2 /W:5 | Out-Null
$rcP = $LASTEXITCODE
# /XD keys + /XF seed-accounts.json：密钥与口令材质绝不走 robocopy（两通道物理隔离，P2 §5.1）
& robocopy $websiteData (Join-Path $dest 'website-data') /MIR /XD keys /XF seed-accounts.json /NFL /NDL /NJH /R:2 /W:5 | Out-Null
$rcW = $LASTEXITCODE
$ok = ($rcP -lt 8) -and ($rcW -lt 8)

# 3) manifest.json：逐文件 sha256 + 退出码 + 成败标记（失败行为：status=failed + stderr 已在任务日志）
$files = Get-ChildItem $dest -Recurse -File | ForEach-Object { [ordered]@{
  path = $_.FullName.Substring($dest.Length + 1); bytes = $_.Length
  sha256 = (Get-FileHash $_.FullName -Algorithm SHA256).Hash } }
[ordered]@{ date = $stamp; completedAt = (Get-Date -Format o)
  robocopyExit = [ordered]@{ 'platform-data' = $rcP; 'website-data' = $rcW }
  status = $(if ($ok) { 'ok' } else { 'failed' }); fileCount = @($files).Count; files = $files
} | ConvertTo-Json -Depth 4 | Set-Content -Encoding utf8BOM (Join-Path $dest 'manifest.json')

# 4) 7 天轮转：按目录名排序删旧（不按 mtime，防 touch 干扰）
Get-ChildItem $BackupRoot -Directory | Where-Object Name -match '^\d{4}-\d{2}-\d{2}$' |
  Sort-Object Name -Descending | Select-Object -Skip $KeepDays | Remove-Item -Recurse -Force -Confirm:$false

# 5) 计划任务日志 14 天轮转（拍板口径）
if ($env:ALLIN_LOG_DIR -and (Test-Path $env:ALLIN_LOG_DIR)) {
  Get-ChildItem $env:ALLIN_LOG_DIR -File | Where-Object LastWriteTime -lt (Get-Date).AddDays(-$LogKeepDays) |
    Remove-Item -Force -Confirm:$false
}
if (-not $ok) { Write-Error "robocopy 失败 platform=$rcP website=$rcW（>=8 为失败）；manifest 已标 failed"; exit 1 }
Write-Output "backup ok: $dest（$(@($files).Count) 文件，manifest status=ok）"
```

### 3.3 失败行为（fail-loud）

| 失败点 | 行为 |
|---|---|
| env 未设 / 源目录缺失 | 直接 throw，任务 Last Task Result 非 0 |
| wal_checkpoint 失败 | throw，**不继续拷贝**（防拷到不一致快照） |
| robocopy 退出码 ≥8 | 继续写完 manifest（`status:"failed"` + 两个退出码），脚本 exit 1——manifest 记录失败现场供排查 |
| manifest 写失败 | 脚本 exit 1；当日目录视为无效（恢复手册 §4 规定只认 `status:"ok"` 的目录） |

### 3.4 两个启动包装器（同仓同规范，要点）

- `start-website-task.ps1`：校验 `ALLIN_ROOT` → 校验 `node -v` ≥22.5（解析主次版本号，不足即 throw，把「Node 版本错」变成开机可发现的失败而非网站 500）→ `& npm.cmd start 2>&1 | Out-File -Append -Encoding utf8 $env:ALLIN_LOG_DIR\website-<yyyy-MM-dd>.log` → `exit $LASTEXITCODE`。
- `start-portal-task.ps1`：同构；先 `$env:PORT='0'` 再 `& npm.cmd run portal`，日志 `portal-<yyyy-MM-dd>.log`。
- 两者均无盘符字面量；`$env:ALLIN_LOG_DIR` 缺省回退 `%LOCALAPPDATA%\allin\logs`。

## 4. 恢复手册（SEV1/SEV2 口径，按 SPEC-106 §6 + P2 储海量 §5.4 八项整合）

> 开账纪律：按 SPEC-106 §2 定级（密钥丢失/库损坏无恢复路径 = SEV1；platform 起不来/CI 双侧全红 = SEV2），T0 开四段式记录（SPEC-106 §4），**先止损后根因**。

### 4.1 SEV1：密钥丢失 / site.db 损坏 / 换机重建（唯一恢复路径 = 密钥包 + 每日备份）

| 步 | 动作 | 命令/要点 | 期望 |
|---|---|---|---|
| 1 | 停 website，确认影响面 | `Stop-ScheduledTask -TaskName 'ALLIN-website-autostart'`（再确认无残留 node 进程） | 9042 无监听 |
| 2 | **先恢复密钥（顺序红线：先 key 后 db——密文没密钥是废纸）** | `cd website; npm run restore-key -- --from <密钥包> --passphrase <口令>` | exit 0 |
| 3 | 加密完整性 | `npm run verify:crypto` | 10/10 绿 |
| 4 | 选备份目录 | 只认 `E:\allin-backup\<日期>\manifest.json` 且 `status:"ok"` 的**最近一份**；按 manifest 抽验 ≥2 个文件 sha256 | `Get-FileHash` 与 manifest 一致 |
| 5 | 拷回 site.db 三件套 | 停服状态下：`website-data\site.db / site.db-wal / site.db-shm` 三件**一起**拷回 `website\data\`（三件套同份镜像可整体回放 WAL） | 文件就位 |
| 6 | 库一致性验证 | `node -e "const{DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('data/site.db');console.log(db.prepare('PRAGMA integrity_check').get())"` | `integrity_check: ok` |
| 7 | 起 website + 冒烟 | `Start-ScheduledTask -TaskName 'ALLIN-website-autostart'` → `npm run smoke` | 19/19 绿 |
| 8 | platform 状态恢复（如需） | 拷回 `platform-data\*` → 起 portal → `GET /api/status`（端口读 `data/portal.port`） | 200；running.json 损坏时 launch.js 既有 `.bak` 回退 |
| 9 | 门禁留痕恢复（如需） | 拷回 gate-runs.jsonl → `GET /api/gate-history` | `readable:true`，tail 可解析 |
| 10 | 记录闭环 | 四段式记录落 `docs/记录/事故/`，**INDEX.md 登记**（否则 docs_index 门禁红） | 门禁绿 |

### 4.2 SEV2：platform 起不来 / 门禁全红 / 备份任务连续失败

- platform 起不来：`allin status`（文件级，不依赖网络）看 running.json；查 `ALLIN_LOG_DIR\portal-*.log`；按 SPEC-106 §5「CI 全红 triage 四步」走（本地复现 → 退出码分类 3=环境/1=新阻断/2=用法 → 排除门禁自腐 → 回滚或前滚）。
- 备份任务连续失败：`Get-ScheduledTaskInfo -TaskName 'ALLIN-daily-backup'` 看 LastTaskResult；查备份侧任务日志 stderr；**在修复前，手动跑一次 `npm run backup-key` 保证密钥链路新鲜**（SEV1 防线优先级最高）。
- website 探活失败：先看任务 ① LastTaskResult 与 `website-*.log` 末尾（常见：Node 版本被升掉、9042 被占——对照 ports.yaml）。
