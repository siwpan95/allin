# 2026-07-12

## 改造 longplay.py：新增「合并已有视频」模式
- 文件：`D:\allin\tools\image-scraper\images\midjourney_video\longplay.py`
- 背景：原脚本依赖 drawpic 的 `core`/`models`/`numpy`/`PIL`，但这些模块在本目录缺失，import 阶段即崩溃。该目录实际存放 267 个 midjourney 生成的 mp4（h264/24fps/~5.2s，但分辨率各异 624²、544×720、512×768…）。
- 改动要点：
  1. 生成式依赖改为惰性 `try/except` 导入；缺失时仅生成模式报错，合并模式照常运行。新增本地兜底 `ensure_output_dir` / `build_video_filename` / `OUTPUT_DIR`。
  2. 加 `from __future__ import annotations`，避免 `ImageFont.ImageFont` 注解在 `ImageFont=None` 时求值崩溃。
  3. 新增 `--merge` 合并模式：`scan_videos` 扫描目录→`normalize_clip` 把各视频统一缩放/补黑边到目标分辨率（默认 720×720）→复用既有 `build_video_with_transitions`(xfade，片段≤50)/`concat_with_ffmpeg`(回退)→`mux_audio`。`--scan-dir/--sort/--limit/--reverse/--no-normalize/--title/--subtitle/--intro-dur` 等参数。源视频绝不删除，`--cleanup` 只清 workdir。
- 关键坑：ffmpeg drawtext 的 `fontfile` 路径冒号必须转义为 `C\:/...`（Windows 盘符），否则滤镜解析把冒号当分隔符报 "No option name"。已修复 `_make_intro_card_ffmpeg`。
- 验证：`--merge --dry-run` 正确列出 267 个(总时长~23:10)；`--limit 3 --title` 产出合法 16s 视频(含片头+xfade)。已清理测试产物。
