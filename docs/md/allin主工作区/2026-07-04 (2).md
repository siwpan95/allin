## jindutiao 项目功能拆分

将 `C:\Users\13122\Desktop\jindutiao\main.py`（154行单文件）按功能拆为四个模块：

- `state_machine.py` — 状态定义 + 状态转移逻辑（StateMachine 类）
- `ui.py` — Canvas UI 创建与更新（ProgressBarUI 类）
- `animation.py` — 动画循环 + 暂停/重置控制（AnimationController 类）
- `main.py` — 入口，组装三层组件 + 依赖注入

拆分原则：状态机不依赖 UI，UI 不包含业务逻辑，动画控制作为协调层。

## demo.py 全自动挂机改造

将手动点怪 RPG 改为状态机驱动全自动运行：
- `game_fsm.py` — 游戏状态机（COMBAT/REST/RECOVER/DEAD），实现战场决策
- `auto_battle.py` — 自动战斗控制器，替代手动按钮点击
- `demo.py` — 重构 UI（按钮→标签列表）、集成状态机+控制器

状态流转逻辑：HP<40%→休息、HP≤0→死亡重生、无活怪→等待复活
攻击策略：优先打血量最低的怪物（最快击杀拿经验）
帧率控制：战斗 550ms / 休息 1000ms / 等待 500ms / 死亡 2000ms

## JSON 配置解耦

将硬编码数值全部抽到 `config/game.json`：
- `player` 节：初始 HP/等级/暴击率/闪避率/休息消耗

- `auto_battle` 节：四状态帧间隔

## 统一入口 main.py — 进度条驱动游戏

将进度条系统和文字传奇整合到一个窗口：
- `game_models.py` — 从 demo.py 抽出的 Player/Monster/AttackCommand/工厂（纯逻辑层）
- `game_ui.py` — 从 demo.py 抽出的 GameUI（可嵌入任意容器）
- `animation.py` — 新增 set_state_change_callback，状态转移时通知外部

- `demo.py` — 精简为 Game 控制器 + 独立运行入口，从 game_models/game_ui 导入
- `main.py` — 统一窗口（上：进度条面板，下：游戏面板），进度条每轮完成→触发难度变化→怪物血量倍率调整

数据流：进度条循环完成 → AnimationController 回调 → DifficultyManager.update → 怪物 HP buff
