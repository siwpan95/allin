### 88.3 H2 `vendor/` —— 已查明是**有意 vendor**，改用**仓级豁免**（规划项 C）

`vendor/README.md`（19,730 B）明写：这是 Cordis 框架及基础库的**源码 vendor 副本**，
刻意不用 npm 依赖，**以便 harness 完整拥有框架层（可审计 / 可打补丁 / 可钉版本）**；
并带 manifest 表逐包记录上游 repo URL 与精确 commit（如 `cosmokit 1.8.1 ←
github.com/deepseek-harness/cosmokit @ 16f6fc05…`），各包保留上游 MIT LICENSE。
被跟踪的 76 个文件**全是 `.ts/.json/.md` 源码**，构建物（`.map`/`.tsbuildinfo`）未被跟踪；
该仓 `.gitignore` **没有** vendor 规则（本就有意跟踪）。
⇒ 按 H2 去 gitignore 它，等于拆掉该项目"完全拥有框架层"的核心设计。**规则没错，是本仓的有意例外。**

**新增机制：仓级豁免表 + 强制理由**

`tools/gate/audit/repo_hygiene_exemptions.csv`（`check,repo,path,reason,recorded_at`），新增 `--exemptions`。

**与基线的本质区别（这正是要单做一套的原因）**：

| | 基线 | 豁免 |
| --- | --- | --- |
| 语义 | 「这些命中我已知、**暂不处理**」 | 「这一条**不是问题**，因为……」 |
| 理由 | **不解释** | **必填** |
| 性质 | 可重生成的机器状态（时间棘轮，会随新增漂移） | 要评审、要留痕的治理物 |
| 后果 | 让门禁对这仓**失明** | 精确到 `check + repo + path`，且理由白纸黑字 |

**强制记账的机械保障**：`reason` 为空的行**一律不生效**，并在运行时打印
`⚠ 豁免表有 N 行缺理由，已忽略（例外也要记账）` —— 否则豁免表会退化成第二份基线。
自测用例：`豁免表有理由即生效 [1生效/0剩余/0无效]`、`豁免表缺理由不生效 [0生效/1剩余/1无效]`。

DSH 那行的理由写了 463 字，把上游 URL、版本、许可证、核实过程与"为什么不能删"全记进去。

**结果：DSH 由 `H2=76 H5=16` → `命中分布: 无 / RESULT: 通过`。**

### 88.4 顺带修掉两处基础设施缺陷（都是"静默落空"那一类）

1. **默认审计文件路径只认分发布局**：`--baseline`/`--exemptions` 的默认值写死
   `<脚本目录>/gate/audit/<name>`，于是**工作副本**（`/tools/gate/repo_hygiene.py`）会去找
   `/tools/gate/gate/audit/…`（不存在）⇒ **基线与豁免表双双静默落空**。
   新增 `_default_audit_file()`：两种落点各试一次，取第一个存在的。
   （与早先修的 `--repos-root` 默认值同一类缺陷。）
2. **gitignore 的父目录陷阱**：为让豁免表入库，先写 `/tools/gate/audit/` + `!/…/repo_hygiene_exemptions.csv`
   —— **恒不生效**。原因是 gitignore 的规则「**父目录被整体排除时，无法再反向包含其中的文件**」。
   改为 `/tools/gate/audit/*`（排除内容而非目录本身）后生效。
   已把这条坑连同同族的 `_sec_out/*` 一起写进 `.gitignore` 注释。
   复核：豁免表**可见**、基线**仍被忽略**（基线是机器状态，本就该忽略）。
