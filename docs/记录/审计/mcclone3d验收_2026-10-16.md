## 七、复盘

1. **教训 A（加内容必须回头改计数）**：两条陈旧计数都不是"文档不更新"——同一份 README 里
   23 条 / 22 模块 350 项 / 跳高 1.19 / 连锁 12 / 300 只 <6ms **全部逐字对上实测**，
   唯独加配方、加检查时漏改了计数行 ⇒ **计数行要用 grep 追，不能靠记**。
2. **教训 B（时点快照 vs 现值：只有一处该写现值）**：设计稿**故意**不随代码改写（它证明"当时为什么这么定"）。
   修法是**追加勘误块 + 指向现值口径**，而不是把设计稿里的历史数字改成现值 —— 后者会同时抹掉证据与"漂了多少"。
3. **教训 C（口径不明的数字比错数字更坏）**：「20 个判据」无法从盘上复算（`cli` 一条检查只打一行，
   内含断言字段若干），于是它既不能证实也不能证伪 ⇒ **要么给出可复跑的口径，要么别写数字**。
   本记录里凡出现数字处都写明了命令与判据（见 §二/§三）。
4. **偏差（小）**：本轮**未推送任何仓**（与 `SPEC-002 §零` 一致）；mcclone3d 与 allin 的改动均**只做本地提交**。
5. **未做项（含"答案落在别处"的一条）**：用户第 3 问「原规划是否还有后续未完成内容」的答案记在
   §八 与本次修订后的 `docs/阶段计划.md` 表注（**没有 Phase 4**），不在本记录里重复论证。
