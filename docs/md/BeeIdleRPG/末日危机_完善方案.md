## 二、目标定位

构建一款 **末日危机1 → 末日危机2 的"加强版"**，在 ClickPocalypse 系列核心玩法基础上，融入 Bee Idle RPG 的架构优势和中文版特有系统。

**核心差异化**：
- 保留末日危机1「纯文字点击」的极简魅力，作为新手模式/经典模式
- 全面实现末日危机2的所有系统（队伍、地牢、城堡、农场、药水、卷轴、声望）
- 融入中文版独有系统（神器、机器人组装、转生）
- 采用 Bee Idle RPG 的程序化世界生成、深度角色系统（种族+属性）、Excel 配置驱动
- 统一 MVC 架构，支持 Web + Desktop 双端

## 三、完善方案 —— 按系统模块拆解

### 🏷️ M1 — 角色系统 (Character System)

**现状**：末日危机2 有 6+ 职业但无种族、无属性维度。Bee Idle RPG 有 8 种族 + 10 职业 + 6 属性 + 30 技能。

**完善方案**：

```
M1.1  引入种族系统（8种族，源自 Bee）
      ├── 人类 / 精灵 / 矮人 / 半身人 / 侏儒 / 半兽人 / 提夫林 / 龙裔
      └── 每个种族提供不同属性修正（STR/DEX/CON/INT/WIS/CHA）

M1.2  扩展职业至 10 种（Bee 已有完整实现）
      ├── 战士 / 法师 / 牧师 / 盗贼 / 游侠
      ├── 圣骑士 / 野蛮人 / 术士 / 武僧 / 德鲁伊
      └── 每职业 3 技能，等级 1/5/10 解锁

M1.3  引入六维属性系统
      ├── 力量(STR) → 物理攻击力
      ├── 敏捷(DEX) → 闪避率、暴击率
      ├── 体质(CON) → HP、格挡率
      ├── 智力(INT) → 法术伤害
      ├── 感知(WIS) → MP、精神力恢复
      └── 魅力(CHA) → 金币加成、商店折扣

M1.4  队伍系统保持 4 人上限
      ├── 支持重复职业
      └── 冒险点数解锁额外队伍栏位
```

### 🏷️ M2 — 装备系统 (Equipment System)

**现状**：末日危机2 有基础装备掉落+自动装备。Bee Idle RPG 有 10 槽位 + 8 品质 + 前缀词缀 + 特效池，体系更完善。

**完善方案**：

```
M2.1  采用 Bee 的 10 槽位体系
      ├── 主手武器 / 副手 / 头盔 / 胸甲 / 手套 / 护腿 / 靴子
      └── 项链 / 戒指 / 饰品

M2.2  采用 Bee 的 8 级品质体系
      ├── 粗糙 → 普通 → 精良 → 优秀 → 卓越 → 大师 → 传说 → 神器
      └── 每级品质对应倍率递增（伤害 1.0→2.05，防御 1.0→1.84）

M2.3  程序化装备生成（Bee item_service 可直接复用）
      ├── 等级相关品质权重
      ├── 武器模板（8类型 × 5等级名）
      ├── 护甲模板（4类型 × 5等级名）
      ├── 16 前缀词缀
      └── 5 种特效池

M2.4  自动装备逻辑升级
      ├── 品质优先 → 同品质比较数值
      └── 可手动锁定特定槽位不自动替换
```

### 🏷️ M3 — 战斗系统 (Combat System)

**现状**：末日危机2 攻击评级/防御评级/暴击/眩晕/潜行体系。Bee Idle RPG 有命中部位/暴击/闪避/格挡/伤害公式。

**完善方案**：

```
M3.1  合并两套战斗系统
      ├── 攻击评级 → 命中判定（攻击方 vs 防御方）
      ├── 暴击（无视护甲，造成全额伤害）
      ├── 闪避判定（Bee: 敏捷 × 1%）
      ├── 格挡判定（Bee: 5% + 体质 × 0.3%）
      ├── 命中部位系统（Bee: 头15%/躯干40%/四肢等，带伤害倍率）
      └── 眩晕机制（HP归零时进入，不被攻击）

M3.2  技能体系扩充
      ├── 点击1保有技能：10职业 × 3技能 = 30技能
      ├── 每个技能有冷却时间、精神力消耗
      ├── 精神力每3回合恢复
      └── 药水"免费施法"期间不消耗精神力

M3.3  队伍AI优化（从点击2继承）
      ├── 不堵门、远程保持距离
      ├── 不冲怪群捡装备
      ├── 战士血量健康时嘲讽
      ├── 牧师自动复活队友
      ├── 盗贼优先宝箱
      └── 随从帮忙收集药水卷轴
```

### 🏷️ M4 — 地牢系统 (Dungeon System)

**现状**：末日危机2 有多地牢、房间、宝箱/武器架/书架。Bee Idle RPG 无地牢概念，但有程序化世界生成。

**完善方案**：

```
M4.1  采用程序化世界生成（复用 Bee world_service）
      ├── 15 个区域，分布在 5×3 网格
      ├── 每个区域有危险等级（1-25）
      ├── 每个区域生成 1-3 个地牢
      └── 地牢内房间数 = 5 + 危险等级 × 2

M4.2  区域连通性
      ├── 曼哈顿距离 ≤ 1 则为邻接区域
      ├── 清理当前区域所有地牢 → 解锁相邻区域
      └── 世界地图可视化（可参考 Bee 的区域网格）

M4.3  地牢内容系统
      ├── 每房间随机怪物数量（危险等级相关）
      ├── 30% 概率出现交互物：宝箱/武器架/书架/药水架
      ├── 20% 概率出现精英/Boss房间
      └── 清理后触发"地牢清空"事件

M4.4  定居点与地标（Bee 原有系统）
      ├── 60% 概率区域有定居点（村庄/城镇/城市）
      ├── 40% 概率有地标（遗迹/神殿/墓地/魔法泉/龙巢等）
      └── 发现地标获得冒险点数 + 经验奖励
```

### 🏷️ M5 — 城堡与农场系统 (Castle & Farm)

**现状**：末日危机2 独有系统。

**完善方案**：

```
M5.1  城堡购买系统

      ├── 清空地牢后花费金币转农场
      ├── 农场自动滋生怪物 → 自动击杀
      ├── 农场产出 = 区域危险等级 × 基础产出
      └── 药水可加速农场效率

M5.3  胜利条件
      ├── 征服所有区域的城堡 = 游戏胜利
      └── 激活转生/声望系统
```

## 六、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3.8+ | Bee 已有完整实现，快速启动 |
| 双端策略 | Desktop 先，Web 后 | Desktop（Tkinter）可最快出可玩版本 |
| 数据格式 | JSON + Excel | Bee 已验证方案，策划友好 |
| MVC 架构 | Model 共享，View 分离 | 支持 Desktop/Web 双端，数据层统一 |
| 第一阶段目标 | 纯文字经典模式 | 快速验证核心循环（战斗→掉落→升级→任务） |
| 像素资源 | David E. Gervais 图块（CC 许可） | 点击2 同款，免费可用 |
