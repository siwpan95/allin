## 0. 归属规则（谁能写哪、谁只管辖下）

1. **机器独有事实只写该机文件** —— 盘位、运行时、仓根 / 发布区、本机专属观测，一机一件，不外溢到别机。
2. **跨机共识写本索引** —— 纪律、规则、机器清单、章节迁移对照；共识条款里的**具体数值**仍回各机文件，
   本索引只给指向，避免同一数值两处漂移。
3. **引用「本机」必须带机器名** —— 条目旁标 `@机器名`；裸写「本机」视为不合格表述。
4. **接入者先报自己的机器名**（见 §3 纪律）。
5. **改推送配置前先跑 `git config --get-all remote.origin.pushurl` 并报机器名**（见 §4）。

## 3. 多端作业纪律：接入者先报自己的机器名

#### 多端作业纪律：接入者先报自己的机器名

本仓**有多端负责推送**（本机推 Gitee、远端侧推 GitHub 镜像，见 §9），且不同接入者（人 / agent）
可能在不同机器上作业 —— 因此「本机」二字**极易混淆归属**。凡涉及机器事实的动作
（推送、记账、改本文件、判路径存在性、挑解释器），一律：

1. **先表明自身名称** —— 接入者在首条消息或首条记账里写明
   `机器名 = DESKTOP-XXX`，取 `Win32_ComputerSystem.Name`
   （**不要用 `$env:COMPUTERNAME`**，它可能为空，本机即为空）；
2. **记账条目带机器名** —— 交接档 / 记忆月账中涉及机器事实的条目注明来源端，
   例如「（@`DESKTOP-KQABATS` 实测）」，避免日后把 A 机的观测当成 B 机的事实；
3. **照抄前先复测** —— 本文件头部「失效条件」已写明：**换机后立即失效，涉及机器事实前现场复测**；
4. **名字对不上时先求证，不要自己下结论** —— 见下方实例。

> **实例（2026-10-29，本次踩坑，正是「多端混淆」的铁证）**：接入者读到 §0「本机 = `DESKTOP-8RSV60V`」，
> 实测本机却是 `DESKTOP-KQABATS`，**名字对不上**。此时接入者**没有求证用户**，就自行推断为
> 「本机换了 ⇒ 这些事实已过期 ⇒ 事实源整体需复测」，并把「过期 / 失效 / 推翻」这类**未证实的定性**
> 写进了唯一事实源、还准备直接推送。
> **用户澄清**：`DESKTOP-8RSV60V` **就是另一台电脑**，那些事实**不是过期**，只是**不属于本机**。
> ⇒ 教训：① 名字对不上**先问一句**（这是另一台机器？还是改名了？）—— 用推断代替查证就是把猜测当事实；
> ② 涉及**定性的判断**须经用户确认后才可写入事实源，不得借「已授权推送」把未证实的结论推出去。

## 6. 机器事实的复测机制（2026-10-30 新增）

> **起因**：当日对 `@DESKTOP-8RSV60V` 全量复测，**9 处断言与磁盘不符，而 19 道门禁 `exit 0`**。
> 根因不是门禁失灵，是判据没覆盖：`g07_doc_freshness` 只验「有没有写时点」、
> `g19_docs_refs` 的 `PATH_REF` 只认仓内相对路径**不认盘符**、`g01_paths` 只管死盘符管不了语义过期。

两个脚本，**职责严格分离**：

| 脚本 | 只做一件事 | 退出码 |
|---|---|---|
| `tools/facts/measure.py` | **只采集**：系统 / 卷 / 物理盘 / 仓数 / 工具链 PATH 实解析 / 推送配置 / 环境变量有无 → 输出可直贴本机文件的 markdown | 0 / 2 / 3 |
| `tools/facts/verify_facts.py` | **只判定**：解析各机文件头部**日期最新的时点块**，校验 `PATH-EXISTS` 与 `COUNT` 两类断言 | 0 无问题 / **1 有 finding** |

> **为什么分开**：采集不做判断，所以永远可信；判定会被质疑，所以必须能自检（`--selftest`）。
> 合成一个脚本会让人分不清「数据错了」还是「判据错了」。

**新增一台机器的步骤（这就是「扩大化」的操作口径）**

1. 在该机跑 `python tools/facts/measure.py --out <临时文件>`
2. **人工裁决**：与上一版逐项比对；不符的先复测再改，**旧值以「（原 …）」保留在同一格**
3. 新建 `机器/<机器名>.md`（照现有三份结构），并在 §1 分区清单登记
4. 跑 `python tools/facts/verify_facts.py`，应得 `findings 0`

**每轮复测的约定**

- 现值**必须写进最新的时点块** —— 判定器只读日期最新的那批块；写进旧块等于没写
- 采集值是**原始值，不是事实**；未经复测裁决的采集结果**不得直接覆盖旧值**

**已知边界（不掩盖）**

- 只判头部时点块；章节体内的表格（如 §1 盘位表）不判
- 只判 `PATH-EXISTS` / `COUNT`；版本号、行为观测、语义判断不判
- 不查**章节引用**完整性（本节开头那个 `§5` 悬空即此类）
- **已接入门禁（2026-10-30 12:35）**：升格为 **`g20-facts`**（Windows 专属，`tier P1`），
  门禁总数 **19 → 20**，八处「19 道」自述已同步订正。**判据只有一份**——定义在 `g20_facts.py` 内，
  `tools/facts/verify_facts.py` 反向 import 复用（门禁必须自包含：`g00-meta` 把 `--selfcheck` 放进只有
  `governance/` 的沙箱跑，够不到 `tools/facts/`；两套判据则会同时报绿、冲突时无人判定）
