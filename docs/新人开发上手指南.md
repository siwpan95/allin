# 新人上手（教程）

> 这份文档是**教程**，不是手册：它带你把整套治理跑通一遍，每一步都告诉你**应该看到什么**。
> 照做即可，不需要先理解原理。跑完再去看 [`规范/`](规范/) 与 [`INDEX.md`](INDEX.md)。
>
> 带 `verify` 标记的命令由 `tools/tutorial/verify_guide.py` 逐条执行——
> **写在这里的命令不是给人看的，是会被跑的**。改了命令而没改期望，CI 会红。

---

## 第 1 步 · 确认工具链

```bash verify
python --version
```

你会看到 `Python 3.13.` 开头。低于 3.11 请先升级——门禁用了 `tomllib` 与新 typing 语法。

```bash verify
node --version
```

你会看到 `v22.` 开头。门禁的聚合入口是 npm script。

```bash verify
git --version
```

你会看到 `git version 2.` 开头。

---

## 第 2 步 · 装上治理核

```bash verify
python -m allin_governance --version
```

你会看到 `allin-governance 2.5.1`。`python -m` 的写法在激活与未激活 venv 时都成立。**版本号必须与 `requirements-dev.txt` 里钉的一致**，
不一致说明装到了别的版本——先 `python -m pip install -r requirements-dev.txt`。

---

## 第 3 步 · 跑一遍门禁

```bash verify
npm run check
```

这是最重要的一步。跑完你会看到：

```
governance: 20/20 gate(s) clean
```

耗时约 70 秒。**红了不需要猜**：每条门禁自己会打印 `remediation` 一行，
告诉你「先分辨是事实过期，还是门禁没看见」。

---

## 第 4 步 · 做一次仓库体检

```bash verify
python -m allin_governance repocheck . --self
```

你会看到一行健康分，例如：

```
== allin  (G:/repos/allin)  健康分 9.4
```

健康分**不是门禁，不阻断**。它用来发现门禁覆盖不到的坏味道：无测试、无 CI、依赖未锁版本。

---

## 第 5 步 · 校验机器事实

```bash verify
python -m allin_governance facts verify --root .
```

你会看到：

```
scanned 1 file(s); findings 0
```

机器事实是 `docs/事实源/机器/<机器名>/` 里「本机有几个仓、装了什么版本」这类断言。
**换机器、加仓、升包之后这一步会红**——它红得对：去改本机分区那一块，别改判据。

---

## 第 6 步 · 故意造一条坏链，看它被拦

在任意 `docs/` 下的文档里加一行：

```text
[坏链](not-exists.md)
```

再跑门禁：

```bash verify
npm run check
```

你会看到 `g19-docs-refs` 报出 `F-LINK-MISSING`，带文件与行号。
**这一步的意义**：亲手确认「文档改动会被检查」。删掉那行，门禁恢复绿色。

---

## 第 7 步 · 提交

```bash verify
git status --short
```

提交时 `pre-commit` 会自动再跑一遍门禁。**钩子失败时不要加 `--no-verify`**——
那等于把红色改成看不见；门禁红通常意味着你的改动确实有问题，或者存量本来就有问题。

---

## 你刚才做了什么

| 步 | 动作 | 覆盖了什么 |
|---|---|---|
| 1–2 | 装工具链 | 环境可复现 |
| 3 | 跑 20 道门禁 | 仓的纪律 |
| 4 | 体检 | 门禁覆盖不到的坏味道 |
| 5 | 校机器事实 | 「本机事实」与「文档断言」对齐 |
| 6 | 故意造坏链 | 亲手触发一次判据 |
| 7 | 提交 | 钩子兜底 |

## 卡住了怎么办

| 现象 | 先看哪里 |
|---|---|
| 门禁红，但看不懂 | 该门禁输出末尾的 `remediation` 一行 |
| `facts verify` 红 | `docs/事实源/机器/<本机名>/` 里的计数与版本 |
| 不知道该改哪份文档 | [`INDEX.md`](INDEX.md)（所有文档必须登记） |
| 想加一条新判据 | [`规范/`](规范/) 找对应 SPEC，先定判据再写规则 |
