### 2.3 JSONL 证据行 schema（对齐 gate-runs 风格：逐项一行 + 汇总一行）

落点：`tools/gate/audit/e2e-runs.jsonl`（被根 `.gitignore` L80 `/tools/gate/audit/*` 自动覆盖，零 .gitignore 改动；5MB 轮转沿 tasks.log 模式）。

```jsonc
// 逐检查点一行（一次运行 6 行）
{ "type": "e2e-checkpoint", "runId": "20261104T214743Z-a1b2", "checkedAt": "2026-11-04T13:47:50.000Z",
  "id": "CP3", "name": "portal 回环探活", "ok": true, "skipped": false,
  "detail": "HTTP 200 port=53121 version=0.2.0", "ms": 42 }
// 汇总一行（末尾）
{ "type": "e2e-run", "runId": "20261104T214743Z-a1b2", "startedAt": "...", "finishedAt": "...",
  "commit": "22e5766", "node": "v22.12.0", "platform": "win32",
  "tempWebsitePort": 9156, "portalReused": true,
  "summary": { "total": 6, "ok": 5, "skipped": 1, "fail": 0 }, "exit": 0 }
```

口径：`summary.fail>0 或 exit≠0` ⇒ 本行判红；`skipped` 仅限平台专属子项（CI 上的 verify-mount）。任一检查点失败时该行 `detail` 必须指名失败面（CLI / portal / website / 判据），满足 P1a SC6 ⑤「指名失败面」。

### 2.4 临时实例生命周期（起 → 探 → 杀 → 清理）

```
① Preflight（≤1s）
   - 断言 git 工作区存在（ALLIN_ROOT 自发现，零盘符）
   - 读 docs/事实源/ports.yaml，校验选定网站临时端口（默认 9156，env ALLIN_E2E_WEBSITE_PORT 可覆盖）
     不与任何 ports[].port 及 reserved 段冲突 → 冲突 fail-loud 退出（端口纪律程序化）
   - 断言 website/data/seed-accounts.json 存在（缺失 → 失败输出指引「先 npm run seed」，沿用 smoke-test.js 惯例）
② portal 生命周期（复用优先，避免双实例竞态）
   - 若 platform/data/portal.port 存在且 GET /api/status 200 → 复用该实例（portalReused:true，不新起）
   - 否则 spawn `node platform/apps/portal/src/index.js`（env PORT=0），轮询读 portal.port 文件 ≤5s
③ website 临时实例
   - spawn `node --experimental-sqlite website/src/server.js`，env PORT=9156 + SITE_BASE_URL
     （与 smoke-test.js 同款 spawn + waitReady 80×250ms，20s 超时）
④ 执行 CP1–CP6（单个检查点超时 5s，AbortController）
⑤ teardown（finally 块保证，任何失败路径都执行）
   - website 临时实例 SIGKILL；仅自拉的 portal SIGKILL（复用实例不杀）
   - portal.port 残留 = 既有语义（platform 离线时该文件本就残留），记 detail 不清理
   - 汇总行落盘 JSONL → process.exit(fail ? 1 : 0)
```

### 2.5 预计时长与超时

| 阶段 | 预计 | 上限 |
|---|---|---|
| Preflight + portal 就绪 | 1–3s | 6s |
| website 临时实例就绪 | 2–5s | 20s（waitReady 上限） |
| CP1–CP6 探测 | 2–5s | 30s（单点 5s） |
| teardown + 落盘 | <1s | 2s |
| **总计** | **15–30s** | **整体 60s 硬超时（超时视为失败，exit 1）** |

### 2.6 已知风险（设计内处置）

- **双 portal 竞态**：临时 portal 若覆盖常驻实例的 portal.port 文件 → website 代理读陈旧端口。处置：§2.4 ②「复用优先」，不复用才自拉【待确认：portal 是否支持隔离 data 目录的 env；若支持则 CI 上始终自拉临时实例更干净】。
- **e2e 与常驻 smoke 撞车**：9155 归 npm run smoke、9156 归 smoke:e2e，互不冲突。
- **CI 上无 DSH**：verify-mount 子项 skipped（§2.2 注）。

## 5. 缺陷分级与放行口径

### 5.1 缺陷分级（对齐 SPEC-106 事故分级思想：按「事实源受损 / 边界失守 / 纪律失灵」定级）

| 级别 | 定义（本升级语境） | 典型例子 | 修复时限 | 放行影响 |
|---|---|---|---|---|
| **Blocker**（≈SEV1） | 事实源受损或安全边界失守：明文泄漏、site.db/状态文件损坏、越权写成功、密钥链路失效、门禁整体失效 | U-B08 SSRF 放行；U-F23 明文落库；corrupt 文件被当缺失静默吞 | 立即，放行前必须清零 | No-Go，无一票否决例外 |
| **Critical**（≈SEV2） | 北极星或降级语义失灵：SC6 检查点假绿、降级卡不出现/吐堆栈、漂移注入未拦截、exit 口径违裁决 | U-Q02 注入不红；U-Q04 假绿；U-Q09 吐原始 502 | ≤2 天 | No-Go（未清零前） |
| **Major**（≈SEV3） | 单点功能缺陷但有一致替代路径：单个非功能阈值超验收值、单门禁红、数字对账不一致（U-Q07） | P95 超阈 20%；status 与 overview 数字不一致 | ≤1 周 | 限期 Go（带豁免记录 + 修复排期） |
| **Minor**（≈SEV4） | 文案/样式/无障碍细节/审计 detail 缺字段 | 徽标图标缺失、W301 提示不准 | 排期（下迭代） | Go，记录台账 |

### 5.2 最终验收 Gate（全绿才放行的 Go/No-Go 定义）

**Go 条件（全部满足）：**
1. SC1–SC9 全部 exit 0 / 达标（§3.3 映射逐条勾）；
2. `run_all_gates.sh` g00–g21 全绿（GitHub Actions gates-posix + gates-windows 双平台同绿，Gitee Go 同绿）；
3. `npm run smoke:e2e` exit 0，JSONL 证据 ≥5 检查点全绿，`summary.drift=0`；
4. §4 非功能验收阈值全达标（两步走第二步回填后的数值）；
5. Blocker/Critical 清零；Major 全部带豁免记录；
6. 灾备演练八项（U-D01~D08）完成且演练记录已落 `docs/记录/` + INDEX 登记（文档税闭环）；
7. openapi 0.2.0 只增不改比对通过（U-Q14）。

**No-Go 一票触发**：任一 Blocker；或 SC6/SC7 失败；或门禁双平台不同绿。

**灰度口径**：单机单用户无流量灰度——「灰度」等价于**并入 run_all_gates 前的 3 天双跑观察期**（g21 与 smoke:e2e 先手动/定时跑，与既有门禁并行，期间只记不拦；无假红后转硬门禁）。假红判定：g21/CP 在未变更的干净检出上连续 2 次非预期红。
