**该机自己写下的三条认识**：
1. **刷基线不等于债务消失** —— `--write-baseline` 会把当时所有命中一锅端吞进基线，那条本该走
   「带裁决理由的行级豁免」的真实凭据红线就此不再报 ⇒ **红线是被一次「图省事的刷新」抹掉的**。
   纪律：「已知且有理由」的写豁免，「已知但还没处理」的洗进基线，两者不能混。
2. **基线与台账都不入库是政策不是遗漏** —— 基线是「已知未处理」的时间棘轮/机器状态（各机检出不同），
   豁免是要评审要留痕的治理物。后果是**本次刷的基线只在本机生效**：换机或重新克隆后
   `repo_hygiene --all` 会重新报约 871 条，须由该机自行 `--write-baseline`。
   ⇒ **没有台账的刷新就是赊账。**
3. **多远端仓遇到分歧，先判断「该提交是否已在别的远端公开」，公开过的就不能变基** ——
   `game-prototypes` 被 Gitee 拒 non-fast-forward 后取 `git pull --no-rebase`（合并）而非 rebase，
   因为 rebase 会改写已推到 GitHub 的提交、逼 GitHub 侧也强推。

**该机自己记下的两处误判**：① 把分级③ 收敛归档仓的「副本」当成重复双落点 ——
